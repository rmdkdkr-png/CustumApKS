# SS2 연습 모드 0단계 — 조사와 설계 (Legacito)

요청: «사무쇼2 연습(트레이닝) 모드를 리그처럼 게임 안에 끼워 넣는다. 화면과 조작은 실기 느낌으로.»
대상: 사무라이 스피리츠!2 (NGPC, `SAMURAI2v000`) · Legacito · 코어 ss2-sp-core(mednafen_ngp) · 2026-10-13

리그와 같은 방식으로 만든다. 롬은 고치지 않는다. 매 프레임 `retro_run` 뒤에 C 코드(league.c 쪽)가 작업 램·문자 램·스크롤 램·팔레트 램을 읽고 쓴다. 필요하면 사용자 입력 일부를 막거나 한 프레임 통째로 바꾼다.

표시
- **[확실]**: 공식 매뉴얼·패치 노트 요약, 직접 읽은 소스 코드.
- **[아마]**: 기사·커뮤니티 요약, 또는 자신 있는 기억.
- **[불확실]**: 기억뿐이거나 출처끼리 다르다.
- 우리 게임 측정은 출처로 적는다.
  - **[입력]** 입력 조사 · **[상태]** 상태 조사 · **[타격]** 타격 조사 · **[조사]** 기능 조사 중 실측
  - **[설계]** 이 문서를 쓰며 잰 것(`stage0/design/v1~v7`)
  - **[0단계]·[3단계]** 리그 문서에 적힌 값(다시 재지 않음)
- 주소는 모두 **CPU 주소**다. 코어 `SYSTEM_RAM` 오프셋 = 주소 − 0x4000.
- 같은 꼴 반복: 플레이어 블록은 P2 = P1 + 0x200, 표시 물체는 P2 = P1 + 0x40, 커맨드 블록은 P2 = P1 + 0x88.

근거 자료
- 네 조사의 요약과 참조 구현(아래 «이 폴더»). 각 조사의 `REPORT.md` 는 하네스가 막아서 남지 않았다. 요약 본문과 `.py` 참조 구현을 근거로 썼다.
- 이번에 직접 잰 것: 싸움 화면의 판 배치, 일시정지 중 화면 램, 게임 숫자 타일, 안 쓰이는 타일, 순정·한글판 HUD 비교(`design/v1_vram.py`~`v7_tiles.py`).

## 0. 한눈에

- **롬 패치 없이 된다.** 연습에 필요한 상태(위치·체력·시간·분노 MAX)는 모두 램 쓰기로 바꿀 수 있다. P2 를 가만히 세우기, 가드시키기, 입력대로 움직이기도 램 쓰기로 된다.
- **들어가는 곳은 타이틀 메뉴 셋째 줄이다.**
  - 일반 세션에서 «2 인 대전»을 «연습 대전»으로 바꾼다. 리그가 «2 인» 두 타일을 «리그»로 바꾼 것과 같은 방식이다.
  - 앱에서는 통신 대전이 안 된다[0단계]. 그래서 이 칸은 비어 있는 칸이다. 진짜 모드를 하나도 잃지 않는다.
  - 리그 세션에서는 지금처럼 «리그 대전»이다.
- **화면은 게임 안에 그린다.**
  - 연습 메뉴: 게임 자신의 일시정지(«PAUSE») 위에, HUD 판의 빈 줄에 창을 그린다.
  - 대미지 숫자: HUD 셋째 줄 검은 띠에 게임의 «N HITS» 숫자 타일로 쓴다.
  - 앱 띠에는 버튼 안내만 둔다(리그와 같다).
- **조작은 게임 그대로 두고 Option 하나만 가져온다.**
  - Option 탭 = 일시정지 + 연습 메뉴.
  - Option 을 누른 채 방향 = 위치 리셋(↓ 지난 위치 · ← 왼쪽 벽 · → 오른쪽 벽 · ↑ 가운데).
  - 2단계에서 Option+A 녹화, Option+B 재생.
- **1단계(MVP)는 코어를 안 고친다.** 끝나지 않는 라운드, 더미 서기·CPU, 가드(안 함·전부·첫 타 뒤·랜덤), 위치 리셋, 분노 MAX 유지, 연습 메뉴, 대미지 표시.
- **2단계는 코어 훅 하나가 필요하다.** 더미가 입력대로 움직이는 경로(VS 경로)는 P1 입력도 다른 바이트로 옮겨 줘야 한다. 프레임 앞에서 패드를 거르는 훅이 있으면 지연이 0 이다. 앉기·점프·진짜 가드·녹화·재생·리버설이 여기에 달려 있다.
- **이 게임의 공식 현대판에도 훈련 모드가 없다.** NEOGEO Pocket Color Selection Vol.1 에 사무라이 스피리츠!2 가 들어 있다[확실]. 되감기는 있지만 훈련 모드는 없다[아마].

## 1. 무엇을 만드나

사무쇼2(NGPC)의 1인 대전 첫 경기를 «끝나지 않는 연습 경기»로 바꾼다. 타이틀 메뉴에서 «연습 대전»을 고르면, 게임의 캐릭터 고르기 화면이 «상대 선택»이 되어 연습 상대(더미)를 고른다. 이어서 원래대로 내 캐릭터를 고르고 싸운다. 경기 중에는 시간이 멈추고, 쓰러지지 않고, 체력이 저절로 찬다. Option 을 누르면 게임이 멈추고 그 위에 연습 메뉴 창이 뜬다. 여기서 더미 동작·가드·분노·리셋 위치를 정한다. Option 을 누른 채 방향을 누르면 정한 자리로 바로 리셋된다. 화면 글자와 숫자는 모두 게임 화면 안에 게임 글꼴·게임 타일로 그린다.

### 2-다. 입력

| 주소 | 뜻 · 값 | 확인 | 신뢰 |
|---|---|---|---|
| 0x6F82 | 패드 레지스터. U 01 · D 02 · L 04 · R 08 · A 10 · B 20 · Option 40. 코어가 `Emulate()` 처음에 쓴다(SP 엔진 뒤) | [입력] 900/900 프레임 | 높음 |
| 0x56ED / 0x56EE / 0x56F1 | 전역 패드: 지금 / 새로 누름 / 지난 틱 | [입력] | 높음 |
| **0x570D** | **VS 경로의 P1 패드.** 0x57D4=1 이면 P1 은 하드웨어 패드 대신 이걸 읽는다. 1인 대전에서 게임이 안 쓴다(2600프레임 감시) | [입력] | 높음 |
| **0x5715** | **VS 경로의 P2 패드.** 0x40(Option)을 넣으면 게임이 멈추므로 넣지 않는다 | [입력] | 높음 |
| 0x5DC9~ | P1 커맨드 블록: 0x5DCA 새로 누름 · **0x5DCD 리셋(1 을 쓰면 다음 틱에 이력을 비움)** · 0x5DCE 지난 틱 · 0x5DD0 고리 커서(바뀐 프레임 = 틱 프레임) | [입력·ss2sp.c] | 높음 |
| 0x5E51~ | P2 커맨드 블록(+0x88), 리셋 0x5E55. P2 고리는 VS 경로에서만 돈다 | [입력] | 중간 |

버튼 뜻: **A = 베기**(짧게 떼면 약 0x50, 8프레임 넘게 누르면 강 0x60) · **B = 발차기**(0xA0) · **A+B = 분노가 오르는 게임 고유 동작**(빛기둥, 도발로 보임, 이름 미확인) [입력·타격·조사]. 그래서 A+B 는 연습 단축키로 못 쓴다.

**한 틱의 입력 흐름**(손으로 푼 코드 + 실험) [입력]:
```
0x2002B6  56F1←56ED ; 56ED←6F82 ; 56EE←새로 누름
0x21CEDA  CP (57D4),1
  [VS]    5A6B←(570D)&7F ; 5C6B←(5715)&7F
  [1인]   5A6B←(6F82)&7F ; 5C6B←0            ← P2 는 늘 0
0x21CFE1  (새로 누름 P1|P2) & 0x40 → 일시정지
0x21D0C8  P2 커맨드 고리는 VS 일 때만
0x21F110  BIT 0,(블록+5) → 1 이면 CPU 루틴(0x229ECB), 0 이면 사람 갈래
```
게임 로직은 **2프레임에 한 번**(30Hz) 돈다. 프레임 수는 늘 짝수로 나온다.

- 타이머 칸 타일 덮어쓰기(깜빡임) [설계].

## 3. 기능 목록

### 3-가. 공통 틀

- **«라운드 진행» 조건**: `0x40A7==241 && 0x411A==1 && 0x5824==0`. 경기 쪽 쓰기는 모두 이때만 한다. 라운드 준비 코드가 0x57D4 등을 읽는 동안 끼어들지 않게 하려는 것이다[입력].
- **«중립» 조건**(리셋·재설정용): 둘 다 `0x59CE==0 && 0x5BCE==0`, 둘 다 Y = 128, `0x5DC7==0`, `0x41C2` = 라운드 시작 때 값(장풍·효과 없음).
- **부르는 곳**: 지금 리그와 같다. `native.c` 가 진짜 프레임(`retro_run`) 뒤 코어 잠금 안에서 `league_vram` → `league_tick_hub` → (새) `practice_tick(ram, input)` 을 부른다. 입력 콜백은 지금 식에 «더할 비트»를 하나 더한다: `ovr_on ? ovr_mask : ((g_input & ~in_block) | in_or)`.
- **켜는 곳**: 일반 세션이고 롬이 확인된 판일 때만 연습 허브를 켠다. 리그처럼 코어를 올리고 내릴 때마다 끈다. 상태 불러오기 때도 끈다.

| F8 | **대미지 표시** | 맞은 쪽 콤보 수(0x5A97/0x5C97)가 0→1 이면 새 콤보. 매 프레임 체력이 준 만큼 더한다(바닥 64 를 쓰기 **전에** 읽음). HUD 셋째 줄 가운데(칸 9·10, 세 자리면 8~10)에 `(4<<9) | (0x002 + 숫자)` 를 매 프레임 쓴다. 다음 콤보까지 남긴다. 끄거나 나갈 때 원래 칸 값으로 | 잡기 대미지는 약 22프레임 늦게 들어온다(콤보 수는 이미 올라 있어 합에 들어감). 게임 «N HITS» 는 3타부터 양옆에 뜨고 가운데는 비어 있다 |
| F9 | (작은 것) **«COM» → «2P»** | 더미가 CPU 가 아닐 때 타일 0x049·0x04A 그림을 «2P» 로(게임 «1P» 타일 0x03B·0x03C 에서 «1» 만 «2» 로 그림). CPU 로 돌아가거나 나가면 원래 그림 | 리그 머리말처럼 원래 타일을 보관했다 되돌린다 |
| F10 | **나가기** | 메뉴 «다시 고르기» → 리셋 → 허브가 로고를 넘겨 «연습 대전» → 상대 선택(리그 재대결 길, 약 1초). «타이틀로» → 리셋 → 셋째 줄에 커서 | 리셋 전에 연습 상태를 모두 끈다(0x57D4·비트·타일). 리셋은 램을 지우므로 게임 쪽엔 남는 게 없다 |

### 3-다. 2단계 — 코어 훅 하나(프레임 앞 패드 거르기)

**왜 훅이 필요한가.** 더미가 입력대로 움직이려면 VS 경로를 써야 한다(`0x57D4 = 1` + `0x5BCB` bit0 끔 + `0x5715` = 더미 패드). 그러면 P1 도 하드웨어 패드 대신 `0x570D` 를 읽는다. P1 패드를 `0x570D` 로 옮기는 때에 따라 지연이 생긴다[입력]:

| 키를 누른 프레임 k | 원래 게임 | 프레임 앞에서 0x570D 쓰기 | retro_run 뒤에 0x6F82 베끼기 |
|---|---|---|---|
| 짝수 | +1 | +1 | +1 |
| 홀수 | +0 | +0 | **+2** |

**훅 제안.** 코어 `Emulate()` 에서 SP 엔진 뒤, `storeB(0x6F82, *chee)` 바로 앞에서 앱이 준 함수를 부른다. 예: `retro_ngp_padhook(int (*fn)(int pad, uint8_t *ram))`. 함수는 걸러진 P1 패드를 돌려주고, 연습이 켜져 있으면 `0x570D` = 그 패드 & 0x7F, `0x5715` = 더미 패드를 쓴다.
- 지연 0, SP 엔진 출력도 살아 있다[입력].
- 리그가 `retro_ngp_palremap` 을 코어에 넣은 것과 같은 길이다(동봉 코어).
- 런어헤드·프레임 생성의 숨은 프레임에서도 불린다 → 함수는 순수해야 한다(진짜 프레임 뒤에 정해 둔 값만 쓴다).
- 훅이 없으면 «retro_run 뒤 베끼기»로 돌아간다(홀수 프레임 +2). 호스트 시험은 이걸로도 된다.
- 실제 통신 대전도 0x57D4 = 1 을 쓰므로, 반드시 «연습 켜짐» 표시로 가린다[입력].

| # | 기능 | 어떻게 | 위험 |
|---|---|---|---|
| S1 | VS 경로 켜고 끄기 | 라운드 진행 중에만 `0x57D4=1`, `0x5BCB &= ~1`. 그 밖엔 원래 값으로(0x57D4 원래 값, bit0 다시 켬). `dummy_ref.py` 그대로 | 라운드 사이에도 1 로 두면 P2 가 다른 팔레트로 나온다(0x5D51 0x90→0x94). 가리면 라운드 2 도 정상[입력] |

| S8 | CPU 세기 | 0x5CF5(P2 실시간 단계)를 매 프레임 쓰기 | 효과 미확인 |
| S9 | 카드 지정 | 전투 로드 전 0x57DC/DD 에 카드 id 를 써서 올카드 해금 없이 고른다(세이브 오염 걱정 없음) | 직접 쓴 카드가 먹는지 미확인 |

### 3-라. 나중

- 입력 표시(게임 화면엔 자리가 없다 → 앱 띠 후보), 히트박스(박스 데이터 해석 필요), 랜덤 슬롯·가중치 재생, 기술 목록에서 리버설 고르기, 히트스톱 끄기(0x5DC7=0 매 프레임 — 유불리는 그대로[타격]), 날아가는 장풍 지우기(RE 필요), 리그 세션에서 «콜 기다리며 연습»(랭크매칭 문서 3-다(2)).
- 무기 날림은 넣지 않는다. 아수라 MAX 비오의에 맞아도 샬럿은 칼을 그대로 들고, 동작·대미지가 같았다[상태].

### 3-마. 코드 구조 (짧게)

- `practice.c/.h`(새): 경기 중 기능(F2~F9)과 메뉴 창. 상태는 C 안에만 두고, Java 에는 읽기 전용 상태 배열과 «나가기 요청»만 준다.
- 타이틀·상대 선택(F1·F10)은 league.c 허브를 «종류(리그/연습)»로 넓혀 같이 쓴다. 메뉴 글자 판별(`menu_kind`), 머리말(`hdr_put`), 오른쪽 세로 칸(`vp_put`), 대신 누르기(`nav`), 리셋 뒤 돌아오기가 그대로 쓰인다.
- 글자 타일은 `hub_glyphs.py` 처럼 빌드 때 만든다(`practice_glyphs.py` → `practice_glyphs.h`): 메뉴 글꼴 7px 음절 타일, «연습»·«PRACTICE» 메뉴 글자, «2P», 부호 «+ −», 테두리.
- 나가기: 메뉴에서 고르면 `practice` 가 요청을 세우고, native.c 가 같은 잠금 안에서 `c_reset()` 뒤 허브 돌아오기를 부른다(리그 `nativeLeagueHubReturn` 과 같은 순서).

### 4-가. 들어가는 곳 — 추천: 타이틀 셋째 줄 «연습 대전»

| 후보 | 좋은 점 | 나쁜 점 | 판단 |
|---|---|---|---|
| **셋째 줄 «2 인 대전» → «연습 대전»(일반 세션)** | 앱에선 통신 대전이 안 돼 빈 칸이다[0단계] — 진짜 모드를 안 잃는다. 리그가 같은 칸·같은 기술을 이미 실기·롬 6판으로 검증했다. «2 인» 두 타일만 «연습»으로 바꾸면 «연습 대전»이 된다. 현대 게임 메인 메뉴의 «트레이닝» 자리와 같다 | 리그 세션과 같은 칸을 쓴다(세션마다 뜻이 다름). 통신이 언젠가 되면 다시 정해야 한다 | **추천** |
| 무한 대전 줄 바꾸기 | — | 진짜 모드(연승 카드 보상·CPU 뽑기 규칙)를 잃는다 | 안 함 |
| 카드 모음집 줄 바꾸기 | 리그 세션에선 올카드라 쓸모없는 줄 | 일반 세션에선 카드 보기를 잃는다 | 리그 세션 안 연습의 후보로만 |
| 타이틀에서 Option | 메뉴를 안 건드린다 | 게임이 타이틀에서 Option 에 무엇을 하는지 안 쟀다. 숨은 커맨드는 찾기 어렵다 | 안 함 |
| 리그 흐름 안 | 상대 선택을 같이 쓴다 | 리그 세션은 랭크전 롬 사본·전용 세이브·상태 저장 막기라, 연습에 필요한 «상황 기억»과 부딪친다. 점수와 섞인다 | 안 함 |
| 앱 런처 카드 | 쉽다 | «실기 느낌»과 반대 | 보조로만: 실행 창 아래 «연습 대전으로 ›» 링크(리그 링크와 같은 모양) |

- 리그 세션에서도 연습을 하게 하려면(«콜 기다리며 연습», 나중) 셋째 줄에서 ←/→ 로 «리그 대전 ↔ 연습 대전»을 바꾸는 안을 먼저 본다. 게임이 타이틀 메뉴에서 ←/→ 를 쓰지 않는지 재야 한다.
- 순정 롬 메뉴는 «PRACTICE» 로 쓴다. 글자는 메뉴에 이미 있는 것을 다시 쓴다(P·A = PLAY, R = SURVIVAL, C·T·I = COLLECTION, E = GAME — 리그 «LEAGUE» 와 같은 방법). «VS PLAY» 줄은 7칸(둘째 판 14줄 5~11칸)이라 한 칸이 더 필요하다. 12칸이 비었는지 확인하고, 안 비었으면 메뉴 글자로 되는 7칸 이하 낱말로 바꾼다.
- 연습 세션은 사용자의 원래 세이브를 쓴다. 그래서 **올카드 해금은 1단계에서 하지 않는다**(세이브 오염 주의[0단계]). 카드 화면은 가진 카드만 나온다. 카드는 2단계 S9 로 따로 고른다.

### 4-나. 흐름

```
타이틀 셋째 줄 «연습 대전» A
  └▶ (허브: 커서 0 + A 대신) 1인 대전 캐릭터 고르기 = 머리말 «상대 선택»
        커서 = 더미 캐릭터 · A = 수라로 · B = 나찰로 · Option = 스테이지(오른쪽 세로 칸)
  └▶ 머리말 «캐릭터 선택»으로 되돌림 → 내 캐릭터·유파(원래 그대로, Option = 컬러 · B = 2P색으로 결정) 〔177 정리: 175부터 B 도 보통 색으로 결정 — «B = 2P색» 없앰(166-4). 2P색은 거울전에 게임이 상대에 쓰는 색 · 상대 컬러 거울 대신 색으로만〕
  └▶ 카드 화면(가진 카드만) → 이야기·대사는 A 대신 눌러 넘김
  └▶ 첫 라운드 시작 = 연습 시작 (시간 ∞ · KO 없음 · 더미 서기)
        Option 탭 → 일시정지 + 연습 메뉴 · Option+방향 → 리셋
  └▶ 메뉴 «다시 고르기» → 리셋 → «상대 선택» / «타이틀로» → 리셋 → 셋째 줄
```

### 4-다. 상대(더미) 고르기

- 리그의 «상대 선택» 그대로: 머리말 타일(«캐릭터» → «상대»), 상대 고르는 A 를 게임 대신 받기, 뗄 때까지 안 넘기기.
- **A = 수라 더미, B = 나찰 더미.** 이 게임은 상대 유파를 고르는 화면이 없다. 네오지오식으로 «누른 버튼으로 갈린다»(리그의 A 기본색 · B 2P색과 같은 생각).
- **Option = 스테이지.** 오른쪽 세로 이름 칸에 스테이지 이름(리그의 HUB_VLAB 그대로). 무작위 → 0 → … → 7 → 무작위. 처음 값은 지난번 값.
  - 리그는 같은 화면에서 B 가 스테이지다. 연습은 B 를 유파에 썼으므로 스테이지를 Option 으로 옮겼다. 띠 안내에 적는다.
- 15명 모두 고를 수 있다. 가운데 무작위 칸 = 유가(리그와 같다). 더미는 AI 가 필요 없으므로 리그 상대가 없는 캐릭터도 된다.
- 싸우지 않는 6조합(소게츠 수라·리무루루/한조/주베이/모로즈미/나코루루 나찰)도 더미로는 된다. 다만 메뉴에서 «CPU» 를 고를 수 없게 한다[0단계].

### 4-라. 경기 중 버튼

| 입력 | 연습 중 | 게임이 보는 것 |
|---|---|---|
| 방향·A·B | 원래 게임 그대로 | 그대로 |
| A+B | 원래 게임 그대로(분노 오르는 동작) | 그대로 |
| **Option 탭**(누르는 동안 다른 버튼 없음) | 뗄 때 일시정지 + 연습 메뉴 | 허브가 Option 을 4프레임 대신 누른다 |
| **Option + ↓** | 리셋(메뉴에서 고른 리셋 위치) | 아무것도 못 봄 |
| **Option + ← / →** | 왼쪽 벽 / 오른쪽 벽으로 리셋(리셋 위치도 이걸로 바뀜) | 아무것도 못 봄 |
| **Option + ↑** | 가운데로 리셋 | 아무것도 못 봄 |
| Option + A / B | 2단계: 녹화 시작·끝 / 재생·멈춤 | 아무것도 못 봄 |

- **Option 을 누르고 있는 동안 Option·방향·A·B·SP 버튼(코어가 A+B·원버튼으로 접는 Y·X·L·R)은 게임에 안 준다**(입력 콜백 `in_block`). 조합 입력이 캐릭터 동작으로 새지 않게 하려는 것이다.
- 일시정지는 누를 때가 아니라 **뗄 때** 걸린다. 탭인지 조합인지 떼기 전엔 모르기 때문이다(현대 게임의 «Select+방향» 리셋과 같은 방식).
- 리셋 위치(화면 그대로, 누른 쪽 벽으로 둘이 붙는다):
  - 가운데: 왼쪽 120 · 오른쪽 200, 카메라 80(라운드 시작과 같음).
  - 왼쪽 벽: 왼쪽 24 · 오른쪽 104, 카메라 0. 오른쪽 벽: 왼쪽 216 · 오른쪽 296, 카메라 159.
  - 간격 80 은 라운드 시작과 같게 했다. 벽 쪽 값은 찍힌 화면을 보고 다듬는다.
  - 메뉴 «리셋 좌우: 바꿈» 이면 P1 과 더미 자리를 맞바꾼다(방향도 같이 → 돌아서는 동작 없음).
- 터치 패드에서 Option+방향은 두 엄지로 누른다. 기기에서 되는지 본다(5-나).

### 4-마. 연습 메뉴 창 (게임 일시정지 위)

**왜 이 방법인가**(측정 근거, 2-마):
- 일시정지 중엔 게임이 첫째 판·문자 램·스프라이트 램을 안 건드리고, 방향·A·B 를 무시한다. 우리가 그린 것이 그대로 남고, 우리가 버튼을 가져가도 게임이 반응하지 않는다.
- 첫째 판은 HUD 판이고 줄 4~16 이 비어 있다. 스프라이트는 모두 가운데 우선순위라, 여기 그린 창이 싸움꾼을 가린다.
- 게임의 «PAUSE» 글자(줄 18)는 그대로 둔다. 원래 일시정지 화면 위에 창이 하나 뜬 모양이 된다.

**자리와 모양**

```
 줄 0  [얼굴][체력·카드][1P]  [ ∞ ]  [COM][체력·카드][얼굴]
 줄 1        수라                          수라
 줄 3  ──────────────── 36 ────────────────      ← 대미지(게임 숫자 타일, F8)
 줄 4        ┌────────────────────┐
 줄 5        │     연습 메뉴      │
 줄 6        │▶ 더미       서기   │             ← 고른 줄은 다른 팔레트(노랑)
 줄 7        │  가드       안 함  │
 줄 8        │  내 분노    보통   │
 줄 9        │  상대 분노  보통   │
 줄 10       │  리셋 위치  가운데 │
 줄 11       │  리셋 좌우  그대로 │
 줄 12       │  숫자       대미지 │
 줄 13       │  지금 리셋         │
 줄 14       │  다시 고르기       │
 줄 15       │  타이틀로          │
 줄 16       └────────────────────┘
 줄 17 [분노 게이지]                   [분노 게이지]
 줄 18  PAUSE
```

- 창 = 첫째 판 **줄 4~16 × 칸 3~16**(14칸 × 13줄 = 112 × 104 px). 화면은 20칸 × 19줄이다.
- 바탕 = 기존 타일 0x001(온통 색 3)에 우리 팔레트. 테두리 = 우리 타일 3개(가로·세로·모서리, 모서리는 뒤집기 비트로 네 개).
- 글자 = 메뉴 글꼴 7px(리그 «리그 대전» 글자와 같은 글꼴), **음절 하나 = 타일 하나**. 지금 보이는 글자만 타일에 올리고 같은 음절은 한 타일을 같이 쓴다. 커서 «▶» 1개. 어림 40개 안팎.
- 타일은 **빌린다**. 열 때 원래 바이트를 보관하고 닫을 때 되돌린다.
  - 1순위: 안 쓰인 후보 0x0D8~0x105(46개). 열 때 스프라이트 램 64칸과 두 판에서 이 타일을 가리키는 곳이 있는지 보고, 있으면 그 타일은 건너뛴다.
  - 모자라면: 메뉴가 열린 동안 스프라이트를 숨기고(스프라이트 램 보관 · 우선순위 비트 0) 싸움꾼 타일 자리 0x057~0x0D7 을 빌린다. 일시정지 중엔 애니메이션이 멈춰 있어 되돌리면 그만이다.
- 팔레트 = 첫째 판 13·14번을 메뉴가 열린 동안만 우리 색으로 쓰고 닫을 때 되돌린다(13 = 흰 글자·회색·검남 바탕, 14 = 노랑·주황·검남). 색은 기기에서 보고 정한다.
- 칸 값은 메뉴가 열린 동안 **매 프레임 다시 쓴다**(리그와 같은 습관, 값이 바뀔 때 다시 그림).

**버튼**

| 버튼 | 메뉴에서 |
|---|---|
| ↑ ↓ | 줄 옮기기 |
| ← → | 값 바꾸기(바로 먹는다) |
| A | «지금 리셋»·«다시 고르기»·«타이틀로» 실행, 값 줄에선 → 와 같음 |
| B · Option | 닫기 |

- **닫는 순서**: ① 바꾼 칸·빌린 타일·팔레트(·숨긴 스프라이트)를 모두 되돌린다 → ② 다음 프레임에 Option 을 4프레임 대신 눌러 게임을 푼다 → ③ A·B·방향은 사용자가 뗄 때까지 게임에 안 준다(풀리자마자 공격이 나가지 않게, 리그의 «뗄 때까지 안 넘긴다»).
- 사용자가 누른 Option 은 메뉴가 열린 동안 게임에 안 준다. 그래야 게임이 풀리기 전에 되돌림을 끝낼 수 있다.
- «지금 리셋» = 닫기 + 리셋 요청(중립에서 실행). 멈춘 동안엔 동작을 끊을 수 없어서다.
- 메뉴가 열린 동안 SP 버튼(Y·X·L·R)도 막는다. SP 엔진이 일시정지 중에 커맨드를 넣어 두면 풀릴 때 기술이 나갈 수 있다.
- 라운드 진행 중이 아닐 때(소개·라운드 콜) Option 은 게임에 그대로 준다. 메뉴는 0x411A==1 일 때만 연다.
- 앱이 상태를 저장하거나 내려갈 때 메뉴가 열려 있으면 먼저 닫는다(되돌림). 우리 그림이 저장된 상태에 섞이지 않게 하려는 것이다.

### 4-바. HUD 숫자·글자

- **대미지(F8)**: 셋째 줄 검은 띠 가운데. 게임 «N HITS» 의 숫자 타일 0x002~0x00B 를 그대로 쓴다 → 글꼴·색이 게임 것이다. 새 타일이 필요 없다.
- **타이머 칸은 건드리지 않는다.** ∞ 여도 게임이 틱마다 다시 써서 깜빡인다(2-마). 타이머 칸을 쓰려면 리그 팔레트 때처럼 코어에 «그리기 직전» 훅이 필요하다 → 나중.
- **«COM» → «2P»(F9)**: 줄 0 칸 12·13 의 타일 그림만 바꾼다.
- 유불리(S6)는 같은 가운데 자리에 «+4»·«−6». 부호 두 타일만 새로 그린다.

### 4-사. 화면 아래 띠(앱)

리그처럼 **버튼 안내만** 둔다. 정보는 게임 화면 안에 있다.
- 상대 선택: «A 수라 · B 나찰 · 옵션 스테이지»
- 내 캐릭터: «A 결정 · B 2P색으로 결정 · 옵션 컬러» 〔177 정리: 175부터 «B 2P색» 안내 없음 — B 도 보통 색 결정(166-4)〕
- 경기: «옵션 연습 메뉴 · 옵션+↓ 리셋 · 옵션+←↑→ 위치»
- 메뉴: «↑↓ 고르기 · ←→ 바꾸기 · A 실행 · B 닫기»

| O-8 | 빈 타일 0x0D8~0x105 | 7상태에서만 봤다 | P-15, 런타임 검사로 막는다 |
| O-9 | 첫째 판 줄 4~16 에 게임이 그리는 때 | 라운드 콜·KO·승리 글자가 여기 뜰 수 있다 | 연습에선 라운드가 안 끝나 안 나올 것. 라운드 시작 연출 동안 메뉴를 막는다(0x411A==1 만) |
| O-10 | A+B 동작의 정체 | 단축키에서 뺐다. 메뉴 설명에 쓸 이름 | 동작 id 0xB0/0xB8 표를 캐릭터별로 |
| O-11 | CPU 세기 고정(0x5CF5) | 2단계 S8 | 매 프레임 쓰고 2400프레임 피해 비교 |
| O-12 | «N HITS» 의 P1 쪽 칸 | 대미지 숫자와 겹치지 않는지 | P1 3타 콤보로 줄 3 차분 |
| O-13 | 앱 체크포인트·상태 불러오기 | 연습 중 저장된 상태를 연습 없이 열면 0x57D4=1·bit0 끔·타이머 ∞ 가 램에 남는다 | 저장 때 연습 상태를 옆 파일로 남기거나, 열 때 램 표시(0x57D4==1 인데 통신 아님)로 «연습 이어 하기» |
| O-14 | 패드 훅의 순수성 | 런어헤드 숨은 프레임에서도 불린다 | 훅 함수는 진짜 프레임 뒤 정한 값만 쓰고, 상태를 바꾸지 않는다 |
| O-15 | 나코루루가 P2(더미)일 때 매 칸 | 리셋 때 매 X | P2 나코루루 상태로 물체 표 덤프 |
| O-16 | 스테이지 7(유가 무대) | 0x5827 = 7 은 끝판 연출이 섞일 수 있다[랭크매칭 문서 4-나] | 연습 진입 시험에 넣는다(P-2) |
| O-17 | 첫째 판 팔레트 12~15 | 메뉴 동안만 쓰고 되돌리므로 위험은 작다 | 싸움 전체에서 쓰이는지 한 번 본다 |
