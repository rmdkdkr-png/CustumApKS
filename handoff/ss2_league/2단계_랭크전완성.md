# SS2 가상 리그 2단계 — 랭크전 완성 (Legacito)

기획서 「NGP 사무라이 쇼다운 2 가상 리그 v1」 5장 2단계: **가상 상대 12명, 순위표, 상대전적, 재대결, 영속 저장 → 재시작 후에도 동일한 기록 유지.**
1단계(상대 1명과 실제 경기 → 결과 자동 기록)를 그대로 쓰고, 상대를 12명으로 늘려 순위표·상대전적·재대결을 붙였다.
상대는 모두 게임의 CPU 다. 닉네임은 지어낸 이름이고, 화면에 «실제 사람이 아님»을 적었다.

## 설치와 실행

1. `Legacito-league-s2.apk` 설치. 1단계 시험판과 같은 패키지(`com.dudu.legacito.league`, 같은 시험 키)라 **덮어 설치하면 1단계 기록을 그대로 잇는다**(아래 «1단계 기록 이어받기»). 정식 Legacito 와는 나란히 깔린다.
2. 런처에서 사무쇼2 카드 → 실행 창 아래 「가상 리그 (시험) — CPU 상대 랭크전 ›」 → 리그 화면.
3. 위에서부터: 진행 중 경기(있으면) → **내 순위 카드** → **가까운 순위**(내 위·아래 두 명씩) → **전체 순위 13명** → 규칙 → 보류·무효 경기.
4. 상대를 누르면 상세(캐릭터·검질·CPU 난도·점수·순위·나와의 전적·재대결 표시·최근 경기·규칙) → **도전**. 경기는 1단계와 같다(1인 대전 캐릭터 고르기까지 자동, 내 캐릭터·검질·카드를 고르면 첫 상대로 그 상대가 나옴).
5. 결판 뒤 결과 창: 최종 승패·승수, 점수·순위 변화, 상대전적, 첫 승, 연승 → **재대결** · **다음: (바로 위 순위 상대)** · **랭킹으로**.

- **조합**: 모두 게임이 CPU 로 내는 24조합(무한 대전 뽑기 표 0x22F952 의 22칸 + 유가 2) 안에서 골랐다. 싸우지 않는 6조합은 명단에 없고, 앱도 그 조합으로는 경기를 만들지 않는다(0단계 «싸우지 않는 CPU»).
- **난도와 초기 점수**: 실측한 난도 구간(0단계 «CPU 난도» — 1인 대전 첫 경기 CPU 단계 1/4/7, 배율 하 00C0/0140 · 중 00D9/0126 · 상 00F3/010C)에 맞춰 쉬움 880~940 · 보통 970~1030 · 어려움 1060~1120. 사용자는 1000 에서 시작해 처음엔 7위다. 쉬움·보통·어려움 4명씩.
- **동점**: 점수 내림차순, 동점이면 직전 순서 유지, 최초 동점은 고정 id 순(나 먼저 — 처음엔 나와 칼끝노인만 1000).
- 칼끝노인(o01)은 1단계와 같은 상대다. 상대 난도는 점수에 따라 몰래 바뀌지 않는다(기획서 3장).

### 1단계 기록 이어받기

1단계 시험판 위에 덮어 설치하면 처음 열 때 기록을 한 번 손본다(`League.upgrade`).
- 빠진 상대 11명을 고정 id 순으로 뒤에 더한다. 칼끝노인 점수·전적, 내 점수·연승, 경기 기록은 그대로.
- 1단계 경기 기록을 시간 순으로 다시 훑어 «첫 승» 경기와 «연승을 끊은 상대»를 채운다.
- 옛 명단(2명)에서 시작해 아직 안 끝난 경기는 시작 순위를 지워, 정산 때 13명 기준으로 다시 잰다(점수 구간은 시작 점수 그대로).
- 바로 저장하고(`roster: 2`), 다시 열어도 두 번 더하지 않는다.
- 기록 파일을 둘 다 못 읽으면(깨짐·다른 판 형식) 새 기록으로 덮지 않고 `league.json.unreadable-<시각>` 으로 이름을 바꿔 남긴다.

### 그 밖에 고친 것

- 리그 화면에서 뒤로 갈 때 `Home` 을 연다. 내부 121 부터 `MainActivity` 는 앱 아이콘 별칭이라, 아이콘을 바꾼 사용자는 옛 코드로는 뒤로 가기에서 앱이 죽었다.
- 롬 확인: 리그 화면을 열 때 랭크전 롬 사본을 만들어 md5 로 지원 판인지 본다. 확인이 끝날 때까지 도전·«다시 시작»을 막고(«롬 확인 중»), 결과 창도 확인 뒤에 띄워 재대결·다음 버튼이 확인 결과를 따른다. 사본은 임시 파일에 쓴 뒤 이름을 바꾼다(게임 창과 동시에 써도 반쯤 쓴 롬이 안 남는다, 실패하면 임시 파일을 지운다).
- 기록 파일을 못 읽는데 옆으로 옮기지도 못하면 새 기록을 메모리에만 두고 **아무것도 저장하지 않는다**(진짜 기록을 덮지 않게) — 리그 화면에 이유를 띄우고 도전을 막는다.
- 무효·보류 저장이 실패하면 메모리를 되돌린다(전엔 «무효»로 굳어 다시 시도할 수 없었고, 그 뒤 실제 경기 결과가 버려질 수 있었다 — 1단계부터 있던 문제). 체크포인트는 저장이 성공한 뒤에 지운다.
- 화면을 돌려 리그 화면이 다시 만들어질 때 지난 결과 창이 또 뜨지 않게 했다.
- 상대 상세에 «내 캐릭터·검질·카드는 도전한 뒤 게임 안에서 고릅니다(전원 올카드)», 결과 창에 내 캐릭터·검질도 보인다.
- 닉네임 뒤 조사(과/와)를 받침에 맞춘다.

## 남은 제약

- **실기 시험 없음**: 이 작업 환경엔 KVM 이 없어 안드로이드 에뮬레이터를 못 돌린다. 화면 코드는 컴파일과 APK 내용(클래스·네이티브 심볼·서명)까지만 확인했다. 리그 화면의 배치·글자 넘침은 기기에서 봐야 한다.
- 실제 경기 시험은 같은 소스의 리눅스 코어(ss2-sp-core main)로 했다. 판정은 게임 램만 보므로 코어의 프레임 생성 차이와 무관하다(1단계와 같음).
- 경기는 늘 «1인 대전 첫 경기»다(1단계와 같음). 승자 잔류·토너먼트는 3단계(0단계 보고서 «무한 대전 상대 뽑기»에 참고할 원작 규칙을 적어 두었다).
- 닉네임·초기 점수는 초안 기본값이다(기획서 1장 «세부 수치는 구현 검토 후 조정»). 초기 점수 구간은 실측한 CPU 설정(단계·배율)에 맞춘 것이지, 난도별 실제 승률로 맞춘 것은 아니다 — 플레이 결과를 보고 조정한다. 바꾸려면 `League.ROSTER` 만 고치면 되고, 이미 있는 상대의 설정은 기록에 남은 값을 쓴다(새로 더하는 상대만 ROSTER 값을 쓴다).
- 상세의 난도 표기 «쉬움 = 하 · 보통 = 중 · 어려움 = 상»은 한글판 메뉴 기준이다. 순정 롬(일본어·영어) 메뉴에는 やさしい/ふつう/むずかしい 로 나온다(적용은 같은 옵션 바이트).
- 이 폴더의 1단계 JVM 시험은 상대 1명 순위를 전제해 2단계 `League.java` 에서 5개가 어긋난다. 1단계 확인 항목은 2단계 시험에 모두 옮겼다.
