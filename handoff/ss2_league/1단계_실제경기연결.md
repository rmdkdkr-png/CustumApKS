# SS2 가상 리그 1단계 — 실제 경기 연결 (Legacito)

기획서 「NGP 사무라이 쇼다운 2 가상 리그 v1」 5장 1단계: **상대 1명, 원작 직접 조작, 최종 결과 감지와 기록.**
가상 상대(칼끝노인 · 우쿄 · 수라 · 난도 보통)를 골라 실제 경기를 하고, 경기 전체 승패가 자동으로 기록되며, 앱을 다시 열어도 기록이 남는 한 사이클을 Legacito 에 넣었다.
상대는 게임의 CPU 다. 화면에 그렇게 적었고, 온라인 사람처럼 보이게 하지 않는다.

## 설치와 실행

1. `Legacito-league-s1.apk` 를 설치한다. 패키지가 `com.dudu.legacito.league`(표시 이름 「Legacito 리그」)라 **정식 Legacito 와 나란히 깔린다.**
   공개 시험 키(`CN=PocketCore fgtest`)로 서명했다 — 정식 Legacito 키는 유저만 갖고 있어서다. 정식판에 넣을 때는 같은 소스를 `release-unsigned` 로 굽고 유저 키로 서명한다(`tools/SIGNING.md`).
2. 처음 켜면 Legacito 와 같이 「모든 파일 접근」을 허용한다. 롬 폴더·한글패치는 Legacito 와 같은 저장소를 쓴다.
3. 런처에서 사무쇼2 카드 → 실행 창 아래 **「가상 리그 (시험) — CPU 상대 랭크전 ›」** → 랭킹 화면.
4. 칼끝노인 → **도전**. 게임이 켜지면 1인 대전 캐릭터 고르기까지 앱이 대신 들어간다. 내 캐릭터·검질·카드를 고르면 첫 상대로 칼끝노인(우쿄)이 나온다.
5. 경기 전체 결판이 나면 게임이 멈추고 리그 화면에 결과 창이 뜬다: 최종 승패와 승수, 점수·순위 변화, 상대전적, 연승. **재대결** 또는 **랭킹으로**.

## 들어간 것

**실행부(native, `league.c`)** — 앱 프레임 루프에서 진짜 프레임마다(retro_run 뒤, 코어 잠금 안) 한 번:
- 대진: 결판 전까지 상대 `0x57DF`·유파 `0x57E0` 를 쓴다. CPU 카드 `0x57E6/7 = 0xFF`(카드 없음).
- 규칙: 옵션 `0x636A` 난도(상대 설정) · `0x636B` 2선승 · `0x636C` 60초 — 롬 세이브 기본값(포인트 1 일 수 있다)에 기대지 않는다.
  난도가 실제로 먹었는지는 결판 때 CPU 단계 `0x5814`(첫 경기 1+3×난도)와 CPU 배율 `0x57E2/0x57E4` 로 남긴다.
- 올카드: 캐릭터·유파 고르기 화면(MODE 240 · SCR 2/4)에서 카드 소유 120칸을 8로. 게임이 모드를 고를 때 세이브에서 다시 읽어 덮으므로 그 뒤에 쓴다.
- 메뉴 자동 진입: 새로 켠 판이면 무장 뒤 20·60 프레임에 A(사이는 뗀다) → 1인 대전 캐릭터 고르기. 그 화면이 30프레임 이어지면 손을 떼고, 400프레임 안에 못 닿아도 손을 뗀다. 그동안만 사용자 입력을 막는다.
- 경기 시작: `(0x40A7==241 && 0x411A==1 && 0x5824==0)` 이 서는 첫 프레임 + 승수 0:0 + 이어하기 횟수 `0x5804==0`. 그때 P2 블록을 남긴다.
- 최종 결과: `0x5824` bit7 이 0 인 걸 본 뒤 1 로 서는 **첫 프레임 한 번**. 승자 = 0x40 P1 / 0x20 P2 / 둘 다 없으면 무승부, 승수 `0x5821/0x5822`, P1·P2 블록, 사용자 카드, 실효 포인트·시간, CPU 단계·배율.
  체크포인트에서 재개할 때는(`LEAGUE_FROM_CKPT`) 이미 서 있는 bit7 도 이 경기 결과로 잡는다 — 랭크전은 램이 0 인 새 부팅에서 시작하므로 체크포인트 안의 결판은 이 경기 것뿐이다(정산 직전에 앱이 내려간 경우).
- 코어를 올리거나 내릴 때 무장을 무조건 푼다 — 다음 게임(자유 플레이·다른 코어)으로 새지 않는다.
- 런어헤드·프레임 생성의 숨은 프레임은 코어 안에서 되돌려지므로 여기 오지 않는다(런어헤드 2·프레임 생성 켬에서 끔과 같은 프레임·같은 값 확인).

**앱(Java)**
- `League` — 기록 저장소와 정산. `루트/league/league.json` 원자 저장(임시 파일 → fsync → 이름 바꾸기, 같은 내용을 `.bak` 에 한 벌 더).
  - 시작 전에 경기 id(UUID)·상대·규칙을 저장하고 시작한다. 저장 실패면 시작하지 않는다.
  - 정산 = 결과 + 점수 변경 + 상태(정산 완료)를 **한 번의 저장**으로. 같은 경기 id 는 다시 정산하지 않는다. 저장이 실패하면 메모리를 되돌리고 1초 뒤 다시 한다(결과는 코어 쪽에 그대로 있다).
  - 보류(점수 안 움직임, 원인과 복구 방법 기록): 대진 불일치(결판 때 P2 블록 ≠ 표시한 상대) · 규칙 불일치(실효 포인트·시간 ≠ 2선승·60초 — 무한 대전 같은 다른 모드에서 결판) · 시작 전 롬·코어 불일치.
  - 점수: **시작 때 저장한 두 점수**로 구간 고정, 기획서 3장 표(+18/−6, ±12, +6/−18), 상대에는 내 변화량의 반대. 무승부는 점수 유지·무승부 전적만. 기권은 패배와 같은 변화.
  - 순위: 점수 내림차순, 동점이면 **직전 순위 그대로**(처음엔 고정 id 순). 경기마다 시작 전·후 순위를 남긴다.
  - 경기 상태: ready 준비(첫 라운드 시작 전까지) · playing 진행 중 · resume 복귀 대기 · settled 정산 완료 · forfeit 기권 · hold 오류 보류 · cancelled 무효(첫 라운드 전에 그만둠). 끝난 상태는 다시 안 바뀐다. 열린 경기가 있으면 새 경기를 만들지 않는다. 리그 화면을 열 때 «진행 중»으로 남은 경기는 앱이 경기 중에 내려간 것이라 «복귀 대기»로 바꾼다.
- `LeagueActivity` — 랭킹, 상대 상세(캐릭터·검질·난도·나와의 전적·최근 경기·규칙), 진행 중 경기(상태·사유·복구 방법 표시 · 재개/기권 · 첫 라운드 전이면 «다시 시작»/«무효로 닫기»), 보류·무효 경기 목록(원인·복구 방법), 결과 창. 두 번 눌러 게임 창이 둘 뜨지 않게 막는다.
- `EmuActivity` 랭크전 모드
  - 랭크전 전용 세이브 폴더(`루트/league/saves/`) — 올카드·옵션이 게임오버 때 `.flash` 에 써져도 원작 세이브는 그대로.
  - 원작 오토세이브를 읽지도 쓰지도 않는다. 불러오기·되돌리기·리셋·**저장(슬롯 파일 이름이 자유 플레이와 같다)**·실행 옵션 다시 굽기를 막는다.
  - 시작은 인텐트가 아니라 **경기 상태로** 가른다(시스템이 액티비티를 다시 만들면 처음 인텐트가 그대로 온다): 준비 → 새 판 + 메뉴 자동 진입 · 진행/복귀 대기 → 체크포인트로만 이어감(없거나 못 불러오면 새 판을 열지 않고 리그 화면으로 — 재개 불가면 기권만) · 끝난 경기 → 결과 창.
  - 이미 시작한 경기에서 롬이 바뀌었으면(시작 때 기록한 md5 와 다르면) 보류하지 않고 경기를 복귀 대기로 둔 채(원인·복구 방법 기록) 리그 화면으로 — 판을 바꿔 지는 경기를 무효로 만들 수 없다.
  - 체크포인트: 첫 라운드가 시작된 뒤, 앱이 내려가는 **그 순간**만 임시 파일에 쓴 뒤 이름을 바꿔 넣는다(상태 저장의 쓰기·닫기 실패도 실패로 알리게 고쳤다). 다시 올라오면 지우고, 재개하면 한 번 쓰고 지운다 — 되감기로 못 쓴다.
    결판이 잡혀 있으면 먼저 정산하고, 그 저장이 실패했으면 결판 프레임에 멈춘 채로 체크포인트를 써서 재개 때 같은 결과를 다시 잡는다(결과가 사라지지 않는다).
  - 뒤로 가기·메뉴 바의 목록/종료: 첫 라운드 전이면 계속하기 / 그만두기(무효, 점수 없음). 그 뒤면 계속하기 / 나중에 이어하기(체크포인트 저장이 실패하면 경기에 남는다) / 기권. 창이 떠 있는 동안 게임은 멈춰 있고, 그 사이 결판이 잡히면 창을 닫고 정산한다.
  - 정산 저장이 실패하면 게임은 멈춘 채(메뉴 바를 열고 닫아도) 1초마다 다시 시도한다(결과는 코어 쪽에 그대로). 백그라운드에서 정산되면 앱으로 돌아올 때 결과 창을 띄운다.
  - 게임 화면 밖(위쪽 메뉴 알약 줄 왼쪽)에 «랭크전 · 칼끝노인 (우쿄 · 수라)» — 게임 안 이름(우쿄)과 닉네임(칼끝노인)을 가른다.
- `Patcher.resolveLeague` — 랭크전 고정 사본. `LaunchSheet`·`MainActivity` — 사무쇼2 실행 창에 리그 입구.

## 검수 결과

안드로이드 기기·에뮬레이터는 이 작업 환경에 없다(KVM 없음). 대신 **앱과 같은 C 코드(league.c)를 실제 코어(같은 소스의 리눅스 빌드) 옆에서** 돌리고(`tests/hosttest.py`, Legacito 기본인 런어헤드 2·프레임 생성 켬), 정산 코드는 JVM 에서 돌렸다(`tests/LeagueTest.java`). 코드 리뷰는 세 방향(생명주기·스레드 / 정산·저장·기획서 / 네이티브)으로 두 번 돌리고 지적마다 반박 검증을 붙였다. 1차 17건·2차에서 사실로 확인된 9건을 모두 고쳤다(2차의 «받아 둔 코어로 랭크전이 막힌다»는 지금 앱에선 안 일어난다고 판정됐지만 랭크전 코어를 고정해 미리 막았다).

| 실행 버전 | 여섯 사본(ss2·ss2_h1 × v1.01·동봉판·순정)에서 경기 흐름 통과 |
| 랭킹 | 동점 1000:1000 에서 직전 순위 유지, 순위 변화 기록, 시작 점수로 구간 고정 |

JVM 시험 26항목 모두 통과. 호스트 하네스 시나리오 `t_full.py`(w/l/d) · `t_resume.py`(a→b 진행 중 재개, c→d 정산 직전 재개) · `t_nav.py`(card/nocard) · `t_diff.py`(난도 0/1/2) 모두 통과.

## 남은 제약

- **실기 미확인.** 빌드·서명·심볼·클래스까지 확인했지만 폰에서 돌려 보지는 못했다. 화면 배치(이름표 자리)·패드 입력은 실기에서 볼 것.
- 상대 6조합(소게츠 수라 · 나코루루/리무루루/한조/모로즈미/주베이 나찰)은 덮어쓰면 CPU 가 싸우지 않는다(0단계 «싸우지 않는 CPU», 28 × 30 표). 게임도 이 6조합을 CPU 로 내지 않는다 — 스토리 표에 없고, 무한 대전 뽑기 표(롬 0x22F952)에선 정확히 이 6칸이 막혀 있으며, 무한 대전 안에 강제로 넣어도 싸우지 않는다(0단계 «무한 대전 상대 뽑기»). 앱은 이 조합으로 경기를 만들지 않는다. 1단계 상대 우쿄 수라는 28개 P1 조합 모두 정상. 2단계 명단은 나머지 24조합(= 게임이 CPU 로 내는 조합)에서 고른다.
- 1단계라 가상 상대는 1명. 2단계(12명, 순위표·재대결 확장)는 `League.fresh()` 명단과 `rankOf` 만 늘리면 된다.
- 결판 뒤 게임은 원래 다음 장 이야기로 가지만 앱이 그 자리에서 멈추고 리그 화면으로 돌아간다.
- VS PLAY(통신)는 코어의 링크 케이블 처리가 접속 확인에서 멈춰(2026-08 미완성 그대로) 확인하지 못했다. 리그는 CPU 전이라 무관.
- Legacito 의 조작 패치 `ss2_allcards.ips` 는 세이브의 카드 개수를 255(게임 범위 0~8 밖)로 만들어 카드 모음집 숫자가 깨진다(0단계 재조사에서 발견). 랭크전은 이 패치를 안 쓰고 램으로 올카드를 준다.
