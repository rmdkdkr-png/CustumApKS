# SS2 가상리그 0단계 — 주소 탐색 결과

대상: 사무라이 스피리츠!2 (NGPC, `SAMURAI2v000`) · 코어 ss2-sp-core main(b93d7f6 = Legacito 동봉 코어와 같은 소스, 프레임 생성 끔) · 2026-10-12~13
주소는 모두 **CPU 주소**(0x4000~0x7FFF). 코어 `retro_get_memory_data(SYSTEM_RAM)` 오프셋 = 주소 − 0x4000.
기준 문서: 유저가 준 기획서 「NGP 사무라이 쇼다운 2 가상 리그 v1」(docx) 4장 «먼저 검증할 두 가지»·«연동 모듈에서 필요한 정보».
첫 판은 유저 요지(필수 4·선택 2·결과 감지 규칙·대진 덮어쓰기 검증)로 썼고, 기획서를 받은 뒤 이 판으로 고쳤다 — 맨 아래 «기획서 대조»와 «재조사»가 새로 든 것이다.

## 어떻게 확인했나

- 도구: `ss2probe.py`(이 폴더) — libretro 코어를 ctypes 로 직접 돌려 상태 저장/불러오기, 입력, 램 읽기/쓰기, 프레임마다 16KB 램 기록, 화면 캡처.
  인계 zip 의 `ngp_state` watch 와 같은 용도로 `python3 ss2probe.py watch --core … --rom … --state … --poke 150:0x5C46=0` 를 넣어 두었다.
- 1차(직접): 스토리 1장에서 라운드 결과를 HP 쓰기로 정해 4갈래(2:0·2:1·0:2·1:2) 램 전체 기록 → 승수·결과 비트 탐색, 옵션 화면 값 바꿔 가며 차분,
  상대 뽑기~전투 로드 사이에 덮어쓰기 실험, 유파 원천 바이트 스캔.
- 2차(워크플로 10 에이전트): 가장자리 경우 · 대진 덮어쓰기 0~14 전수 · 카드 · 다른 롬 · **노트를 믿지 않고 다시 찾기** 다섯 갈래를 각각 조사하고,
  주장마다 다른 에이전트가 따로 재현·반박했다. 아래 표는 둘 다 확인한 것만 «확정»으로 적는다.
- 3차(직접): `ss2league_ref.py` 규칙으로 5판 연속(이어하기·무승부 라운드 포함) — 결과 5/5 한 번씩, 상대 5/5 일정대로.

## 선택 2

| 무엇 | 주소 | 값 | 비고 |
|---|---|---|---|
| **CPU 난도** | **0x636A** | 0 やさしい · 1 ふつう · 2 むずかしい | GAME OPTION 블록: 0x636B ポイント(1~3) · 0x636C 시합 시간(0x80 ∞, 0x63 99, 0x3C 60, 0x1E 30) · 0x636D 대전 포인트 · 0x636E 대전 시간. 세이브(플래시)에서 부팅 3 프레임째 읽힘(타이틀에서 모드를 고를 때 한 번 더). 포인트·시간은 **매치 중에 바꾸면 그 매치엔 안 먹고**(0x5813·0x5812 가 이미 복사됨) 다음 상대를 뽑을 때 반영. 난도는 아래 «CPU 난도» |
| **카드 플래그** | **0x57DC / 0x57DD** | 고른 능력 카드 1·2 = (캐릭터<<4)\|(유파<<3)\|k (k 칸 0~3), 0xFF = 없음 | 카드 화면(能力追加)을 나갈 때 씀, 다음 카드 화면까지 유지. 전투 준비마다 여기서 다시 만듦: 0x5B56/0x5B57(전투 중 칸 번호), 0x57D8(공격 배율)·0x57DA(받는 피해 배율, 16비트 0x0100=1.0). 소유 개수: 0x63BA + 8×캐릭 + 4×유파 + k (0~8, 세이브 데이터). 쓰면 줄어드는 «사용» 플래그는 없음 |

카드 화면(能力追加)은 그 캐릭터·유파의 카드를 하나라도 가졌을 때만 나온다(1단계는 안내 글뿐, A → 「する/しない/もどる」, しない = R, A).
**공정 경기용 «카드 없음»:** 결판 프레임부터 다음 전투 로드 전까지 0x57DC = 0x57DD = 0xFF 를 쓰면 다음 판 배율이 1.0, 카드 기술 없음(확정).
소유 개수를 0 으로 만들면 카드 화면 자체가 건너뛰어지지만 세이브 데이터라 플래시에 영구 저장될 수 있어 권하지 않음.

## 결과 감지 규칙

### 요청서 규칙(«상태 = 결과 화면 AND 승수 2, 첫 프레임 1회»)은 그대로 쓰면 틀린다

검증 11+24+40 매치에서 확인된 반례:
1. **무승부 라운드**(더블 KO, 시간 끝 같은 HP)는 **둘 다 +1** — 포인트 2 에서 1:1 → 2:2 가 되고 매치는 계속된다(«승수 2» 오발).
2. 매치 자체가 무승부로 끝날 수 있다(3:3, 0x5824 = 0x90) — 승수 2 아님, P1 은 이어하기 화면(사실상 패배).
3. 결판 라운드가 무승부 라운드일 수 있다(0xD0 = P1 승, 0xB0 = P2 승, 점수 3:1 등).
4. 포인트 3 이면 4:3 까지 간다. **스토리 7~9 장·특수 보스(19)·SURVIVAL 은 1 라운드 매치**(0x5813 = 1).
5. «결과 화면» 상태를 MODE/SCR 로는 못 잡는다(결판 뒤 이름판까지 MODE 241·SCR 8 그대로).

### 권장 규칙 (확정 — 연속 매치 실측에서 매치마다 정확히 1회, 승자 모두 맞음)

```
매 프레임:
  r = peek(0x5824)
  if r & 0x80 == 0:            armed = True          # 붙은 뒤 bit7 을 한 번 0 으로 봐야 시작(낡은 결판 값 무시)
  elif armed:                  armed = False         # bit7 0→1 의 첫 프레임 = 결판 프레임 (MODE 는 늘 241)
      winner = P1 if r & 0x40 else (P2 if r & 0x20 else DRAW)
      score  = (peek(0x5821), peek(0x5822))          # 이 프레임에 이미 최종 점수
```
- 승자는 **반드시 0x5824 의 낮은 비트로** 정한다. SURVIVAL 더블 KO·보스 19 무승부에선 결판이 수백 프레임 늦게 0xA0 로 서고 그때 승수는 1:1 이다(승수로 보면 틀림).
- «결과 화면에서» 쏘고 싶으면 대신 0x5825 가 0 → C0/A0/90 이 되는 프레임 1회(이름판 마지막 프레임). 수명이 10 프레임일 수 있어 매 프레임(최소 8 프레임마다) 봐야 한다.
- 쓰지 말 것: `승수 == 2`, `승수 == 0x636B`(옵션은 이 매치 값이 아님 — 쓴다면 0x5813), SCR 값.

## 대진 덮어쓰기

### 절차 (확정 — 스토리 처음부터 엔딩까지 12판, 지고 이어하기 포함)

```
목표 = 일정[0]
매 프레임:  poke(0x57DF, 목표.id); poke(0x57E0, 목표.유파)       # (+ 카드 없음: poke(0x57DC,0xFF); poke(0x57DD,0xFF))
결판 프레임(위 규칙)에만:  목표 = 일정[다음]
```
왜 이렇게: 게임은 다음 상대를 **뽑는 프레임**(결판 뒤 이야기/장 제목 화면 중, 결판 + 600~2500 프레임)에 0x57DF/0x57E0 을 한 번 쓴다 — 그 전에 쓴 값은 지워진다.
뽑은 뒤부터 **P2 블록 0x5D51 이 만들어지는 전투 로드 프레임 직전까지** 쓴 값은 깨끗하게 먹는다(전투 전 대사·초상·HUD 修羅/羅刹 글·이름판·캐릭터 전부).
로드 뒤에 쓰면 섞인다(대사는 옛 캐릭터, 나중에 몸만 바뀜, 아주 늦으면 초상만). **매치 중에 바꾸면 다음 라운드부터 P2 가 바뀐다** — 결판 프레임에만 목표를 바꾸는 이유.
- 첫 판: 스토리 프롤로그(MODE 241 SCR 0) 중 序章 제목이 뜰 때 뽑는다(그때까지 무작위 — 하드웨어 시계를 씨앗으로 씀). 위 규칙으로 그대로 덮인다.
- 지고 이어하기: 마지막 카드/유파 확정 직후 게임이 그 장 원래 상대를 다시 써 넣는다 — 매 프레임 쓰기면 그 뒤에 다시 덮여 그대로 된다.
- 덮어써도 스토리 진행(0x57FE 0→9)·장 이야기·엔딩(0x57D5)은 그대로. 배경은 장을 따른다(상대 아님). 게임 자신의 뽑기는 덮어쓴 것을 모르니 같은 상대가 다시 나올 수 있다.

## 롬 파일 주의

- `ss2.ngc` 와 `ss2_h1.ngc` 는 **코드가 바이트까지 같다**(0x000000~0x1EFFFF). 다른 28,845 바이트는 전부 카트리지 세이브 영역(0x1F001C~) — 한글판이 아님.
  모든 주소가 두 파일에서 같게 동작함을 확인.
- 세이브에서 옵션과 카드가 온다: ss2.ngc 는 옵션 01 02 3C 02 3C(ふつう·포인트 2·60초), 카드 없음(카드 화면 안 나옴) / ss2_h1.ngc 는 02 01 80 01 80(むずかしい·포인트 1·∞), 카드 있음.
  **유저 세이브에 따라 기본 승수가 1 일 수 있다** → 리그는 0x636B(또는 매치 시작 전 0x5813)를 직접 정하는 게 안전.
- 코어는 게임 중 «저장» 후 언로드하면 세이브 폴더에 `.flash` 를 쓰고, 다음 부팅에 그걸 읽는다 — 남은 .flash 가 옵션·승수를 바꿀 수 있다.
- 첫 상대 무작위는 호스트 시계(부팅 시각 초)를 씨앗으로 쓴다 — 같은 입력이라도 부팅 시각이 다르면 첫 상대가 다르다. 상태 파일에서 시작하면 결정적.

| 경기 시작 | **잡힌다** | `(0x40A7==241 && 0x411A==1 && 0x5824==0)` 이 서는 첫 프레임 + 승수 0:0 + 0x5804==0(이어하기 아님). 입력은 그 2프레임 뒤부터. 전투 중 Option 일시정지로는 다시 서지 않는다. 데모(어트랙트)에는 전투가 없어 헛발이 없다 |
| 사용자 조작 측 | **늘 P1 블록** | 1인 대전에서 화면 좌우가 바뀌어도 입력은 P1(0x5A46·0x5B51). 내 캐릭터 = 0x5B51>>4, 검질 = (0x5B51>>3)&1 — 무작위(쿠로코) 칸을 고르면 캐릭터·검질이 무작위로 정해지므로 고른 뒤 램에서 읽는다 |
| 라운드 승수 | **잡힌다** | 0x5821/0x5822 |
| 경기 최종 승자 | **잡힌다(1회)** | 0x5824 bit7 상승 첫 프레임, 승자 0x40/0x20/없음=무승부 |

«원작 모드가 상대와 진행 순서를 고정한다면 자유 대진이 가능한 것으로 가정하지 않는다» — 스토리는 상대를 롬 표에서 뽑지만(아래 «이어하기»), 매 프레임 덮어쓰기로 자유 대진이 된다. 기획서가 꼽은 세 방법을 모두 해 봤다:

| 방법 | 결과 |
|---|---|
| 원작 메뉴 제어(입력 주입) | 전원·리셋 뒤 «A → 4프레임 이상 뗐다가 A» 로 1인 대전 캐릭터 고르기에 닿는다(전원 뒤 10~420프레임·데모 중 어디서나, 세 롬 같음). 두 A 사이를 안 떼면 실패, A 하나 더면 첫 커서(아수라)가 골라진다. 카드가 있는 세이브면 카드 화면이 끼므로 캐릭터·유파까지 대신 밟는 고정 입력은 깨진다 → 캐릭터 고르기까지만 대신 밟는 게 맞다 |
| 앱이 관리하는 경기 시작 상태 | 캐릭터 고르기 화면 상태를 불러오면 된다. 다만 상태 파일은 롬 판마다 따로여야 하고(한글 VRAM 이 섞인다) 상태 안에 플래시 내용이 실려 다닌다. 타이틀 이전 상태면 옵션·카드가 1인 대전에 들어갈 때 카트리지 값으로 다시 읽힌다 |
| 검증된 상태 수정(램 쓰기) | 된다 — 세션 시작부터 쓰면 첫 상대(프롤로그 무작위)도 덮인다. 깨지는 건 P2 블록이 다시 만들어지는 프레임(전투 로드 + 약 356, SCR 8→10) 뒤에 쓰기 시작할 때뿐(1라운드가 섞인다) |

**1단계 구현(Legacito)은 메뉴 제어(캐릭터 고르기까지) + 상태 수정(대진·옵션·올카드)을 함께 쓴다** — `1단계_실제경기연결.md`.

## 재조사 — 첫 판의 «남은 것»

### 카드

- **얻는 조건**(소유 개수가 느는 곳은 셋뿐): ① 스토리 7장 마물(19) 격파 직후 1장 — P1 캐릭·유파의 ★★★ 카드 고정, ② 스토리 클리어 뒤 카드 공개 화면에서 난도별 2·3·4장(첫 장은 P1 캐릭·유파, 등급은 난도 따라 ★/★★/★★★, 나머지는 아무 캐릭 무작위 — 0x6373=무작위 ★ 장 수·0x6374=무작위 ★★ 장 수), ③ 무한 대전(SURVIVAL) 연승 8·16·24…(44연승까지 끝 없음) 마다 P1 캐릭·유파 1장. 지고 이어해도 상은 같다. 카드 모음집의 주기/받기는 통신 상대가 없으면 아무 일도 없다.
- 지급 대기열 0x636F~0x6374(남은 장수·캐릭·유파·첫 장 등급·무작위 카운터) — 마물·클리어는 0x5825 가 C0 이 된 뒤 2~4프레임, 무한 대전은 연승이 8의 배수가 되는 프레임에 선다. 등급 표(15캐릭 공통): 수라 k0★★ k1★ k2★★★ k3★★ · 나찰 k0★ k1★★ k2★★ k3★★★. 0x63B4/0x63B6/0x63B8 = 난도별 스토리 클리어 횟수, 0x63AA/0x63AC/0x63AE = 난도별 무한 대전 최고 연승.
- **k3 칸(必殺技2)**: 배율은 안 바꾼다(0x57D8=0x57DA=0x0100). 캐릭터마다 다르다 — 분노 MAX ←→↓+A 비오의 강화형은 하오마루 수라(15타→19타)·모로즈미 수라(마지막 타 42→52)·시키 수라 셋, 분노 조건 커맨드형(갈포드 수라·유가 수라/나찰), 그 밖은 분노와 무관한 커맨드·기술 강화. P1 분노 0x5A47(0~0x30, 0x30=MAX), MAX 유지 타이머 0x5A48/0x5A49 — **램에 0x30 을 써도 진짜 MAX 모드는 안 된다**(타이머가 안 줄고 MAX 기술이 안 나감), 시험은 실제로 맞아서 MAX 를 만들어야 한다.
- **CPU 도 카드를 가진다**(첫 판의 «0x5D56/57 은 늘 FF» 는 틀림): 0x57E6/0x57E7 = CPU 카드 id(P1 의 0x57DC/DD 와 같은 형식), 다음 상대를 뽑는 프레임에 써지고 전투 로드 때 0x5D56/57 = id&3. 원래 게임은 8·9장(유가)에서만 쓴다 — 상대가 아니라 **뽑는 순간의 장(0x57FE)** 으로 정해진다. 무한 대전은 연승 13~25 에 k0/k1, 26 부터 k2/k3 도 쓴다. 대진 덮어쓰기와 같은 창에 0x57E6/7 을 쓰면 상대에게 카드를 주거나(먹는다) 0xFF 로 뺄 수 있다.
- **CPU 배율**: 0x57E2 = CPU 공격 배율, 0x57E4 = CPU 가 받는 피해 배율(16비트, 0x100 = 1.0) — 장·난도에 따라 기본값이 다르다(예: 1장 0x00D9/0x0126). 리그는 늘 1인 대전 **첫 경기**에서 싸우므로 같은 난도면 상대가 바뀌어도 이 값이 같다. 0x57E3 은 0x57E2 의 윗바이트다(첫 판 표의 «보스 플래그 아님»과 같은 말).
- 옵션(0x636A~C)도 타이틀에서 모드를 고를 때 카트리지 값으로 다시 읽힌다 — 승수·시간·난도는 캐릭터 고르기 뒤(또는 계속) 써야 한다. MODE 240·SCR 2/4/6 은 크레딧 뒤 데모에서도 나오지만 모드를 고를 때 다시 읽으므로 해는 없다.
- **올카드 해금**: 소유 개수 0x63BA + 8×캐릭 + 4×유파 + k(120칸)가 1 이상이면 그 카드를 고를 수 있다(최대 8, 8 에서 받아도 8). 게임은 부팅 3프레임째와 **타이틀에서 모드를 고르는 순간** 세이브에서 다시 읽어 램을 덮으므로, 캐릭터·유파 고르기 화면(MODE 240 · SCR 2/4)에서 써야 한다. 마감은 유파 확정 뒤 SCR 4→0 이 되는 그 프레임인데, 유파 A 부터 걸리는 시간이 캐릭터마다 다르다(아수라 42 · 겐쥬로 68 · 샬럿 132 프레임) — 고정 지연이 아니라 SCR 4 동안 써야 한다(1단계 구현이 그렇게 한다). 고른 카드는 실제 전투에 먹는다.
- **세이브 오염 주의**: 게임은 램 0x635A~0x6459(세이브 한 칸, 옵션·카드 개수 포함)를 게임오버·무한 대전 끝·설정 저장(예)·스토리 클리어 때 플래시에 쓰고, 코어는 언로드 때 `.flash` 로 남긴다. 램에 올카드를 쓴 채 이 중 하나를 거치면 카드 120칸이 영구 저장된다. 상태 파일도 플래시 내용을 싣고 다닌다 — 기준은 «게임이 플래시를 썼나»가 아니라 «상태를 만든 세션에 플래시 블록이 있었나»다(부팅 때 `.flash` 를 읽었어도 실린다). 그런 상태를 다른 세이브 폴더에서 열고 언로드하면 그 폴더의 `.flash` 가 덮인다.
  → **랭크전 전용 세이브 폴더**(1단계 구현)로 원작 세이브를 지킨다. 실측: 사용자 `.flash` md5 그대로, 올카드 `.flash` 는 랭크전 폴더에만. 랭크전 체크포인트는 랭크전 세션에서만 열리고, 랭크전 중 상태 저장·불러오기는 막혀 있어 랭크전 상태가 자유 플레이로 건너가지 않는다.
- Legacito 의 조작 패치 `ss2_allcards.ips` 는 공장 세이브 칸에 머리글·옵션만 쓰고 카드 개수를 0xFF(255, 범위 0~8 밖)로 남겨, 카드 모음집 숫자가 깨지고 CPU 난도가 0(하)으로 바뀐다.

### CPU 난도

0x636A(0 하 · 1 중 · 2 상)를 새로 켠 판에서 무장 순간부터 매 프레임 쓰면(1단계 구현 방식) 1인 대전 첫 경기에 먹는다.
확인은 전투 중 램으로 한다(ko101, 같은 입력, 우쿄 수라 상대). 경기 도중에 바꿨을 때 언제 반영되는지는 따로 재지 않았다(랭크전은 경기 중에 안 바꾼다).

| 0x636A | CPU 단계 0x5814 | CPU 공격 배율 0x57E2 | CPU 받는 피해 배율 0x57E4 |
|---|---|---|---|
| 0 하 | 1 | 0x00C0 (0.75) | 0x0140 (1.25) |
| 1 중 | 4 | 0x00D9 (0.85) | 0x0126 (1.15) |
| 2 상 | 7 | 0x00F3 (0.95) | 0x010C (1.05) |

- **읽는 때는 둘뿐**: 다음 상대를 뽑는 프레임, 그리고 지고 이어하기 때 카드 화면이 끝나는 프레임. 전투 중에는 안 읽는다 → 매치 중에 바꾸면 그 매치엔 안 먹는다. 타이틀에서 1인 대전을 고르는 순간 세이브 값으로 다시 읽히므로 그 뒤에 써야 한다.
- **뽑기 프레임에 같이 써지는 실효 바이트**(난도 d, 뽑을 때의 장 s=0x57FE, 이어하기 횟수 n=0x5804):
  - 0x57F5 = d(사본) · 0x5814 = CPU 시작 단계 = max(0, 3d+1+L[s]−n), L = 0,0,0,0,1,1,1,2,2,3 · 0x5815 = 단계 상한 = max(0, 3d+3+M[s]−⌊n/2⌋), M = 0,0,0,1,1,2,3,4,5,6
  - 0x57E2 = CPU 공격 배율 = T[2d+min(⌊s/2⌋,3)], T = C0,CC,D9,E6,F3,100,10C,119 · 0x57E4 = CPU 가 받는 피해 배율 = U[같은 칸], U = 140,133,126,119,10C,100,F3,E6
  - 리그 첫 경기(s=0, n=0): 하 C0/140/1/3 · 중 D9/126/4/6 · 상 F3/10C/7/9 (배율/배율/시작 단계/상한)
- 전투 로드 때 0x5814 가 0x5AF5/0x5CF5(P1/P2 실시간 단계)로 복사된다. 라운드 시작 단계 = max(0, 0x5814 + 상대 승수 − 자기 승수)(상한으로 안 자름). 라운드 중엔 약 602프레임마다 다시 정해지고(0~0x5815), 사람이 막기만 하면 오르고 맞거나 때리면 내린다.
- **효과 크기**: 난도 차이의 대부분은 피해 배율이다. 실측 한 표본(15상대 × 봇 7종, 2400프레임)에서 P1 이 받은 피해 하/중/상 85.5/99.7/113.1, KO 12/23/48 이었지만, 독립 표본(12상대 × 봇 4종)에서는 +11%(유의하지 않음)였다 — 숫자는 표본에 따라 크게 흔들린다. 배율을 1.0 으로 묶고 단계만 바꾸면 차이가 작거나 없다.
- 난도를 옵션 없이 고정하려면 결판 뒤~로드 전에 실효 바이트 7개(0x57E2~0x57E5·0x5814·0x5815·0x57F5)를 매 프레임 쓰면 0x636A 를 바꾼 것과 램이 프레임마다 같다(로드 뒤라면 라운드 시작까지 0x5AF5·0x5CF5 까지).
1단계 구현은 결판 때 이 셋을 경기 기록에 남겨(`cpu_level`·`cpu_mult`·`diff_ok`) «난도가 실제로 먹었는지»를 경기마다 확인할 수 있게 했다.

### 싸우지 않는 CPU — 덮어쓴 대진 중 6조합 (상대로 쓰면 안 됨)

28 × 30 표(사람이 고를 수 있는 P1 14캐릭 × 2검질 × 상대 15캐릭 × 2검질, P1 은 가만히, 2400프레임 — `cpu_passive_matrix.csv`)로 재 보니 **P1 이 누구든 상관없이 상대 쪽 6조합만** 이상하다:

| 상대 | 가만히 있는 사람에게 준 피해(28조합 모두) | 다가가 약공격하는 사람에게 준 피해 |
|---|---|---|
| (1,0) 소게츠 수라 | 0 | 0 (사람이 15~16타로 KO) |
| (5,1) 리무루루 나찰 | 0 | 0 |
| (6,1) 한조 나찰 | 0 | 0 |
| (12,1) 주베이 나찰 | 0 | 0 |
| (10,1) 모로즈미 나찰 | 11 | 0 |
| (4,1) 나코루루 나찰 | 27 | 0 |

나머지 24조합은 가만히 있는 사람을 2400프레임 안에 82~128 깎고, 다가가는 사람과도 정상으로 싸운다(대조: 우쿄 수라·겐쥬로 수라).
6조합은 모두 스토리가 내지 않는 검질이다(스토리 표의 상대: 0/1 1/1 2/1 3/1 4/0 5/0 6/0 7/1 8/0 8/1 9/0 10/0 11/0 12/0 13/1 14/0 14/1). 다만 스토리에 없는 다른 검질(카즈키 수라·하오마루 수라·우쿄 나찰 등)은 정상이라, «스토리에 없어서»가 원인이라고 단정할 수는 없다.
→ **리그 상대로는 이 6조합을 쓰지 않는다**(기획서 «미지원 설정을 가능한 것처럼 노출하지 않는다»). 1단계 앱은 이 조합으로는 경기를 만들지 않게 막았고(`League.oppSupported`), 1단계 상대 우쿄 수라(11,0)는 28조합 모두 정상이다.

### 이어하기 때 «그 장 원래 상대»

램에 따로 없다 — 롬 표 0x218700(파일 0x18700, 8길 × 16바이트, 바이트 = id | (유파<<7))에서 `0x57FF(길 0~7) × 16 + 0x57FE(장)` 칸을 매번 읽는다(코드 0x21867B 한 곳이 첫 판·이긴 뒤·7~9장·이어하기 되쓰기를 다 한다). 9장에서 지면 장이 9→8 로 줄어 8장(유가 수라)부터 다시 한다.
길은 **P1 캐릭터마다 정해진 둘 중 하나**다: 0x57D5(지금 P1)≠0x5806 이면 0x57FF ← 롬 0x21853D[2×P1캐릭터 + (난수&1)](P1≥14 면 난수&7). 그래서 첫 상대 후보도 캐릭터마다 둘뿐이다 — 카즈키·샬럿·모로즈미·시키 → 3/1·7/1, 소게츠·겐쥬로·주베이 → 11/0·10/0, 하오마루·리무루루·우쿄 → 12/0·10/0, 나코루루·한조·갈포드·아수라 → 12/0·9/0.
매 프레임 0x57DF/0x57E0 쓰기면 이 값들을 맞출 필요가 없다(되쓰는 값은 다음 프레임에 덮인다). 0x5841/0x5842 는 «마지막 일반 상대» 사본이고 스토리에서는 화면에 영향이 없다 — 다만 **무한 대전에서 무작위(쿠로코) 칸 + 나찰로 고른 모드**(0x57DE·0x5843≠0)에서는 이 값이 다음 판 P1 캐릭터(0x57D5/0x57D6)로 복사된다(이길 때마다 P1 이 바뀌는 모드).

### VS PLAY(통신)

코어(ss2-sp-core)에 링크 케이블 처리가 있어 `ss2probe.Link` 로 두 대를 프레임 번갈아 이어 봤다. 바이트는 오가지만 접속 확인에서 메뉴로 돌아간다(2026-08 링크 도입 커밋에 «악수가 안 끝난다»로 남은 미완성 그대로). 리그는 CPU 전이라 무관하다.

## 남은 것

- VS PLAY 판정(통신 미완성), 플래시 저널 칸이 다 찼을 때의 동작, CPU 가 k2/k3 카드 기술을 실제로 쓰는지.
- 싸우지 않는 CPU 6조합의 원인(CPU 동작 표가 비었는지 등).

## 이 폴더

- `ss2probe.py` — 탐색 도구(라이브러리 + `watch` 명령 + 링크 케이블 두 대 `Link`).
- `ss2league_ref.py` — 위 결과 감지·대진 덮어쓰기·카드 없음 규칙의 참조 구현(`League(schedule).step(peek, poke)` 를 매 프레임). 5판 연속 실측 통과.
- 상태 파일·롬·램 기록은 저장소에 넣지 않는다(scratchpad 에만).
