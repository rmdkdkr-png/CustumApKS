# SS2 가상리그 0단계 — 주소 탐색 결과

대상: 사무라이 스피리츠!2 (NGPC, `SAMURAI2v000`) · 코어 ss2-sp-core main(b93d7f6, 프레임 생성 끔) · 2026-10-12
주소는 모두 **CPU 주소**(0x4000~0x7FFF). 코어 `retro_get_memory_data(SYSTEM_RAM)` 오프셋 = 주소 − 0x4000.
요청서 원문은 이 세션에서 못 열어서(클로드 프로젝트 파일), 유저가 준 요지(필수 4·선택 2·결과 감지 규칙·대진 덮어쓰기 검증)를 기준으로 했다.

## 어떻게 확인했나

- 도구: `ss2probe.py`(이 폴더) — libretro 코어를 ctypes 로 직접 돌려 상태 저장/불러오기, 입력, 램 읽기/쓰기, 프레임마다 16KB 램 기록, 화면 캡처.
  인계 zip 의 `ngp_state` watch 와 같은 용도로 `python3 ss2probe.py watch --core … --rom … --state … --poke 150:0x5C46=0` 를 넣어 두었다.
- 1차(직접): 스토리 1장에서 라운드 결과를 HP 쓰기로 정해 4갈래(2:0·2:1·0:2·1:2) 램 전체 기록 → 승수·결과 비트 탐색, 옵션 화면 값 바꿔 가며 차분,
  상대 뽑기~전투 로드 사이에 덮어쓰기 실험, 유파 원천 바이트 스캔.
- 2차(워크플로 10 에이전트): 가장자리 경우 · 대진 덮어쓰기 0~14 전수 · 카드 · 다른 롬 · **노트를 믿지 않고 다시 찾기** 다섯 갈래를 각각 조사하고,
  주장마다 다른 에이전트가 따로 재현·반박했다. 아래 표는 둘 다 확인한 것만 «확정»으로 적는다.
- 3차(직접): `ss2league_ref.py` 규칙으로 5판 연속(이어하기·무승부 라운드 포함) — 결과 5/5 한 번씩, 상대 5/5 일정대로.

## 선택 2

| 무엇 | 주소 | 값 | 비고 |
|---|---|---|---|
| **CPU 난도** | **0x636A** | 0 やさしい · 1 ふつう · 2 むずかしい | GAME OPTION 블록: 0x636B ポイント(1~3) · 0x636C 시합 시간(0x80 ∞, 0x63 99, 0x3C 60, 0x1E 30) · 0x636D 대전 포인트 · 0x636E 대전 시간. 세이브(플래시)에서 부팅 3 프레임째 읽힘. **매치 중에 바꾸면 그 매치엔 안 먹고**(0x5813·0x5812 가 이미 복사됨) 다음 상대를 뽑을 때 반영 |
| **카드 플래그** | **0x57DC / 0x57DD** | 고른 능력 카드 1·2 = (캐릭터<<4)\|(유파<<3)\|k (k 칸 0~3), 0xFF = 없음 | 카드 화면(能力追加)을 나갈 때 씀, 다음 카드 화면까지 유지. 전투 준비마다 여기서 다시 만듦: 0x5B56/0x5B57(전투 중 칸 번호), 0x57D8(공격 배율)·0x57DA(받는 피해 배율, 16비트 0x0100=1.0). 소유 개수: 0x63BA + 8×캐릭 + 4×유파 + k (0~8, 세이브 데이터). 쓰면 줄어드는 «사용» 플래그는 없음 |

카드 화면(能力追加)은 그 캐릭터·유파의 카드를 하나라도 가졌을 때만 나온다(1단계는 안내 글뿐, A → 「する/しない/もどる」, しない = R, A).
**공정 경기용 «카드 없음»:** 결판 프레임부터 다음 전투 로드 전까지 0x57DC = 0x57DD = 0xFF 를 쓰면 다음 판 배율이 1.0, 카드 기술 없음(확정).
소유 개수를 0 으로 만들면 카드 화면 자체가 건너뛰어지지만 세이브 데이터라 플래시에 영구 저장될 수 있어 권하지 않음.

## 결과 감지 규칙

### 요청서 규칙(«상태 = 결과 화면 AND 승수 2, 첫 프레임 1회»)은 그대로 쓰면 틀린다

검증 11+24+40 매치에서 확인된 반례:
1. **무승부 라운드**(더블 KO, 시간 끝 같은 HP)는 **둘 다 +1** — 포인트 2 에서 1:1 → 2:2 가 되고 매치는 계속된다(«승수 2» 오발).
2. 매치 자체가 무승부로 끝날 수 있다(3:3, 0x5824 = 0x90) — 승수 2 아님, P1 은 이어하기 화면(사실상 패배).
3. 결판 라운드가 무승부 라운드일 수 있다(0xD0 = P1 승, 0xB0 = P2 승, 점수 3:1 등).
4. 포인트 3 이면 4:3 까지 간다. **스토리 7~9 장·특수 보스(19)·SURVIVAL 은 1 라운드 매치**(0x5813 = 1).
5. «결과 화면» 상태를 MODE/SCR 로는 못 잡는다(결판 뒤 이름판까지 MODE 241·SCR 8 그대로).

### 권장 규칙 (확정 — 연속 매치 실측에서 매치마다 정확히 1회, 승자 모두 맞음)

```
매 프레임:
  r = peek(0x5824)
  if r & 0x80 == 0:            armed = True          # 붙은 뒤 bit7 을 한 번 0 으로 봐야 시작(낡은 결판 값 무시)
  elif armed:                  armed = False         # bit7 0→1 의 첫 프레임 = 결판 프레임 (MODE 는 늘 241)
      winner = P1 if r & 0x40 else (P2 if r & 0x20 else DRAW)
      score  = (peek(0x5821), peek(0x5822))          # 이 프레임에 이미 최종 점수
```
- 승자는 **반드시 0x5824 의 낮은 비트로** 정한다. SURVIVAL 더블 KO·보스 19 무승부에선 결판이 수백 프레임 늦게 0xA0 로 서고 그때 승수는 1:1 이다(승수로 보면 틀림).
- «결과 화면에서» 쏘고 싶으면 대신 0x5825 가 0 → C0/A0/90 이 되는 프레임 1회(이름판 마지막 프레임). 수명이 10 프레임일 수 있어 매 프레임(최소 8 프레임마다) 봐야 한다.
- 쓰지 말 것: `승수 == 2`, `승수 == 0x636B`(옵션은 이 매치 값이 아님 — 쓴다면 0x5813), SCR 값.

## 대진 덮어쓰기

### 절차 (확정 — 스토리 처음부터 엔딩까지 12판, 지고 이어하기 포함)

```
목표 = 일정[0]
매 프레임:  poke(0x57DF, 목표.id); poke(0x57E0, 목표.유파)       # (+ 카드 없음: poke(0x57DC,0xFF); poke(0x57DD,0xFF))
결판 프레임(위 규칙)에만:  목표 = 일정[다음]
```
왜 이렇게: 게임은 다음 상대를 **뽑는 프레임**(결판 뒤 이야기/장 제목 화면 중, 결판 + 600~2500 프레임)에 0x57DF/0x57E0 을 한 번 쓴다 — 그 전에 쓴 값은 지워진다.
뽑은 뒤부터 **P2 블록 0x5D51 이 만들어지는 전투 로드 프레임 직전까지** 쓴 값은 깨끗하게 먹는다(전투 전 대사·초상·HUD 修羅/羅刹 글·이름판·캐릭터 전부).
로드 뒤에 쓰면 섞인다(대사는 옛 캐릭터, 나중에 몸만 바뀜, 아주 늦으면 초상만). **매치 중에 바꾸면 다음 라운드부터 P2 가 바뀐다** — 결판 프레임에만 목표를 바꾸는 이유.
- 첫 판: 스토리 프롤로그(MODE 241 SCR 0) 중 序章 제목이 뜰 때 뽑는다(그때까지 무작위 — 하드웨어 시계를 씨앗으로 씀). 위 규칙으로 그대로 덮인다.
- 지고 이어하기: 마지막 카드/유파 확정 직후 게임이 그 장 원래 상대를 다시 써 넣는다 — 매 프레임 쓰기면 그 뒤에 다시 덮여 그대로 된다.
- 덮어써도 스토리 진행(0x57FE 0→9)·장 이야기·엔딩(0x57D5)은 그대로. 배경은 장을 따른다(상대 아님). 게임 자신의 뽑기는 덮어쓴 것을 모르니 같은 상대가 다시 나올 수 있다.

| 1 | 風間蒼月 | 6 | 服部半蔵 | 11 | 橘右京 |
| 2 | 覇王丸 | 7 | ガルフォード | 12 | 柳生十兵衛 |

## 롬 파일 주의

- `ss2.ngc` 와 `ss2_h1.ngc` 는 **코드가 바이트까지 같다**(0x000000~0x1EFFFF). 다른 28,845 바이트는 전부 카트리지 세이브 영역(0x1F001C~) — 한글판이 아님.
  모든 주소가 두 파일에서 같게 동작함을 확인.
- 세이브에서 옵션과 카드가 온다: ss2.ngc 는 옵션 01 02 3C 02 3C(ふつう·포인트 2·60초), 카드 없음(카드 화면 안 나옴) / ss2_h1.ngc 는 02 01 80 01 80(むずかしい·포인트 1·∞), 카드 있음.
  **유저 세이브에 따라 기본 승수가 1 일 수 있다** → 리그는 0x636B(또는 매치 시작 전 0x5813)를 직접 정하는 게 안전.
- 코어는 게임 중 «저장» 후 언로드하면 세이브 폴더에 `.flash` 를 쓰고, 다음 부팅에 그걸 읽는다 — 남은 .flash 가 옵션·승수를 바꿀 수 있다.
- 첫 상대 무작위는 호스트 시계(부팅 시각 초)를 씨앗으로 쓴다 — 같은 입력이라도 부팅 시각이 다르면 첫 상대가 다르다. 상태 파일에서 시작하면 결정적.

## 남은 것

- VS PLAY(통신)는 에뮬레이터 혼자 못 돌려 미확인. SURVIVAL·스토리·엔딩은 확인.
- 카드 k3(必殺技2) 효과, 카드를 얻는 조건, CPU(P2) 카드(0x5D56/0x5D57 은 늘 0xFF).
- 이어하기 때 게임이 되돌려 쓰는 «장 원래 상대»가 어디 저장돼 있는지(매 프레임 쓰기로는 상관없음).
- 요청서의 정확한 제출물 형식은 원문을 받으면 맞춘다.

## 이 폴더

- `ss2probe.py` — 탐색 도구(라이브러리 + `watch` 명령).
- `ss2league_ref.py` — 위 결과 감지·대진 덮어쓰기·카드 없음 규칙의 참조 구현(`League(schedule).step(peek, poke)` 를 매 프레임). 5판 연속 실측 통과.
- 상태 파일·롬·램 기록은 저장소에 넣지 않는다(scratchpad 에만).
