## 1. 생성기 — 인계문 §6 의 난제가 풀렸다

「실행기 함수 이름 ↔ `EV_*` 63개 대응표 역산」이 끝났다. 기계적이었다.

실행기 키는 **69개**다. 그중

- `hello` → `HELLO[]` (이벤트가 아니다)
- `REL` → `RELLINE[][]` (상대별 객체, 이벤트가 아니다)
- `muse` 하나가 `d.ctx` 로 `MUSE_B`(battle) · `MUSE_Q`(quote) · `MUSE_M`(그 외) 셋으로 갈린다

를 빼면 정확히 **63개**가 `EV_*` 와 1:1 로 맞는다.

C 에 자리가 없는 **실행기 전용 여섯**: `domLead` `domBehind` `halfHp2` `halfHp1` `rush` `oppInfo`.
자리를 만들려면 `gen_lines.js` 의 `EV` 목록과 `ss2comm.c` 의 emit 을 같이 고쳐야 한다.

### 어떻게 뽑나

```sh
node tools/gen_lines.js index.html <출력 ss2comm_lines.h> [--check <기존 헤더>] [--dups] [--evmaxv N]
```

세 가지가 핵심이다.

1. **헤드리스로 진짜 실행기를 띄운다.** `SPEAKERS` 의 값은 문자열이 아니라 함수이고
   `pick()` `NM()` `RO()` `NR()` 와 `cfg` 를 물고 있다. `?debug=1` 로 열면 `window.__ss2` 에
   `SPEAKERS` 와 `cfg` 가 같이 나온다. 인계문이 「스텁 쓰지 마라」고 한 그대로다.

2. **`Math.random` 을 갈아끼워 전수 열거한다.** `pick(a){ return a[(Math.random()*a.length)|0]; }`
   이므로 `r=(i+0.5)/120` 을 훑으면 난수가 아니라 모든 칸이 한 번씩 나온다.
   그 뒤 무작위로 3,000번 더 돌려, 훑기가 놓친 조합이 있으면 알려 준다.
   **옛 생성기는 난수로 만나는 대로 쌓았다.** 그래서 옛 표의 변주 순서가 뒤죽박죽이었다.

3. **유파 양쪽을 다 돈다.** `RSTS()=>cfg.style==="b"` 이고 `NR(수라문안, 나찰문안)` 로 갈린다.
   나코루루처럼 인격이 둘인 화자는 `cfg.style` 을 `s`·`b` 로 다 돌려야 열 개가 다 나온다.

`CHARS` · `CHAR_BY_IDX` · `CHAR_LORE` · `FACE_ROM` 은 `__ss2` 로 안 나온다.
이 넷은 함수가 아니라 숫자·문자열뿐인 표라 **리터럴 원문을 그대로 평가**한다(스텁이 아니라 원문 자체다).
실행기가 나중에 이 넷도 `__ss2` 로 내보내면 그때는 페이지에서 바로 읽는 편이 낫다.

### 대조 결과

- `RELLINE` · `SS2COMM_FACE_ROM_INIT` — **바이트 단위로 동일하게** 재현
- `LORE` — 내용 동일 (마지막 항목 쉼표 하나만 다름, C 에서 유효)
- `LINES` 945칸 — 아래 §2·§3 참고

## 2. 옛 표에서 대사가 잘려 있었다

`EVMAXV` 가 10 으로 굳어 있었는데 `charselChat` 이 12·14·12 개다.
`nakoruru` 2줄, `hanzo` 4줄, `galford` 2줄 — **모두 여덟 줄이 조용히 사라져 있었다.**

`ss2comm.c` 는 `cand[EVMAXV]` 와 `i<EVMAXV` 만 쓰고 10 을 하드코딩한 데가 없다.
그래서 생성기는 **필요한 만큼 자동으로 맞춘다**(지금은 14). 굳이 고정하려면 `--evmaxv 10` 을 주고,
그때는 무엇이 잘렸는지 하나씩 알려 준다.

`LINES` 크기는 75,600 → 105,840 바이트로 는다(포인터 배열, 대부분 0).

## 3. **자리 계약** — 이게 제일 중요하다

`ss2comm.c` 가 늘 무작위로 고르는 게 아니다. **일곱 이벤트는 변주 번호를 고정해서 부른다.**

```c
emit_ex(EV_SURV,     rec?0:(surv>=10?1:(surv>=7?2:(surv>=3?3:-1))), …)
emit_ex(EV_RECORD,   sess_wins*2>=sess_games?0:1, …)
emit_ex(EV_STAGE,    (stage+1)>=8?0:((stage+1)>=5?1:-1), …)
emit_ex(EV_STREAK,   sess_streak>=5?0:-1, …)
emit_ex(EV_MOVEHIT,  d>=12?0:2, …)
emit_ex(EV_MOVEDOWN, 0 …)  /  emit_ex(EV_MOVEDOWN, 1, 0,0, 0)   ← 1 은 who=0 (이름 없음)
emit_ex(EV_MOVEKO,   0 …)
```

그런데 `emit_ex` 는 넘치는 번호를 **마지막 것으로 자른다**:

```c
if(vsel >= 0) fmt = cand[vsel < n ? vsel : n-1];
```

옛 생성기가 페이로드 하나만 써서 분기를 접는 바람에 이 자리들이 안 채워져 있었다. 결과:

| 이벤트 | C 가 부르는 자리 | 옛 표 | 실제로 벌어지는 일 |
|---|---|---|---|
| `RECORD` | 0 이김 · 1 짐 | 1개 | **져도 "오늘 %d전 %d승! 술맛 나는 날이군"** |
| `MOVEDOWN` | 0 이름 있음 · 1 **이름 없음** | 2개 (둘 다 `%s` 포함) | **"로 눕혔군!"** — 조사만 남는다 |
| `SURV` | 0·1·2·3 (신기록/10/7/3연승) | 1개 | 넷 다 같은 말. 3연승에도 "전설을 쓰는군" |
| `STAGE` | 0·1 | 1개 | 둘 다 같은 말 |
| `MOVEHIT` | 0 강타 · 2 약타 | 3개 (**전부 강타**) | 약타에도 "묵직하게 박혔군" |

새 생성기는 번호마다 알맞은 갈래를 박고 **그 이벤트만 정렬하지 않는다.**
`emit_ex` 가 빈 칸을 건너뛰며 압축(`if(LINES[..][i]) cand[n++]`)하므로
**중간을 비우면 뒤 번호가 통째로 밀린다.** 그래서 C 가 안 읽는 자리도 같은 갈래로 반드시 채운다.

### 아직 정하지 않은 것 — 사람이 정할 일

`MOVEHIT` · `MOVEKO` · `MOVEDOWN` 은 `vsel` 이 고정이라 **런타임에 변주가 아예 안 돈다.**
표에 열 줄이 있어도 늘 같은 줄만 나온다. 두 길이 있다.

1. **지금 그대로** — 자리 계약만 지키고 이 이벤트는 변주 없음을 받아들인다
2. **`ss2comm.c` 를 고친다** — 강타/약타를 별도 이벤트로 나누고 각각 `vsel=-1` 로 부르면 변주가 산다

`ss2comm_lines.h.new` 는 1번을 따르되 **남는 변주를 뒤에 붙여 뒀다.**
2번으로 가더라도 대사를 다시 모을 필요는 없다. **C 는 건드리지 않았다.**

## 4. 새 헤더를 넣기 전에

- 넣으면 `ss2comm_lines.h` 의 md5 가 바뀐다. **코어판과 앱판을 같이 갱신해라** (§15 세 갈래 규칙).
  한쪽만 넣으면 어긋난다
- 검증 기준표의 `ss2comm_lines.h md5 = e35452004d90fa7b71f3bc818d801d80` 도 새로 잡아야 한다
- 확인한 것: 컴파일 통과, `test_flow.sh` **11/11 통과**, 문자열 3,569 → **3,754개**
- `test_flow.sh` 의 「겹침」이 0 → 1 로 바뀌는데 **회귀가 아니다.** 표 순서가 바뀌어
  런타임 무작위 선택이 다른 줄에 걸린 것뿐이다. `쥬베이`·`소게츠`·`아수라` 가
  "검이 무뎠나. 다시 잡아라" 를 **원래부터 똑같이** 쓰고 있다(실행기 원문에도 3번 있다)

### 덤 — 화자끼리 겹치는 대사가 170건이다

「열다섯 목소리가 서로 다르다」가 이 프로젝트의 약속인데, 실제로는 여러 화자가 같은 문장을 쓴다.
심한 것: `EV_OPPSP` 의 "온다" 를 **일곱 명**이, `EV_FLOWSP` 의 "벌써 필살기 %d번째군" 을 **일곱 명**이 쓴다.
`--dups` 로 전부 볼 수 있다. 대사를 손볼 때 참고해라.

## 5. 이 방에서 실측으로 확인한 것 — 인계문과 다른 부분

- **릴리스 자산은 안 붙은 저장소에서도 받아진다.** `emu-ex-plus-alpha/Pre-release` 와
  `CustumApKS/ngpemu-latest` 둘 다 `http 200` 으로 진짜 APK 가 내려왔다.
  「저장소가 안 붙어서 403」은 이 방에서는 성립하지 않았다
- **정석 CI 릴리스가 낡았다.** `emu-ex-plus-alpha/Pre-release` 의 `assets/gpOverlay.png` 가
  `c434b3d8467673c1766988d6555fe87b` 인데 master 소스와 기준표는 `24bed154fbd45b774a8410e90aaf8483` 다.
  지금 그 주소로 받으면 옛 그림이 든 APK 가 온다. 보험 CI(`CustumApKS`) 쪽이 오히려 기준표와 맞는다
- **`.so` 가 갈리는 것은 경로 탓이 아니라 빌드 환경 탓이다.** 서로 다른 저장소·경로의
  CI 빌드 둘이 `lib/*/libmain.so` 4종을 CRC 까지 똑같이 냈고(두 APK 차이는 `gpOverlay.png` 와
  서명 3종뿐), 서로 다른 경로의 방 빌드 둘도 `.so` 네 개의 크기가 다 같았다.
  방 빌드와 CI 빌드 사이에서만 arm64 가 8바이트 차이 난다(CI 는 temurin JDK · lukka/get-cmake).
  **같은 길로 구운 것끼리는 `.so` md5 가 맞아야 한다.**
  (중간에 「문서의 2,621,888 이 틀리고 2,621,880 이 맞다」고 적었던 것은 잘못이다.
  방 빌드는 2,621,888 이 맞고, 2,621,880 은 CI 빌드 값이었다.)
- **권한은 나중에 다 열렸다.** 처음에는 `CustumApKS` 만 쓸 수 있었고 `add_repo` 가 거부됐는데,
  다시 요청하니 `ss2-sp-core` · `emu-ex-plus-alpha` · `ss2-sp-runner` 셋 다 붙었다.
  **거부됐다고 끝이 아니다 — 다시 해 봐라.**

### 무엇이 틀려 있었나

`RELLINE[yuga][하오마루]` 가 **「하오마루라. 그저 검을 휘두르는 인간이군」**
이었다. 하오마루는 유가가 의식에 **가장 필요로 하는 남자 그릇**이다.
설정과 정면으로 어긋난다. → **「하오마루. 네가 남자 그릇이다」**

### 무엇을 안 건드렸나

`START` 0번 칸의 **「%s… 가엾구나」**. 이게 모로즈미와 붙었을 때
「모로즈미… 가엾구나」가 되는데, 아내와 아들을 앗아간 장본인이 하는 말이라
사이코 같아서 어울린다는 평가를 받았다. 특정 대사가 아니라 **범용 칸**이
우연히 만든 것이었지만, 우연이 맞았으므로 그대로 뒀다.

### 안 쓴 것

- **엔딩 내용** — 문서 393-397, 아카이브가 차단돼 「확인 못 함」. 쓰지 말라고 적혀 있다.
- **미코토 · 유다** — 후속작 설정이다. NGPC판 시점에 없는 이야기다 (문서 6장).
- **나코루루의 「레라」·이중인격** — 폐기 (v1.0.1, 유저 지시). 대사·주석 어디서도 인격
  분리를 말하지 않는다. 기술명 「레라 무츠베」·「레라 오 치키리」는 공식 표기라 그대로.
  수라/나찰 말투 차이(NR)는 같은 사람의 결 차이로만 유지.

### 간다라

플레이어블이 아니고 **해설자도 아니다.** 해설자 15명은 로스터에서
**간다라만 뺀 것**이다 (문서 332). 그래서 간다라는 **유가 입으로만** 나온다 —
「간다라는 내가 지었다. 시체 수천을 꿰매서」(캐릭터 선택 잡담),
「간다라라도 불러올까」(메뉴 혼잣말).

### 어휘를 통째로 갈았다

「후후 / 구경거리 / 볼만했다」 같은 무색 관전평을
**그릇 · 터 · 의식 · 재료 · 거두다 · 짓다 · 문(門)** 으로 바꿨다.
「짓다」는 간다라·반면의 아수라·시키를 전부 걸 수 있는 동사라 축으로 삼았다.

- 캐릭터 선택 잡담 **8칸 → 14칸.** 목적·간다라·시키·모로즈미를 여기서 흘린다
- `RELLINE` 유가 행 **8칸 → 15칸 전부** 채웠다
- 세 저장소 동기 완료 (`ss2comm_lines.h` md5 `7462c8b2…`, 러너는 `index.html`)
- `test_flow.sh` **8/11 — 회귀 없음** (실패 3개는 예전 계약을 검사하는 것들 그대로)

## 7. 심판(쿠로코) 구호를 한국어로

음차만 해 뒀던 것을 우리말로 옮겼다.

| 전 | 후 |
|---|---|
| 일 본째 — 진조니, 쇼부! | **첫 판 — 정정당당히, 승부!** |
| 이 본째 — 진조니, 쇼부! | **둘째 판 — 정정당당히, 승부!** |
| 삼 본째 — 진조니, 쇼부! | **셋째 판 — 정정당당히, 승부!** |
| %s — 오미고토! | **%s — 훌륭하오!** |

`一本目` 을 「첫 판 / 둘째 판 / 셋째 판」으로 맞춘 건 **표 전체가 이미
