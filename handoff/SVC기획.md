# SvC MotM 커스텀 — 기획

대상: 『SNK vs. Capcom: Match of the Millennium』(NGPC), 한글패치 v17.2
확인한 것: 헤더 `SNKvsCAPCOM1`, 게임ID 0x0069, 4 MB.
한글패치는 원본 대비 **4.5%(190,766바이트)** 가 다름 — 실제 대규모 번역 패치.
우리 코어로 부팅·900프레임 구동 확인 (인트로 렌더 정상).

---

## 0. ~~먼저 고칠 것~~ → 고쳤습니다

**비-SS2 게임에도 기둥과 해설띠가 붙던 문제, 이번에 잡았습니다.**
롬 헤더 이름(0x24)이 `SAMURAI2` 인지로 판별해, 아니면 기둥·해설띠·오버레이·
원버튼을 통째로 끄고 원본 해상도로 내보냅니다.

확인: SvC → 160×152 (기둥·띠 없음) / 사쇼!2 → 288×184 그대로.
코어 6종 재빌드 완료(`62bba02`). 리드미의 「사쇼!2 가 아니면 잠자코 있습니다」가
이제 사실이 됐습니다.

이건 SvC 작업의 1번 항목(게임 판별)의 **첫 절반이기도 합니다** — 판별 지점이
이미 생겼으니, 프로파일 고르는 자리로 그대로 확장하면 됩니다.

## 1. 구조 — 엔진을 게임별로 갈라야 한다

지금 엔진은 SS2 전용으로 박혀 있다.

| 파일 | 줄 | SS2 의존 |
|---|---|---|
| `ss2comm.c` | 2,563 | RAM 오프셋 15종 하드코딩, 로스터 15 가정 38곳 |
| `ss2sp.c` | 628 | 커맨드 컴파일러 — 게임 무관한 편 |
| `ss2comm_lines.h` | 1,278 | 대사표 (SS2 전용 내용) |
| `ss2sp_moves.h` | 495 | 기술표 15캐릭터/30유파 |
| `ss2comm_art.h` | 71 | 일러 주소표 |
| `ss2comm_font.h` | 924 | 글꼴 — **그대로 재사용** |

**제안: 게임 프로파일 구조체 도입.**

```
typedef struct {
  const char *hdr;          /* 롬 헤더 이름으로 판별 — "SAMURAI2" / "SNKvsCAPCOM1" */
  struct { u16 mode, hp1, hp2, ch1, ch2, act1, act2, facing, round; } off;
  const char **roster;  int roster_n;
  const void *art, *lines, *moves;
} game_profile;
```

부팅 때 헤더 읽어 프로파일 하나 고르고, 엔진은 프로파일만 본다.
프로파일이 없으면 **전 기능 비활성 + 원본 해상도** (0번 항목이 여기서 해결된다).

폰트·띠 그리기·기둥 합성·오버레이 UI·일시정지는 **게임 무관이라 전부 재사용**된다.
새로 파야 하는 건 오프셋·로스터·기술표·대사·아트 넷이다.

## 2. 정찰 — RAM 지도 (여기가 진짜 일이다)

SS2 때와 같은 방법. 찾아야 할 값:

| 값 | 쓰는 곳 | 난이도 |
|---|---|---|
| 모드(전투/메뉴/데모) | 언제 입을 열지 | 쉬움 — 화면 전환하며 차분 |
| P1/P2 체력 | 히트·빈사·KO | 쉬움 — 맞을 때만 변함 |
| P1/P2 캐릭터 ID | 누구인지 | 쉬움 — 캐릭터 고르며 차분 |
| 액션 ID | 필살기 판정 | **어려움** — SS2 때도 제일 오래 걸렸다 |
| 바라보는 방향 | 커맨드 좌우 반전 | 중간 |
| 라운드·승수 | 매치포인트·총평 | 중간 |

**필요한 것: 세이브 다발.** SS2 때처럼 장면별로 상태 저장해서 주시면 됩니다 —
캐릭터 선택 / 라운드 시작 / 서로 때리는 중 / 빈사 / KO / 승리화면 / 메뉴 각각.
많을수록 정확해집니다. 그거 받아서 차분 떠서 오프셋 뽑습니다.

SvC 는 SS2 와 다른 점이 있어 미리 봐 둘 것:
- **팀전(래티오) 구조** — 한 매치에 캐릭터가 여럿. P1/P2 슬롯이 하나가 아닐 수 있다
- 모드가 여러 개 (토너먼트 / 올림픽 / 스파링 / 서바이벌) — 모드별로 램 배치가 다를 수 있다
- **26명** (SNK 13 + 캡콤 13) + 보스 — SS2 의 15명보다 많다

---

## 3. 원버튼 필살기 — 되는지부터 확인

SS2 에서 통한 원리는 「입력 기록 리셋 + 커맨드 대신 넣기」였다.
그 게임 판정 루틴이 입력 기록을 거꾸로 훑으며 안 맞는 입력을 건너뛰는
성질 때문에 찌꺼기가 긴 커맨드를 가로챈다 — 그래서 리셋이 먹혔다.

**SvC 도 같은 성질인지는 확인해 봐야 한다.** 다른 엔진이면 다른 접근이 필요하다.
확인 방법: 커맨드를 프레임 단위로 넣어 보고 성공률을 재면 된다(SS2 하네스 재사용).

되는 게 확인되면 26명치 기술표를 파야 한다 — SS2 가 30유파 495줄이었으니
비슷하거나 더 크다.

**여기는 「된다/안 된다」부터 재고 나서 결정하는 게 맞다.** 안 되면 이 항목만 빼고
해설·기둥으로 가면 된다.

---

## 4. 해설 대사 — 제일 긴 작업

SS2 는 화자 15명 + 쿠로코에 **4,232줄**이었다. 그게 이 프로젝트에서
가장 오래 걸린 부분이다. SvC 는 26명이라 같은 밀도면 더 커진다.

**현실적인 단계 제안:**
- 1단계: 화자를 **소수(4~6명)** 로 시작 — 쿄·테리·류·춘리 같은 간판
- 2단계: 반응 이벤트를 SS2 의 절반 정도로 (KO·필살기·선제·빈사·역전·라운드·총평)
- 3단계: 반응 좋으면 화자와 줄 수를 늘린다

SS2 의 이벤트 체계·큐·중복 방지는 그대로 쓰니, 새로 쓰는 건 **문안뿐**이다.

---

## 5. 기둥 아트

SvC 도 캐릭터 초상·일러가 롬 안에 있다. SS2 때 만든 수확 도구
(`harvest_art.py`, 상태파일 VRAM → 롬 주소표)를 그대로 쓴다.
**그림은 이번에도 배포물에 안 넣는다** — 주소표만.

26명이면 수확·초점 확정 작업량이 SS2(15명×4변형=60장)보다 크다.
변형 없이 1인 1장으로 시작하는 게 낫다.

---

## 6. 배포·권리 — 미리 정리할 것

- 코어·앱 모두 **GPL 그대로**. 구조는 SS2 와 동일하니 새 문제 없음
- 그림·롬 미포함 원칙 그대로
- **앱판을 낼 거면 잠금 정책을 정해야 한다.** 지금 앱은 사쇼2 전용으로 잠가
  「범용 에뮬 대체재가 아니다」를 지키고 있다. SvC 를 넣으면 **2개 게임 허용**이
  된다. 두 게임 화이트리스트까지는 같은 논리로 방어 가능하다고 본다
  (여전히 범용 에뮬이 아니다). 셋 이상으로 늘리면 그 논리가 약해진다
- 한글패치 v17.2 는 **제작자 본인 저작** (확인됨) — 사쇼2 와 똑같이
  「본인 작업, 패치만 배포, 패치 적용된 롬은 배포 안 함」으로 적으면 됩니다

## 추천 진행 순서

```
0. 비-SS2 게임 기둥/띠 끄기          ← 작다. 지금 릴리즈 전에
1. 게임 프로파일 구조로 엔진 가르기   ← 중간. 0번과 같이 하면 효율적
2. 세이브 받아서 RAM 오프셋 뽑기      ← 유저 협조 필요
3. 원버튼 되는지 성공률 측정          ← 여기서 3번 항목 갈지 말지 결정
4. 해설 소수 화자로 1차              ← 붙이면 바로 티가 난다
5. 기둥 아트 26명                    ← 마지막
```

2번(세이브)만 주시면 3번까지는 제가 밀고 갈 수 있습니다.
