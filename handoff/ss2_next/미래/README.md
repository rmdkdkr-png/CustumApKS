## 1. 아웃핏(옷 바꾸기)

설계·실측 전문: `../설계/outfit.md` (실측 E1~E24, 시제품, 추천안, 데이터 형식, 시험 계획).
도구(코드만 — 롬에서 나온 그림·팩은 저장소에 안 넣었다): `outfit_tools/`
- `core_tilemap.diff` — ss2-sp-core 에 붙이는 코어 패치 시제품(141줄): 게임이 롬 → 문자 램으로 몸 타일을 베끼는 순간 P1·P2 따로 바꿔 넣는다(`retro_ngp_tilemap`). 런어헤드·프레임 생성에서 원래 그림 프레임 0, 끄면 원래 코어와 바이트까지 같음(실측).
- `outfit_sheet.py` — 캐릭터 포즈 전부를 4색 PNG 시트로 내보내고, 고친 시트를 «바꿈 표»(.ss2o, 롬과의 XOR 차이)로 되읽는 왕복 도구.
- `pat.py`(무늬 옷) · `hairx.py`(하오마루 «백발» 자동 처리) · `poses.py`·`posrender.py`·`ox.py`(포즈 레코드 해석·롬에서 포즈 그리기·VRAM 해석).

판단 요약:
| 갈래 | 되나 | 품 |
|---|---|---|
| 팔레트만(3색) | 됨 — 이번 컬러 16가지 + 내 색이 이것 | 0 |
| 부위마다 팔레트 | 안 함 — 몸 25장이 팔레트 하나, 한 타일 안에 피부·옷이 섞임 | — |
| 장신구 겹치기(모자 등) | 기술은 됨(코어 렌더러 + 포즈 3,100개 머리 기준점 표) | 개발 5~8일 + 기준점 3~5시간 + 방향별 그림 |
| 다시 그린 옷 | 기술은 다 됨(무압축 타일 · 포즈 레코드 해석 · 코어 바꿔 넣기 · 시트 도구) | 캐릭터 1명 옷 1벌 = 몸 포즈 146~301개 → 손그림 18~37시간 |

다시 시작할 때 1단계 추천(약 5일): **무늬 옷 4가지**(물방울·줄무늬·격자·사선 — 그림 품 0, 하오마루 빼고 13명) + **특별 옷 팩**(첫 팩 하오마루 «백발»),
검질 고르기에서 ↑↓ 로 고르기(게임이 안 쓰는 키 — 실측), 오른쪽 세로 칸에 옷 이름. 코어 패치가 필요하므로 ss2-sp-core 쪽 작업이 함께 간다.

## 2. 경기 AI

아직 조사 전. 이번 랭크 매칭 조사(`../설계/ranked.md` 2장)에서 확인한 것:
- CPU 세기는 램 다섯 곳(CPU 단계 시작 0x5814 · 단계 상한 0x5815 · 공격 배율 0x57E2 · 받는 피해 배율 0x57E4 · 단계 바닥 0x5CF5)으로 조절된다 — 게임 원래 AI 의 «세기»만 바뀌고 «버릇»은 그대로.
- 상대마다 다른 버릇(공격적·수비적·잡기 위주 등)을 주려면: (가) 게임 AI 상태 램을 더 찾아 성향 값을 건드리기, (나) 코어 입력 필터로 P2 입력을 앱이 직접 만드는 «스크립트 AI»(연습 더미가 이미 P2 를 멈추는 길을 씀), (다) 사무쇼 2019 «도장»처럼 사람 플레이를 기록해 흉내 내는 «고스트».
- (나)·(다)는 P2 입력을 프레임마다 앱이 정해야 해서 코어에 입력 바꿔 치기 훅이 필요하다(프레임 데이터 조사의 «더미 기상 옵션»과 같은 훅).
