### A2. 원작 스토리 [ROM]

- 배율표 0x2385E0 [장 0x57FE][난도], atk/dfn (쉬움 · 보통 · 어려움)
  - 0-1장: C0/140 · D9/126 · F3/10C
  - 2-3장: CC/133 · E6/119 · 100/100
  - 4-5장: D9/126 · F3/10C · 10C/F3
  - 6-9장: E6/119 · 100/100 · 119/E6
- 단계표 0x238680 [장][난도], 시작/상한
  - 0-2장: 1/3 · 4/6 · 7/9 … 9장: 4/9 · 7/12 · 10/15

- 스토리 CPU 카드: 항상 FF/FF (0x2186C1). 예외는 8장 0xE3, 9장 0xEA/0xEB (유가)
- 실시간 단계 0x5CF5 (P2 블록 0x5BC6 + 0x12F):

### A3. 원작 무한대전(서바이벌) CPU 카드 [ROM + 실측] **[정정]**
- 루틴 0x22F702. 판마다 atk +2 (최대 0x166), dfn −2 (최소 0xB3)
- "캐릭터별 허용표" 0x24F2E1 (`33 B7 BB BB FB BB 37 33 33 33 3B BB 3B 3B 33`)는 **사실상 안 쓰입니다.**
  - 0x22F88D-0x22F8A4에서 바이트를 읽어 DE에 마스크하지만, DE를 다시 읽지 않습니다.
  - 이후 분기는 A(수라 4 / 나찰 8 상수)만 씁니다. 0x22F8D1이 E를 A로 덮습니다.
- 실제 동작 (critic `surv.py`, 0x580B를 13/26/39로 강제, JUE·KO):
  - 13~25연승: k0/k1 한 장
  - 26~38연승: 50% k0/k1 한 장, 50% ★★★ 한 장 (수라 k2, 나찰 k3)
  - 39연승~: 0x24F2F0 목록 4 → 0x24F33C `00 02 FF`, 목록 8 → 0x24F34E `00 03 FF` → ★★★ 한 장
  - **원작은 CPU에게 두 장을 주지 않습니다.** 허용표가 막는 캐릭터도 받습니다 (갈포드 수라 72/FF, 아수라 수라 82/FF, 카즈키 수라 02/FF).
- 결과: `u159/critic/work/s13o.txt`, `s26ko.txt`, `s39o.txt`

### A4. 카드가 하는 일 [ROM + 실측]
- 경기 시작 루틴 0x21BCF0: P1 카드 0x57DC/DD → 0x57D8/DA, CPU 카드 0x57E6/7 → 0x57E2/E4
- 카드마다 0x21BD25 호출 → id&3 → 점프표 0x21BD40 `{+08,+13,+1D,+1D}`
  - k0 @0x21BD48: atk +0x33, 받는 피해 +0x0C
  - k1 @0x21BD53: atk −0x0C, 받는 피해 −0x33
  - k2/k3 @0x21BD5D: ret (배율 변화 없음)
  - 경기당 한 번, 덧셈
- 피해 코드 0x2233F6은 타격마다 0x57D8/E2, 0x57DA/E4를 읽습니다.
  - 그래서 `league.c:1366-1367`의 매 프레임 쓰기가 CPU 카드 보너스를 지웁니다.
- **[정정] 비대칭:** 리그는 P1 배율 0x57D8/DA를 덮지 않습니다.
  - autopick(`league.c:469-474` 주석)이 P1 카드를 0x57DC/DD에 씁니다.
  - 그래서 **플레이어 카드는 랭크에서 실제로 먹고, CPU 카드만 지워집니다.**
  - 147 봇 사다리 보정에는 P1 카드가 없었습니다.
- 전투 칸 0x5B56/57 (P1), 0x5D56/57 (P2) = id&3. 0x21EA6A, 0x21EBDC에서 씀
  - 유일한 읽기: 동작 스크립트 op 0x4E (핸들러 0x228C72, op 표 0x2391BE)
  - 롬 내 `4E 90 01 kk` 수: k0 9, k1 3, k2 33, k3 38 (합 83). **[정정]** cards 쪽 "k0 11"은 틀림
- HUD 0x2268B2 **[정정]**: 카드가 있으면 타일 칸 0x0C4B/0x0C4F, 없으면 0x0E4B/0x0E4F를 0x901C/0x9020에 씁니다.
  - 그 칸에 뜨는 글자는 그 카드의 한자입니다 (아수라 = 魔斧). 공용 아이콘이 아닙니다.
  - VS 띠로 타일을 복사하면 그때 실려 있는 글자가 나옵니다.

### A7. 제안 세부
- **바닥 조정** (`RankCore.java:100`)

- **티어별 카드**

  - **[정정]** 카드 가치(k0 ≈ 140, k1 ≈ 110, 둘 ≈ 250 MMR)는 E4 한 쌍(n=18)에서 나온 값이라 95% 구간이 약 ±150 Elo입니다. 같은 표의 S0n은 같은 카드로 약 580 Elo입니다. 출시 전 전용 사다리 실행이 필요합니다.

- **장식 카드 빼기 (임시안)**: `league.c:1347-1354`에서 strong이 아니면 FF/FF. strong이면 ★★★ 한 장만 (원작 39연승~과 같게).
- **상대 카드 표시**: 「상대 발견!」 자막(`EmuActivity.java:2505`, rankQ.reveal)과 결과 카드. 등급: 수라 k0★★ k1★ k2★★★ k3★★ / 나찰 k0★ k1★★ k2★★ k3★★★

## B. 카드 기믹

### B1. 카드 데이터 [실측]
- id = (ch<<4)|(sty<<3)|k. 전투는 id&3만 씁니다. 비트 2는 무시되고, FF가 아닌 값은 다 카드입니다.
- 소유: 0x63BA + 8ch + 4sty + k (0..8), 세이브 블록
- 4종 이름: k0 공격력상승, k1 방어력상승, k2 추가필살기1, k3 추가필살기2
- 등급은 능력치에 영향 없음: 아수라 수라 k0(★★) = 샬롯 나찰 k0(★) = +0x33

### B2. 기술 게이트 [ROM + 실측]
- 게이트 패턴: `4E 98 01 00 01 00 | 16 | 4E 90 01 kk 07 00 | 4E 91 01 kk 01 00 | 16`
  - op 0x16 (0x22721D) = 이전 동작으로 되돌림 (기술 거절)
- 스크립트 인터프리터 0x226F32 (포인터 XIZ+0x4F), 캐릭터별 동작표 포인터 0x226E5A
- k0: 공용 동작 0x69 시작 (근접 A 추정). k1: 공용 0x96(→B), 0x99(↓B)
- k2/k3: 캐릭터당 필살기 4~7개 (예: 아수라 k3 act D8 @0x24731E, k2 act DE @0x247407)
- 전투 칸은 살아 있는 값입니다. 라운드 중 0x5B56/57=(2,3)을 쓰면 아수라 DP+B → act DE, QCF+B → act D8 (`cardmove.py`)
- 목록: `u159/cards/actions_map.txt`

### B3. 피해 루틴 0x2233A7-0x223519 [ROM]

### B4. RAM 기믹 측정 [실측] (P2 정지 0x5BCB&=~1, P1 앉아 A)
