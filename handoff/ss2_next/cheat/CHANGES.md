## 2. 사용자에게 보이는 것

- 실행 창(런처)·게임 안 「설정」 창에 **«치트  ›»** 고리(켜진 게 있으면 강조색 **«치트 · 3개 켬  ›»**). 누르면 **같은 창 안에서** 치트 줄 11개
  (치트 켬/끔 · 올카드 끔/이번만/세이브에 남기기 · 시간 · 내 체력 · 상대 체력 · 내 분노 · 상대 분노 · 상대 · CPU 세기 · 내 공격력 · 유가).
  - 마스터 «치트» 기본 **켬**, 하나하나 기본 **끔**. 마스터를 끄면 다 쉬고 고른 값은 그대로.
  - 부제: 런처 «고른 건 이 게임에 저장돼요. 리그 대전엔 안 먹어요.» · 게임 안 «바꾸면 바로 먹어요. 리그 대전엔 안 먹어요.»(확인 안 된 롬 판이면 «이 롬 판에선 치트가 안 켜져요»).
  - 끝 줄 기록 경고: «치트로 이겨도 스토리 클리어·연승·카드 상은 세이브에 남아요. 리그 대전엔 안 먹어요 — 리그 기록은 깨끗해요.»
  - 단추: 게임 안 **«적용 ▶»** = 다시 열지 않고 바로 게임으로(값만 native 에, «치트 적용» 알림) · 런처 «닫기» = 겉 창으로. 뒤로(킥)도 겉 창으로.
  - 올카드 **«세이브에 남기기»**로 바꾸는 순간 확인 창 «올카드를 세이브에 넣을까요?» — 넣기 = 지금 `.flash` 를 `.flash.cheatbak` 으로 보관한 뒤에만 값을 씀 · 그만/바깥 = 그대로.
    도움말에 게임이 언제 저장하는지(게임 오버·스토리 클리어·무한 대전 끝·게임 설정 저장)와 바로 남기는 법(게임 설정에서 값 하나를 바꿨다 돌려 «예»).
  - 런처 치트 창에 보관본이 있으면 **«세이브 되돌리기 (올카드 전)  ›»** + 확인 창 → `.flash` 를 보관본으로, 오토세이브(+`.prac`)는 `.state.auto.cheat` 로 비킴, 올카드가 «세이브에 남기기»면 끔으로.
  - 런처 카드 아래 요약 줄에 «치트».
- 게임 중 왼쪽 위(리그 이름표 자리) 흐린 **«치트»**, 연습 경기 중이고 경기 치트가 켜져 있으면 **«치트 · 연습 중엔 경기 치트 쉼»**.
- 알림: «치트 적용» · «올카드가 세이브에 들어갔어요»(«세이브에 남기기»가 이 세션에서 세이브에 들어간 순간 한 번) · «리그 대전에선 치트가 꺼져요»(리그 판을 열 때 치트를 켜 뒀으면) · «이 롬 판에선 치트가 안 켜져요» · «세이브를 되돌렸어요».

## 3. 결정(설계와 다르거나 설계가 안 정한 것)

1. **연습 대전 흐름 전체에서 경기 치트를 쉰다**(설계는 연습 경기 `league_practice_match()` 만). 연습 허브의 상대 고르기 → 내 캐릭터 → 이야기(MODE 241, prog 06)
   동안 경기 치트가 돌면 공격 배율 0x57D8 을 곱해 두는데, 연습은 0x57D8 을 안 고쳐 **연습 경기 대미지가 2·3배**로 샜다(CPU 단계 0x5814/15 도).
   그래서 `league_session_owner()` 가 허브 종류 1 이고 H_TITLE 이 아니면 2 → 치트 «이유 3». 올카드·유가는 연습에서도 먹는다(설계 그대로).
   허브가 H_TITLE 인 채 사용자가 타이틀에서 1인 대전을 고르면 그건 일반 판 — 경기 치트 먹음(시험 `pracblock`).
2. **«내 공격력»은 라운드 중에만 곱한다**(시제품 버그 고침). 게임은 경기 앞 이야기 동안 0x57D8 = 0x100 을 쓴 뒤 카드 공격 상승을 **더한다**(0x100 → 0x133).
   시제품은 이야기부터 곱해 0x300 + 0x33 = 0x333 을 새 기준으로 삼아 3배가 0x999(약 9배)였다(`dbg_pow.py` 로 확인). 이제 라운드 사이·이야기에선 원래 값.
3. **«세이브에 남기기»를 끄면** 이번 판에서 8 로 덮은 램을 그 전 값(게임이 마지막에 세이브에서 읽은 값)으로 되돌린다(시제품은 8 을 둔 채라 끈 뒤 게임오버에서 8 이 남았다).
   이번만 창 안에서 세이브에 남기기로 바꾸면 창 보관본(원래 값)을 이어받아, 다시 이번만으로 와도 8 이 원래 값으로 안 굳는다. 이미 게임이 저장했으면 세이브엔 남아 있다(되돌리기는 런처).
4. 확인 창 «그만»은 **원래 값 그대로**(설계 «이번만으로»). 끔에서 다이얼로 바로 «세이브에 남기기»를 누른 사람이 그만을 눌렀는데 이번만이 켜지면 이상해서.
5. 값 이름: 올카드 셋째 값 **«세이브에 남기기»**(제품 결정 글 그대로, 설계 «세이브에»). 저장 값은 `save`.
6. **설정 화면(PAGES)엔 안 넣음** — 설정 화면에서 바꾸면 «세이브에 남기기» 확인 창·세이브 보관을 건너뛴다. 치트 창(실행 창·게임 안)에서만.
7. 치트 창은 **새 창이 아니라 같은 창의 내용 갈아 끼우기** — 런처(MainActivity `curSheet`)·게임(EmuActivity `sheet`)이 패드 키를 그 창 하나로 넘기므로, 따로 창을 띄우면 호스트를 고쳐야 했다. MainActivity 는 안 건드림.
8. 연습 띠 끝 « · 치트»(설계) 대신 왼쪽 위 흐린 표시 하나로(연습 띠 글 `practiceText` 를 안 건드려 병합이 쉽게). 연습 중 안내도 그 표시에.
9. «이 롬 판에선 치트가 안 켜져요»는 치트를 하나라도 켜 둔 사람에게 로드마다(연습 경고는 롬 판마다 한 번이지만, 치트는 켜 둔 걸 알아야 해서).
10. `.flash` 보관: `.flash` 가 없던 사람은 **빈 보관본** = «없었음» → 되돌리면 `.flash` 를 지움(롬 안 세이브로). 되돌린 뒤 보관본은 지운다(다시 «세이브에 남기기»를 고르면 새로 보관).
11. **싸움 중 상태 저장**(오토세이브·슬롯·«적용하고 이어하기»·되돌리기 자리): `cheat_before_save` 가 올카드 창 말고도 곱한 공격 배율·꺼 둔 상대 CPU 비트·다음 라운드 시간(0x5812)을
    원래 값으로 돌리고, 새 `cheat_after_save`(native.c `nativeSaveState` 의 serialize 바로 뒤 한 줄)가 되쓴다(그 사이 에뮬레이션 없음). 설계엔 없던 것 — 코드 검토에서 나옴:
    안 그러면 불러올 때 배율이 또 곱해지고(2배 → 4배), 치트를 끈 뒤 불러와도 상대가 가만히·시간 ∞ 로 남았다(시험 `stfight`).
    지금 라운드 타이머(0xFFFF)·분노 MAX·체력은 상태에 그대로 — 끈 뒤 불러오면 그 라운드만 ∞·MAX 는 게임대로 닳아 없어짐(설계 «끄면 지금 라운드는 ∞ 그대로»와 같은 성질).
12. 상태 [5](세이브에 이미 올카드)는 코어를 올린 뒤·상태를 불러온 뒤 첫 «세이브 다시 읽기» 전까지 **−1(모름)**(상태 파일이 플래시 내용도 싣고 온다).
    Java 는 이 세션에서 0 → 1 이 된 순간만 «올카드가 세이브에 들어갔어요» — 이어하기로 연 판에서 처음 모드를 고를 때 잘못 알리던 것(코드 검토).
13. **CPU 세기를 게임대로로 돌리면 다음 상대부터**(지금 상대는 표 값 그대로 — 게임이 상대 뽑을 때 실효 값을 다시 정한다). 도움말에 한 줄. 지금 상대의 원래 값을 보관해
    되돌리는 길은 안 넣음: 게임이 그 값에 이어하기·CPU 카드로 «더하기»를 하는지 몰라(공격 배율 0x57D8 이 그랬다) 보관값이 틀릴 수 있다.
14. 유가를 고른 뒤 판 중간에 «유가»를 끄면 P1 은 그 판 끝까지 유가 그대로(게임의 0x57D5 를 되돌릴 원래 값이 없다 — 가운데 칸은 원래 무작위). 다음 고르기부터 반영.
15. cheat.c 의 램 주소 매크로·진짜 MAX 코드는 practice.c 와 겹치지만 따로 둔다(league.c·practice.c 도 각자 둔다 — 이 코드베이스의 방식, 병합 충돌도 적다).

## 5. 통합할 때 알 것

- **struct 크기 안 바뀜** — league.c `L`/`H` 그대로(함수만 하나 더함), practice.c 안 건드림, `.prac` 덩어리 그대로. 시험 상수 고칠 것 없음.
- native.c 충돌 자리(다른 기능도 만질 수 있는 곳): `#include` 줄, `load_locked`/`unload_locked` 첫머리, `nativeFrame` 의 `practice_tick` 다음 줄·나가기 갈래, `nativeReset`, `nativeLeagueHubReturn`, `nativeSaveState`(before_save 줄), `nativeLoadState`(성공 갈래). 모두 한 줄 더하기.
  FRAMEDATA(연습 프레임 미터)가 `practice_tick` 근처에 줄을 더하면 순서는 «리그 → 연습(+프레임 데이터) → 치트» 를 지키면 된다(치트가 가장 뒤).
- **RANKED(끝없는 랭크 매칭)**: 새 세션 종류가 `EmuActivity.ranked()` 를 안 거치면 로드 뒤 `Emu.nativeCheatLock(true)` 를 불러야 한다(Java 잠금). C 쪽은 허브 종류 0 이 켜져 있거나 허브 없이 `league_arm` 으로 무장돼 있으면 스스로 막는다(`league_session_owner` == 1). 새 허브 종류(2 …)를 만들면 `league_session_owner` 에 넣을 것.
- **COLOR(룩)**: 치트 «유가»로 일반 판 P1 이 캐릭터 14(유가)가 될 수 있다(블록 E0/E8). league.c `PAL1` 은 0~13 만이라 지금은 `ch < 14` 가드로 건너뛴다 — 모든 모드 컬러가 P1 캐릭터를 표로 찾으면 14 를 안전하게(건너뛰거나 표에 넣기).
- 치트는 팔레트·화면 램·입력을 안 건드린다(작업 램만). 입력 콜백도 그대로(2단계 게임 속 창 때 `cheat_in_block`).
- options 키 `pocketcore_ss2_cheat` · `pocketcore_ss2_cheat_{cards,time,hp1,hp2,rage1,rage2,cpu,diff,pow,yuga}` — 값 이름은 Cheats.VALS.
- 세이브 파일: `saves/<롬 이름(확장자 뺌)>.flash.cheatbak`(보관본) · 되돌리면 `<롬 파일>.state.auto.cheat`(+`.prac`).

## 6. 기기에서 볼 것(여기선 adb·에뮬레이터 안 씀) · 알려진 빈틈

- D-1~D-4(설계 10-나): 실행 창 «치트 ›» → 창 → 올카드 이번만 → 1인 대전 카드 화면 / 게임 안 «설정» › «치트» › 시간 무한 «적용 ▶» 바로 먹음 / 둘 다 판 ◀▶ 리그 → 잠금 알림·리그 기록 정상 /
  «세이브에 남기기» → 게임 설정 저장 → 껐다 켬 → «들어갔어요»·런처 «세이브 되돌리기» / 런어헤드·프레임 생성 켠 채 무한 체력 막대.
- 런어헤드(2프레임)는 숨은 프레임을 진짜 상태에서 앞서 돌려 보여 주므로, 무한 체력이면 맞는 순간 막대가 1~2프레임 살짝 줄었다 다시 찰 수 있다(연습 체력 바닥과 같은 성질) — 기기에서 확인.
- 코드 검토(`code-review` medium) 결과 9건 중 실제 5건 고침(위 11·12, 부제·같은 값 누름·CPU 세기 도움말), 나머지(유가 판정 흐름·매크로 겹침·런처 요약이 options 를 두 번 읽음)는 그대로 — 이유는 위 13~15.
- 게임 안에서 «세이브에 남기기»를 고를 때의 보관본은 **디스크의 `.flash`**(지난번 코어를 내릴 때 것) — 같은 세션에서 그 전에 게임이 저장한 칸은 아직 디스크에 없어 보관본에 안 든다(되돌리면 그 몇 판의 기록이 빠짐).
- 되돌리기는 런처에서만(코어가 그 롬을 안 돌 때). 런처 썸네일 캡처가 같은 롬을 몰래 돌리는 중이면 이론상 겹칠 수 있다(캡처는 타이틀만 찍어 세이브를 안 씀).
- CPU 세기는 표 값을 덮어 쓰므로 CPU 카드(0x57E6/7)의 배율 효과는 그동안 표 값으로 바뀐다(설계대로 — 옵션 0x636A 는 안 건드림).
- 2단계(게임 속 치트 창 · 고르기 화면 «유가» 세로 글자 · «기록 지키기»)는 이번 범위 밖.
