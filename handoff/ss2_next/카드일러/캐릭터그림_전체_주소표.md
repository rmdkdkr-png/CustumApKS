## §0 공통 — 게임의 그림 목차, 도장 검사, 읽는 법

### 0.1 목차 (게임이 쓰는 길 그대로)

| 무엇 | 위치 | 값 |
|---|---|---|
| 마스터 표 | CPU 0x250000 (파일 0x050000) | u32 목록 |
| 그림 기록 표 RT | u32 at 파일 0x05002C | = CPU 0x25C9C9 |
| 팔레트 풀 POOL | u32 at 파일 0x050038 | = CPU 0x259190 (파일 0x059190) |
| RT[k] | u32 at RT + 4k | `count<<24 \| int16 표 CPU 주소` |

- 그림 «뱅크» k의 i번째 디스크립터 주소는 `tb + (int16)tb[i]` 입니다. tb = RT[k] & 0xFFFFFF.
- **오프셋에 음수가 있으므로 부호 확장이 필수**입니다.

| 뱅크 k | RT[k] | 내용 |
|---|---|---|
| 3 | 0x1F25F567 | HUD 얼굴 31개 (§1) |
| 4 | 0x202619CB | 고르기 얼굴 32개 = 바탕 16 + 색 겹 16 (§3) |
| 22 | 0x0C2A0A52 | 카드·스토리 일러 12개 |
| 23 | 0x0C2A7EF6 | 〃 12 |
| 24 | 0x0C2AFDAA | 〃 12 |
| 25 | 0x0C2B702E | 〃 12 |
| 26 | 0x0E2BEAB4 | 〃 14 (12·13 = 스토리 전용 유가, §4) |

### 0.2 디스크립터 형식 (그림 하나)

```
u16  n                     타일 수
u32  pool                  타일 묶음 CPU 주소
u16  off[n]                타일 i = pool + off[i]  (16바이트 2bpp 타일)
u8   hdr                   bit7 = 칸이 u16(타일+속성), 아니면 u8(타일만) / 하위 7비트 = 줄 수
줄마다: 칸들 … 그리고 끝 표시 (u16 칸이면 0xFFFF, u8 칸이면 0xFF)
```

- **u16 칸**(카드·스토리·HUD 얼굴)의 비트:

| 비트 | 뜻 |
|---|---|
| 0~8 | 그림 안 타일 번호 |
| 9~12 | 팔레트 칸(0~7 쓰임) |
| 13 | CP.C — 컬러 모드에서는 무시 |
| 14 | 세로 뒤집기 |
| 15 | 가로 뒤집기 |

  게임 로더(0x2004A1 → 0x200588)는 타일 i를 VRAM 타일 base+i 에 복사하고, 칸 값 + base 를 맵에 씁니다.
- **u8 칸**(고르기 얼굴)은 뒤집기와 칸별 팔레트가 없고, 층 전체가 팔레트 하나입니다.
- **타일**: NGPC 2bpp, 16바이트입니다. 한 줄은 u16 LE 이고 왼쪽 픽셀이 높은 비트에 있습니다. 색 번호 0은 투명입니다.
- **팔레트**: u16 × 4 이고 12비트 0BGR 입니다. 0번 색은 늘 투명으로 씁니다.
- **압축은 어디에도 없습니다.** 롬 바이트가 그대로 VRAM 바이트입니다.

### 0.3 도장 검사 (풀기 전에 «이 롬이 그 롬인가» 확인)

음악을 심은 사본은 md5 가 알려진 6판과 다릅니다. 그래서 md5 대신 아래 **주소값들이 모두 맞을 때만** 그림을 풉니다. 하나라도 틀리면 얼굴 없이 글자로 냅니다. 8판 모두에서 실측해 일치했습니다.

### 0.4 앱이 바이트를 얻는 법

- 코어는 `need_fullpath=true` 입니다(build/libretro.c 1962행). 그래서 native.c `load_locked` 는 롬 바이트를 읽지 않고 경로만 넘깁니다(825~836행의 읽기 가지는 안 탐).
- 코어는 롬을 `ngpc_rom.orig_data`(파일 그대로)와 `ngpc_rom.data`(헤더·0x02470F/10 두 바이트를 고친 실행용 사본)로 들고 있지만 **내보내지 않습니다.** 내보내는 것은 아래뿐입니다.
  - `retro_get_memory_data`: SYSTEM_RAM 16KB, CPU 0x4000~0x7FFF
  - `retro_ngp_charram`·`scrollram`·`palram`·`spriteram`·`spritecol`: VRAM
  - `SET_MEMORY_MAPS` 도 없습니다.
- **권장 — 사본 파일 직접 읽기.**
  - Java `romPath`(EmuActivity) 또는 native `g_rom_path` 를 씁니다. 리그 사본은 루트/league/rom/<원래 이름> 입니다.
  - 필요한 범위는 아래와 같고, 합쳐 약 17만 바이트입니다. 2MB 를 통째로 읽어도 됩니다(League.md5 가 이미 매번 통째로 읽음).

| 무엇 | 파일 범위 |
|---|---|
| 마스터 표 머리 | 0x050000~0x05003B |
| 기록 표 | 0x05C9C9~0x05CA49 |
| 팔레트 풀 | 0x059190~0x05A7AF |
| HUD | 0x02650F~0x02678F, 0x05EA62~0x05F5A4 |
| 고르기 | 0x00D748~0x00D7C7, 0x031792~0x0317B9, 0x05F5A5~0x0619CB + 표 0x0619CB~0x061A0A |
| 카드 | 0x030595~0x0315F5, 0x0315F6~0x0316E5, 0x098CA8~0x0BEAD0 |

- 대안:
  - 코어에 `void *retro_ngp_rom(size_t *len)` 를 추가(`retro_ngp_charram` 과 같은 선택 심볼, dlsym). 코어 재빌드가 필요합니다.
  - VRAM 베끼기는 게임이 그 순간 올려 둔 것만 보이므로 메뉴용으로 부적합합니다.
  - 원본 + IPS 재적용은 불필요합니다. 한패가 그림 자리를 안 건드립니다.
- **음악 심은 사본**: Ss1Music 은 끝 채움 0x04F38A~0x050000, 0x1DF762~0x1F0000 과 «갈아 끼운 SS2 곡 레코드·세트» 자리에만 씁니다. 위 그림 범위와 겹치지 않습니다. 0x04F38A~ 구간은 마스터 표 0x050000 바로 앞에서 끝납니다.

## §2 F2 — 카드 일러 96×96  (판정: 확인됨)

**어디서 보이나**
- 카드 모음집 → 카드 보기. 판2 3~14줄 × 4~15칸, 타일 0x100~, 팔레트 판2 #0~7. 투명 자리는 BG 0x83E0 = 흰 종이로 보입니다.
- 1인·무한 대전의 카드 고르기, 연승무쌍 결과, 엔딩 «카드 출현!!», 어트랙트에도 나옵니다.
- 카드 고르기와 연승무쌍 결과에서 게임이 «캐릭터 초상»으로 내는 것은 art = 4·id + 2·style (j0) 입니다.

**찾는 길** (코드 0x213EE9 카드 보기 로더에서 그대로 따옴)
1. art a = 4·id + 2·style + j (j 0/1). 카드 번호 = 2a+1, 2a+2 이고, 두 장이 그림 하나를 같이 씁니다.
2. **T_ART** 파일 0x0315F6 = 60 × `[u8 rec, u8 idx]` → 디스크립터 = 뱅크 rec 의 idx 번째(§0.1).

4. 디스크립터 hdr 0x8C(12줄, u16 칸) 이고, 타일은 75~144개, 팔레트는 8개를 싣고 2~8개를 씁니다.

## §3 F1 — 캐릭터 고르기 얼굴 32×32  (판정: 확인됨)

**어디서 보이나**
- 고르기 화면(MODE 240, SCR 2) 아래 줄입니다.
  - 바탕: 판2 14~17줄, 4k..4k+3칸, 타일 0x020+0x20k+i, 팔레트 8+k.
  - 색 겹: 판1 같은 칸, 타일 0x010+0x20k+지역번호, 팔레트 8+k.
- 커서 칸만 진짜 색이고, 나머지는 어두운 색입니다.

**찾는 길**
1. n = ICONIDX[id]. ICONIDX 는 파일 0x0317AA, u8 × 16 입니다. 고르기 격자는 파일 0x031792, u8[3][8] 입니다.
2. 바탕 디스크립터 = 뱅크 4의 n번, 색 겹 = 뱅크 4의 16+n번. int16 표는 파일 0x0619CB 입니다.
   - 디스크립터 = `u16 n | u32 0x25FCCB | u16 off[n] | u8 0x04 | 4줄 × (u8 지역 타일 ×4 + 0xFF)`
   - u8 칸이고 뒤집기·칸별 팔레트는 없습니다.
3. 바탕 타일은 파일 0x05FCCB + 0x100·n 의 16개 연속이고, 색 겹은 10~16개(겹치는 것 제거)입니다. 빈 타일은 파일 0x0606EB 입니다.
4. 팔레트는 u16 오프셋 표 4개(id로 찾음) + POOL 입니다.
   - 진짜 바탕: 파일 0x00D7A8 + 2·id
   - 진짜 색 겹: 0x00D788 + 2·id
   - 어두운 바탕: 0x00D768 + 2·id
   - 어두운 색 겹: 0x00D748 + 2·id
   - 어두운 것은 모든 id에서 진짜 + 0xA00 입니다.
5. 합치기: 바탕 위에 색 겹을 올리고, 둘 다 0번 색은 투명입니다. 둘 다 0인 자리는 받침색(게임은 검정)입니다.
   - 칸 하나에 최대 6색 + 투명이고, 16장 중 15장이 4색을 넘는 칸을 가집니다. 아수라만 4색 이하입니다.
   - 그래서 한 층 4색 규칙에는 그대로 안 들어갑니다. 두 층으로 올리거나 미리 합친 비트맵으로 써야 합니다.
