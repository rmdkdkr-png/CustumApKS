# 사무라이 스피리츠! 2 (NGPC) 카드 일러 — 주소·형식·표

롬 주소는 두 가지로 적습니다. **CPU 주소** = 0x200000 + **롬 파일 오프셋**입니다(.ngc는 헤더 없는 원본, 2 MB). 정수는 모두 little-endian입니다.
판정: **확인됨**. 찾은 쪽(trace)과 별도 검증자(verify)가 서로 다른 디코더와 서로 다른 에뮬레이터 구동으로 같은 결과를 냈습니다(§9).

## 2. 해금(올카드) 방법

- 소유 개수 = RAM **0x63BA + 8*ch + 4*sty + k** (u8, 0..8, 120바이트 0x63BA~0x6431). 256바이트 세이브 블록(RAM 0x635A~0x6459)의 +0x60.
- 블록은 카트 0x3F0000부터의 플래시 슬롯(256바이트 저널, 체크섬 없음) 사본입니다. 게임이 부팅 3f째와 타이틀 메뉴에서 모드를 고르는 프레임에 다시 읽으므로, 그 **뒤에** 써야 합니다.
- 대전: league.c / cheat.c «올카드»처럼 MODE 0x40A7==240이고 SCR 0x41C0 ∈ {2,4}일 때 120칸에 8.
- 모음집: 0x624B=3으로 들어간 뒤(0x57C6=0x12) 120칸에 8. 개수를 실시간으로 읽어 «종류 120/960장 · 소장 8/8장». 들어갔다 나오기만 해서는 저장되지 않습니다. 플래시는 건드리지 않았습니다.

## 3. 카드 → 그림 번호

- 카드 id = `(ch<<4) | (sty<<3) | k` (P1 0x57DC/DD·CPU 0x57E6/E7과 같은 id 체계. verify가 능력 추가 화면에서 고른 뒤 0x57DC를 14칸 × 2롬에서 읽어 확인)
- 카드 No = `ch*8 + sty*4 + k + 1` (1..120)
- **그림 번호 A = `ch*4 + sty*2 + (k>>1)`** (0..59). 게임 코드는 `A = (0x5730)*4 + ((0x572E)>>1)`.
- ch 15(쿠로코) id 0xF0~0xFF는 그림이 없습니다. 그림 목록은 60칸뿐이고(A=59 뒤는 `04 00 03 00 02 00`) 격자는 15행입니다.

## 4. 롬 안의 길 (게임과 같은 순서)

상수는 코드의 명령 피연산자에서 읽을 수 있습니다(디코더도 그렇게 함). 6판 모두 값이 같습니다.

| 단계 | 읽는 곳 | 값 / 형식 |
|---|---|---|
| 0. 상수 | 0x213EEA (u32, 앞 바이트 0x43) | 그림 목록 **0x2315F6** |
| | 0x214227 (u32, 앞 0x43) | 팔레트 id 표 **0x23166E** |
| | 0x2023D0 (u32, 앞 0x44 @0x2023CF) | 팔레트 세트 표 **0x230595** |
| | 0x213F0E (u24, 앞 0xE2) | 디렉터리 포인터 **0x25002C** → u32 = **0x25C9C9** |
| | 0x201A31 (u24, 앞 0xE2) | 팔레트 뱅크 포인터 **0x250038** → u32 = **0x259190** |
| 1. 그림 목록 | 0x2315F6 + 2*A (롬 0x315F6) | `u8 group, u8 index`. group 0x16..0x1A, 그룹당 12장(3캐릭터). 순서가 불규칙(16: 3,2,1,0,5,4,7,6,9,8,11,10 / 17: 3,2,1,0,5,4,7,6,11,10,9,8) → **공식 말고 표를 읽을 것**. 게임은 0x2315F0 + 2*(A+3)으로 읽음(앞 3칸은 카드 아님) |
| 2. 디렉터리 | 0x25C9C9 + 4*group | `[u24 T][u8 count]`. 16→T 0x2A0A52, 17→0x2A7EF6, 18→0x2AFDAA, 19→0x2B702E, 1A→0x2BEAB4 (1A만 count 14) |
| 3. 객체 | **obj = T + s16(T + 2*index)** | 예: 0x2A0A52 + (s16)0x891D = 0x29936F. 절대 포인터는 롬 어디에도 없음 |
| 4. 팔레트 id | 0x23166E + 2*A (롬 0x3166E) | u16. 카드는 모두 `(group-0x16)*12 + index + 1` 과 같지만 표를 읽을 것 |
| 5. 팔레트 세트 | 0x230595 + 4*id | `[u8 type=4][u24 record]`. 레코드는 0x230795부터 14바이트 간격 |
| 6. 레코드 | record | `[u8 count=8][u8 dest>>3 = 0x20][u32 list]` + 나머지(`08 00 10 01`, 0x230FEA, `08 20`, 모든 카드 같음). census의 «0x2307A5+14n»은 record+2(list 포인터) 자리 |
| 7. 목록 | list | count개 u16 = 뱅크 안 바이트 오프셋 |
| 8. 색 | 0x259190 + off | 팔레트 하나 = u16 4개, 12비트 0BGR(R = w&0xF, G = (w>>4)&0xF, B = (w>>8)&0xF). 색 0은 투명. 카드 팔레트 범위 0x259190~0x25A7CF |

예 (A=0, 카즈키 수라 k0/k1): 목록 → 16/3, 디렉터리 0x25CA21, T 0x2A0A52, 객체 0x29936F, 팔레트 id 4, 세트 0x2305A5, 레코드 0x2307CD, 목록 0x23100C, 오프셋 CB0 CB8 CC0 CC8 CD0 CE8 CF0 CF8.

## 5. 그림 객체 형식 (압축 없음)

그리기 루틴 0x200588(입구 0x2004A1. C=0이면 RAM 0x4889에 작업을 걸고 vblank에 그림)에서 읽은 형식입니다.

```
+0        u16  n                 타일 수 (카드 75..144)
+2        u32  sheet             타일 풀 CPU 주소
+6        u16  off[n]            타일 i = sheet + off[i] 의 16바이트
+6+2n     u8   fmt               bit7 = 16비트 맵(끝 0xFFFF), 0이면 8비트(끝 0xFF); bit0-6 = 행 수. 카드는 0x8C
+7+2n     맵: 행마다 cols개 u16 + 0xFFFF (cols는 첫 행으로 셈). 카드 12x12 → 12*(12*2+2) = 312바이트
```

- 타일: NGPC 2bpp 16바이트, 행 = u16 LE, 맨 왼쪽 픽셀이 bit15-14. 게임은 `ldirw`로 VRAM 0xA000 + 16*(0x100+i)에 **그대로 복사**합니다.
- 맵 낱말: bit15 H뒤집기, bit14 V뒤집기, bit13 CP.C, **bit12-9 팔레트 0..7 (마스크 0x1E00)**, bit8-0 = off[] 순번. 게임은 낱말 + 0x100(타일 시작)을 판 맵에 쓰고 한 행마다 0x40바이트씩 내려갑니다.
- bit13은 60장 중 43장, 맵 낱말 1352개에 켜져 있습니다. 팔레트는 bit12-9만 보세요.
- 뒤집기 사용: H 76칸, V 63칸 (60장 합계).
- 루틴에 거울 모드(B bit0: 오른쪽→왼쪽, bit15 토글)와 8비트 맵 모드가 있지만 카드는 쓰지 않습니다(B=0, fmt 0x8C).
- 모든 맵 순번 < n, 모든 팔레트 < 8 (60장 검사).
- 팔레트 목록 오프셋 0이 두 군데 있습니다(A=7 슬롯 6, A=10 슬롯 5 → 뱅크+0, 색 000 49D ADF FFF). 맵이 그 슬롯을 안 쓰는 자리채움입니다.
- 객체 크기 469~607바이트.

예 (A=0): 객체 롬 0x9936F, n=122, sheet 0x29A822, off 0x99375~0x99468, fmt 0x8C @0x99469, 맵 0x9946A~0x995A1. 타일 2 = 롬 0x9C022.

## 6. 롬 배치

그룹마다 `[객체 12개(1A는 14개)][타일 풀][s16 표 T]` 순서로 붙어 있습니다. 끝 주소는 포함(inclusive)입니다.

| 그룹 | 캐릭터 | 객체 CPU | 타일 풀 CPU (크기) | 표 T CPU |
|---|---|---|---|---|
| 0x16 | 카즈키·소게츠·하오마루 | 0x298CA8~0x29A821 | 0x29A822~0x2A0A51 (25136 B) | 0x2A0A52~0x2A0A69 |
| 0x17 | 겐쥬로·나코루루·리무루루 | 0x2A0A6A~0x2A2505 | 0x2A2506~0x2A7EF5 (23024 B) | 0x2A7EF6~0x2A7F0D |
| 0x18 | 한조·갈포드·아수라 | 0x2A7F0E~0x2A9A99 | 0x2A9A9A~0x2AFDA9 (25360 B) | 0x2AFDAA~0x2AFDC1 |
| 0x19 | 샬럿·모로즈미·우쿄 | 0x2AFDC2~0x2B181D | 0x2B181E~0x2B702D (22544 B) | 0x2B702E~0x2B7045 |
| 0x1A | 주베이·시키·유가 (+유가 엔딩 2장) | 카드 0x2B7046~0x2B8A21, 엔딩 i0C 0x2B8A22~0x2B8C70, i0D 0x2B8C71~0x2B8EB3 | 0x2B8EB4~0x2BEAB3 (카드 타일만은 ~0x2BE283) | 0x2BEAB4~0x2BEACF |

- 카드 그림 전부(객체+풀+표) = CPU 0x298CA8~0x2BEACF = 롬 0x98CA8~0xBEACF, 155176바이트. 60장 타일 합계 7563개(풀 안에서 중복 제거됨).
- trace·census의 «객체 0x98CA8~0xB8B5A»는 끝이 틀립니다(0xB8B5A는 엔딩 객체 한가운데). 풀 끝 «0xA0A52…»는 배타 표기입니다(위 표가 포함 끝).
- 그 밖의 큰 그림: 1A/i0C·i0D 유가 엔딩 12×12(i0D가 실제 엔딩에 나옴, 팔레트 레코드 0x230AFB), g23 i00 0x2899DA(13×12), g28 i00~08 괴물 프레임(10×14), g1B 타이틀 로고, g22 우주, g15 효과. **캐릭터별 초상은 카드 60장 말고는 없습니다.**

## 11. 앱에서 런타임에 읽어 덧판에 그리기

원칙: 그림 바이트는 앱·저장소·아티팩트에 넣지 않습니다. **사용자가 로드한 롬 파일에서 그때그때 읽어** 풉니다.

### 11.1 롬 바이트 얻기

- native.c는 `need_fullpath`가 거짓일 때만 롬을 malloc으로 읽고, `retro_load_game` 뒤 바로 `free(rom)` 합니다(약 825~835줄). 하네스 코어 빌드(`coretest2/build/libretro.c` 1962줄)는 `need_fullpath = true`라서, 같은 코어라면 앱 쪽에는 롬 버퍼가 아예 없습니다. 그러니 **`g_rom_path`를 직접 다시 엽니다.**
- 필요한 범위(파일 오프셋 = CPU − 0x200000):
  - 0x013EE9~0x013F11, 0x014226~0x01422A, 0x0023CF~0x0023D3, 0x001A30~0x001A33 (상수 확인용 몇 바이트)
  - 0x030595~0x0316F0 (팔레트 세트·레코드·목록·그림 목록·팔레트 id 표, 약 4.4 KB)
  - 0x05002C~0x05003B, 0x059190~0x05A7CF (뱅크 5.7 KB), 0x05C9C9~0x05CA34 (디렉터리)
  - 0x098CA8~0x0BEACF (객체+풀+표, 152 KB)
  - 합쳐 약 165 KB. 메뉴를 처음 열 때 백그라운드에서 한 번 읽어 두거나, 그림 하나에 필요한 객체(≤607 B)와 타일 n개(≤2304 B)만 pread해도 됩니다.

### 11.2 검사 (실패하면 회색 블록으로 대체)

1. 파일 크기 ≥ 0x0BEAD0. 앞 바이트 확인: 0x213EE9=0x43, 0x214226=0x43, 0x2023CF=0x44, 0x213F0D=0xE2, 0x201A30=0xE2.
2. 상수 다섯 개가 위 값과 같은지(다르면 그 값으로 따라가되 아래 검사를 모두 통과해야 사용).
3. 그림마다: group ∈ 0x16..0x1A, index < count, 75 ≤ n ≤ 144, sheet+off+16이 파일 안, fmt == 0x8C, 12행 × 12열, 모든 맵 순번 < n, 팔레트 세트 type == 4, count == 8.

```c
   int g = rom[CPU(pic + 2*A)], i = rom[CPU(pic + 2*A + 1)];
   uint32_t T = rd24(rom, CPU(dir + 4*g)), obj = T + (int16_t)rd16(rom, CPU(T + 2*i));
   int n = rd16(rom, CPU(obj)); uint32_t sheet = rd32(rom, CPU(obj + 2));
   for (int t = 0; t < n; t++) memcpy(o->tiles[t], rom + CPU(sheet + rd16(rom, CPU(obj + 6 + 2*t))), 16);
   uint32_t p = obj + 6 + 2*n;              /* rom[CPU(p)] == 0x8C */
   p++;
   for (int r = 0; r < 12; r++) { for (int c = 0; c < 12; c++, p += 2) o->map[r*12 + c] = rd16(rom, CPU(p)); p += 2; /* 0xFFFF */ }
   uint32_t ent = rd32(rom, CPU(pset + 4*rd16(rom, CPU(pid + 2*A))));   /* (ent & 0xFF) == 4 */
   uint32_t rec = ent >> 8, list = rd32(rom, CPU(rec + 2));              /* rom[CPU(rec)] == 8 */
   for (int q = 0; q < 8; q++) { uint32_t c0 = bank + rd16(rom, CPU(list + 2*q)); for (int k = 0; k < 4; k++) o->pal[q][k] = rd16(rom, CPU(c0 + 2*k)); }
   o->n = n; return 0;   /* 위 §11.2 검사는 생략 — 실제로는 넣을 것 */
}
```

덧판에 올리기: 타일 `o->tiles[0..n-1]`를 층 타일 `tileBase..`에, 맵 칸 = `tileBase + (w & 0x1FF)`, 팔레트 = `palBase + ((w >> 9) & 0xF)`, H = bit15, V = bit14, bit13은 버림. 색은 12비트 0BGR → 니블×17 (기획서 9.1의 «니블×17 → RGB565 → 8888»과 같음). 색 0은 투명 — 게임처럼 보이려면 그 뒤에 0xFFF 흰 판(12×12칸)을 깔 것. 기획서 9.3 `nativeOvLayer(layer, tiles, tileBase, map, cols=12, rows=12, col0, row0, pals, palBase)` 모양에 그대로 들어갑니다. Java(TileCanvas)에서 풀어도 되고 native에서 풀어 넘겨도 됩니다. 어느 쪽이든 결과는 이 바이트들입니다.

### 11.4 160×152 화면 예산 (화면 = 20×19칸)

| 배치 | 칸 | 픽셀 | 타일 (최대 / 최소) | 팔레트 |
|---|---|---|---|---|
| 한 장 전체 | 12×12 | 96×96 (폭 60%, 높이 63%) | 144 (A=34) / 75 (A=54) | 8 (내용이 다른 것은 2~8) |

| 두 장 나란히(8열 자르기) | 16×12 | 128×96 | ≤192 | ≤16 |

- 한 장 데이터: 타일 ≤2304 B + 맵 288 B + 팔레트 64 B.
- 기획서 9.4 덧판 창 층은 타일 512 / 팔레트 16입니다. 결판(216타일·10~11팔레트)에 한 장을 더하면 타일 360은 들어가지만 **팔레트 18~19로 16을 넘습니다.** 방법: (a) 그림 전용 층(타일 144·팔레트 8)을 하나 더 둠, (b) 창 층 팔레트 8~15를 그림 몫으로 비우고 글자를 8개 안에서 칠함, (c) 그림이 뜨는 쪽에서 목록 층(2048/16)을 씀. 두 장을 동시에 쓰면 그림만으로 팔레트 16개를 다 씁니다.
- 두 장 전체(192px)는 폭 160을 넘으므로 나란히 쓰려면 자르기가 필요합니다.
- 칸 정렬: 그림은 8px 칸에 딱 맞으므로 덧판 칸 격자에 바로 놓입니다(보기 화면은 col 4, row 3 = 화면 (32,24)).
- 그림 고르기: 초상용은 대체로 k01. 예외(초상 아님): A=1 카즈키 수라 k23, A=24·25 한조 수라, A=26 한조 나찰 k01(뒷모습), A=40 모로즈미 수라 k01, A=59 유가 나찰 k23. A=32·33 아수라 수라는 회색 톤입니다.
