# CPU 대 CPU · AI 단계 분석 (2026-10-17, 하네스 실측)

## CPU 대 CPU — 된다
- 게임에 데모 대전은 없다. 1인 대전이 시작된 뒤 `0x5819` bit5 를 켜 두면 라운드 시작마다 P1 블록 `0x59CB` bit0(«이쪽은 CPU»)이 켜져 P1 도 게임 AI(`0x229ECB`)로 싸운다. 바로 바꾸려면 `0x59CB |= 1`. `0x57D4` 는 1 이 아니어야 한다(대전 모드 길).
- 127판 끝까지(KO·라운드·승리 대사·다음 장) 모두 정상, 멈춤 0. 경기 중 사람이 P1 을 넘겨받았다가 돌려주기 됨.
- 편마다 세기: 실시간 단계 P1 `0x5AF5` · P2 `0x5CF5` 를 따로 고정. 시작 `0x5814`·상한 `0x5815` 는 둘이 같이 쓴다.
- 스크립트: scratch `u160/investigate/scripts/cv.py`(Nav + CvC).

## AI 단계(0~15)가 바꾸는 것 — 세기보다 «박자»
- 코드: 단계는 9곳에서 읽힌다. 생각 대기 = 기분값 + (16−lv) 틱(1틱=2프레임), 연속기 사이 간격 = 2·⌊(15−lv)/2⌋ 프레임, 가드·대공·장풍 가드·반격·점프 뒤 공중기 확률에 +2lv/+4lv. 대미지·속도·기술 고르기는 안 바뀜.
- 실측(1024라운드): lv0~3 → 12~15 에서 공격 시도 +43%, 반응 14.1→8.8 프레임, 생각하는 시간 17%→3%. 가드율·받는 대미지·점프는 그대로.
- 승률: 단계 하나에 약 5 Elo, 0↔15 전체가 60:40 남짓. 캐릭터 상성(±0.6~0.9 logit)이 훨씬 크다.
- 게임 자체 적응: 약 10초마다 −4~+4, CPU 대 CPU 에선 평균 «시작 − 2» 로 내려앉는다. 라운드 시작마다 시작값 ±1 로 돌아감(톱니).
- 그래서 세기를 진짜로 바꾸는 손잡이는 대미지 배율(원작 하·중·상 차이의 대부분)과 캐릭터다. 유저 결정: «배율은 원작대로, 카드 배율까지 반영» (157 CPU).
