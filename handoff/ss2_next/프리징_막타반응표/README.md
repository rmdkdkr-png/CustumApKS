# 사무쇼2 막타 프리징 — 한글패치가 KO 반응 표를 덮어씀 (2026-10-16)

## 증상 (유저 보고 «프리징», 상태 파일 받음)

1P 우쿄(나찰) 대 COM 모로즈미(수라, «붓쟁이»), 타이머 38. 모로즈미 체력이 0 이 되는 순간 화면·타이머가 그대로 멈춤.
앱은 살아 있고(메뉴·저장 됨) 소리도 남. 받은 `.state`·`.state.auto` 둘 다 멈춘 뒤의 상태 — 어느 코어(앱 패치 없는 1cb33c9 포함)·
어느 롬(JUE·한글)에 넣어도 900 프레임 동안 그대로. 받은 상태 파일·롬은 저장소에 넣지 않았다.

## 원인 (검증함)

- 막타(맞는 쪽 체력 0)의 반응은 `0x2246E8~0x224740` 이 **KO 전용 표**(포인터 표 `0x224825` → T2 `0x224A7F`, T3 `0x224BA8`, 297칸씩)를 먼저 본다.
  원판은 두 표가 `0xFF`(= 보통 표를 써라)와 `0x77` 12칸뿐.
- 한글패치(동봉 `ss2_ko.ips`, v1.01, KO_mute, h1 한글판 모두 같은 바이트)가 이 «빈 것처럼 보이는» `0xFF` 자리 369칸에
  한글 타일 그림을 넣었다(IPS 레코드 파일 0x24A84·0x24ABC·0x24BAD·0x24BF0·0x24C00·0x24C4E, 그림 서술자를 0x224A84·0x224BF0 로 돌림).
- 반응 대본 표 `0x2414F1` 은 123개(0x00~0x7A)뿐이라, 덮인 칸이 0x7B~0x7F 를 고르면 표 밖으로 튄다.
  유저 장면: T3[24] = `0x224BC0` 이 원판 `0xFF` → 한글판 `0xFC` = 반응 0x7C → 대본 0x247716(`0C 06 1D` = 동작 0x1D06 으로 가라)
  → 모로즈미 동작 표 밖 0x050872(카트 밖, 0 으로 읽힘) → 대본 해석기 `0x226F32` 가 op 0x00 을 영영 돈다.
  이게 맞음 처리 호출 안이라 그 프레임의 KO 확인(`0x21D188`, `0x5823 |= 0x88`)에 끝내 못 간다.
- 유저가 친 기술: 공용 슬라이딩(동작 0x7E, 11 캐릭터 공용). 일어나며 B(또는 대시 ↓B)로, 등을 돌리고 서 있던 모로즈미를 KO.

| 반응 id | 칸 수 | 고치기 전 |
|---|---|---|
| 0x7C | 6 | 그 프레임에서 멈춤(유저 사례) |
| 0x7B·0x7E | 1 + 3 | KO 는 되는데 라운드가 안 끝남(0x411A=3 에서 멈춤) |
| 0x7D·0x7F | 15 + 7 | 라운드는 가는데 박자가 달라짐 |
| 나머지 337 칸 | | KO 동작이 원작과 다르게 나옴(멈춤은 없음) |

원판 롬에선 네 반응 표 모든 칸이 0x7A 이하 또는 0xFF 라 같은 장면이 정상 KO. 원버튼·프레임 생성·앱 기능 탓 아님.

## 고침 — 코어 패치 둘 (PocketCore `tools/core_patches/`, 동봉 코어 ci-core 70123cf 부터 = 내부 151)

- `zz_ss2_ko_guard.patch` — 비교 두 바이트만 **메모리 안 롬 사본**에서 고침: `cp D,0xFF / jr Z` → `cp D,0x77 / jr NZ`
  (파일 오프셋 0x02470F 0xFF→0x77, 0x024710 0x66→0x6E). 롬 머리가 사무쇼2(카탈로그 48/26)이고 0x024708 의 14바이트가
  알려진 모양일 때만. 원판에선 동작이 같다(램 바이트까지). 롬 파일·md5·한글 글씨·음악(Ss1Music) 그대로.
  상태 불러오기(`FLASH_StateAction`)가 롬을 `orig_data` 로 되돌리므로 거기서도 다시 건다.
- `zz_ss2_ko_watchdog.patch` — 이미 멈춘 채 저장된 상태·오토세이브 살리기. 라운드 중(0x40A7==241, 0x411A==1) 선수 블록
  +0x4F 대본 포인터가 카트 롬(0x200000~0x3FFFFF) 밖이면 보통 KO 반응 대본 0x242DCB 로 돌린다(범위 안으로 올 때까지 매 프레임).

## 시험 (리눅스, 1cb33c9 + 전체 패치)

- KO 직전 상태(`pre_hit`, 플래시 있는 판 포함) × 롬 5종(JUE·한글 동봉·ko101·KO_mute·h1 한글): 모두 KO 0 프레임,
  2라운드 622 프레임, 0x4000~0x6AFF 가 JUE 와 같음(KO_mute 는 음악 편집만 다름).
- 유저 상태 두 개 × 롬 3종: 우쿄 승 1:0, 2라운드 504·505 프레임.
- 강제 반응 0x7B~0x7F: 모두 0xFF 와 같은 결과.
- 일어나며 KO 180 번: 고치기 전 12번 멈춤 → 0.
- 감시 장치 오탐: 약 160만 프레임 무작위 대전·보스(유가)·연출 0번.

## 남은 것

- NGP.emu(emu-ex-plus-alpha) 쪽도 같은 한글패치를 쓰면 같은 멈춤이 난다 — 그쪽 롬 불러오기·상태 불러오기 자리에 같은 두 바이트를.
- ss2-sp-core main 에 올릴지는 코어 방 판단(지금은 앱 방 패치로만).
