### 1-나. 그림이 어디서 오나 — 무압축 롬 타일, 낱말 복사 고리 (E2·E3·E5~E7)

한패 동봉(`ss2_ko_bundled`)·한패 1.01·h1 한패 1.01·순정 JUE 네 판 모두 묶음 표·타일 묶음(0x332054~0x3D8204)·포즈 레코드 영역·복사 고리 바이트(0x2006B0~)가 같다. 한글 패치는 그림 묶음을 안 건드린다 → 옷 데이터는 롬 판과 상관없이 하나로 된다(팩엔 묶음 CRC 를 넣어 다른 해킹판을 거른다).

### 1-마. 고르기 화면 키 (E19 — 같은 상태에서 누른 판·안 누른 판 비교)

- **검질 고르기(MODE 240 · SCR 4): ↑·↓·OPTION 을 눌러도 작업 램(스택 밖)·VRAM 이 안 누른 판과 같다** → 게임이 안 쓴다. B = 캐릭터 고르기로 뒤로.
- 캐릭터 고르기: OPTION·B 는 게임이 안 쓴다(형제 갈래 컬러가 쓴다), ↑↓ 는 커서 이동.
→ 옷은 **검질 고르기 ↑↓** 가 비어 있다.

## 2. 갈래별 판단

### (a) 팔레트만 — 이미 있음
몸이 팔레트 하나라 «옷 색 바꾸기» = 팔레트 0 의 세 색 바꾸기 = 지금 리그 컬러(코어 `retro_ngp_palremap`)와 형제 갈래 «컬러 16가지 + 내 색». 피부와 흰 옷이 같은 번호(1)라 «옷만 빨갛게»는 캐릭터에 따라 안 된다(하오마루). 아웃핏에서 따로 할 일 없음 — 무늬·팩 옷과 **곱해서** 쓴다.

### (b) 부위마다 다른 팔레트 — 안 함
- 하드웨어는 스프라이트(8×8)마다 팔레트를 고를 수 있지만 게임은 몸 25장을 모두 팔레트 0 으로 쓴다. 부위를 나누려면 «이 타일은 머리/옷/다리» 표가 필요한데,
  ① 타일 하나에 얼굴과 머리띠·옷과 손이 섞여 있어 타일 단위로는 경계가 8px 덩어리로 깨지고, ② 화소 단위 부위 지도(타일 34,272 × 64화소)는 다시 그리기와 품이 같다.
- 자리(포즈 안 줄 번호)로 «아래 줄 = 바지» 같은 규칙은 앉기·점프·쓰러짐에서 머리가 칠해진다.
- 대신 «색 번호 하나 안에서 무늬»(무늬 옷)와 «포즈 단위 화소 처리»(백발)가 같은 느낌을 품 적게 낸다.

### (c) 장신구 겹치기 — 기술은 됨, 나중
- 빈 스프라이트 칸은 대개 12~28장 남지만 게임이 매 프레임 앞에서부터 채우고(최대 64), 같은 우선순위에선 앞 칸이 위라 뒤 칸 장신구는 몸 뒤로 숨는다 → 진짜 스프라이트보다 **코어 렌더러에서 겹쳐 그리기**(gfx.c 스프라이트 줄 그리기 + ss2fg.c 사이 그림 둘 다)가 맞다.
- 머리 위치는 램·롬에 없다(판정 박스도 해석 안 됨). 대신 **타일 단위 기준점**이 쉽다: 코어가 칸마다 «올린 롬 타일 번호»를 알므로(시제품 `tm_slot_src`), «포즈마다 머리가 든 타일 번호 + 그 안 dx·dy» 표만 있으면 그 스프라이트의 화면 자리에 붙인다(뒤집기 반영).
- 표 만들기: 포즈 3,100개. 자동 추정(가장 큰 «두꺼운 어두운 덩어리» = 머리카락의 꼭대기 가운데, E18)은 하오마루 194포즈 중 189포즈에 점이 찍히고 서 있는·공격 포즈는 대체로 맞지만, 쓰러짐·뒤집힘·머리 숙임은 틀린다(`anchor_auto_2.png`). 머리가 밝은 캐릭터(갈포드 흰 머리 = 색 1)는 다른 규칙이 필요.
  → 도구로 사람이 찍기(3~5초/포즈 → 전부 3~5시간), 머리가 안 보이는 포즈는 «숨김».
- 장신구 그림은 방향별(앞·옆·뒤·기울기) 몇 장 — 빠른 동작에서 1~2px 흔들림·회전이 어색할 위험. 품 대비 효과가 무늬·팩보다 낮다 → 3단계.

### (d) 다시 그린 옷 — 길은 다 열림, 그림이 병목
- 두 가지 넣는 길:
  - **런타임 바꿔 넣기(추천)**: 코어가 «타일 번호 → 새 16바이트» 표로 바꿔 쓴다. P1·P2 따로, 경기마다 바꿀 수 있고, 롬 사본이 필요 없다. 한계: **있는 칸 안에서만**(포즈의 스프라이트 배치·장수는 게임 것 그대로 — 윤곽 밖으로 넓히는 그림은 못 넣는다. 시트 도구가 칸 밖 화소를 세어 알린다).
  - 롬 사본 패치(한글 패치처럼): 배치도 바꾸고 묶음을 옮겨 타일을 늘릴 수 있지만(묶음 표만 고치면 됨, 포즈당 25장·25칸 한도), **P1·P2 가 같은 그림**(미러전 구분 불가)이고 실행 전에 골라야 한다 → 나중에 «큰 개조»가 필요할 때만.
- 시제품으로 둘째 길의 앞부분까지 확인: 포즈 전부 시트 내보내기 → 고친 시트 되읽기 → 팩 → 코어 바꿔 넣기 → 실제 경기 화면(3장).

## 3. 시제품 — 무엇을 만들고 돌렸나

### 3-가. 코어 패치 `retro_ngp_tilemap` (`<O>/proto/core_tilemap.diff`, 빌드 `<O>/core_clean/core_tilemap.so`)

gfx.c(상태·API·바꿈) + mem.c(두 줄 훅). 요지:

```c
/* gfx.c */
void retro_ngp_tilemap(int who, unsigned slot_lo, unsigned slot_hi, unsigned bank_lo, unsigned bank_hi,
                       int pat_from, int pat_to, const uint8 *mask8);      /* who 0·1, who<0 = 모두 끔. slot/bank 가 비면 그 자리 끔 */
void retro_ngp_tilemap_repl(int who, int nidx, const uint16 *words, const uint8 *has, int xor_rom);  /* 복사함. xor_rom=1 = 롬과의 XOR 차이 */
void retro_ngp_tilemap_refresh(int who);   /* 지금 그 자리 칸을 롬에서 다시 읽어 지금 설정으로 바로 입힘(끄면 원래 그림) */
uint16 ngp_tilemap_w(uint32 address, uint16 data, const uint8 *rom, uint32 romlen);   /* mem.c 가 부름 */

/* mem.c */
loadW():  if (ngp_tm_any && address >= 0x200000 && address < 0x400000) ngp_tm_src = address;   /* 마지막 롬 낱말 읽기 */
storeW(): if (ngp_tm_any && address >= 0xA000) data = ngp_tilemap_w(address, data, ngpc_rom.data, ngpc_rom.length);
```

- 맞는 쓰기 = 대상 타일 ∈ [slot_lo, slot_hi) **그리고** `ngp_tm_src` ∈ [bank_lo, bank_hi) **그리고** 쓰는 값 아랫바이트 = 롬[src](복사 고리가 아닌 쓰기는 그냥 통과).
- 바꿈 = `idx = (src − bank_lo) / 16`, `row = (src & 15) / 2` → 바꿈 표에 idx 가 있으면 그 줄, 없으면 무늬: `from` 색 화소 중 8×8 가리개 칸을 `to` 색으로(비트 연산 몇 개 — 표 없음, 반복해도 같은 결과).
- 칸마다 올린 롬 주소를 적어 두고(`tm_slot_src[512]`) `refresh` 가 그걸로 다시 입힌다.
- 상태 저장엔 안 들어간다(앱이 매 프레임 정함 — palremap 과 같은 방식). 아무 자리도 안 켜면 `ngp_tm_any = 0` 이라 읽기·쓰기 길에 비교 하나뿐.

## 4. 추천 기능 — «옷»

### 4-가. 무엇을 주나

- 캐릭터마다 옷 목록: **기본 · 물방울 · 줄무늬 · 격자 · 사선** + 그 캐릭터 팩(첫 판: 하오마루 «백발»). 하오마루는 무늬 넷을 빼고 «기본 · 백발».
- 컬러와 따로 고르고 곱해진다(예: 나코루루 «쪽빛» × «격자»). 컬러는 팔레트(코어 palremap), 옷은 타일(코어 tilemap) — 서로 안 건드린다.
- 모든 모드(1인 대전·무한 대전·연습·리그)에서, 형제 갈래 `look.c` 가 켜진 판(사쇼2 · 롬 확인 · 설정 «겉모습 고르기» 켬)에서만.
- 리그: 상대 12명에게 **고유 옷**(P2 자리, 설정 «상대 고유 옷», 형제 갈래 «상대 고유 컬러»와 한 스위치로 묶어도 됨). 미러전에서도 P1·P2 가 따로라 안 섞인다.
- 연습: 더미(P2)는 기본. 내 옷만.

### 4-나. 어디서 고르나 (게임 화면 안)

```
검질 고르기 (MODE 240 · SCR 4, look 이 쥔 동안)
  ↑ / ↓  : 옷 바꾸기(이전/다음, 그 캐릭터에서 쓸 수 있는 것만 돈다) — 게임엔 안 준다(원래 안 쓰는 키)
           → 바로 retro_ngp_tilemap(0, 0x100, 0x119, 묶음[커서 캐릭터], …) + refresh(0) → 다음 프레임 미리보기 그림이 그 옷
           → 오른쪽 세로 칸 = 옷 이름(1.5초 또는 ↑↓ 를 누르는 동안), 그 뒤 다시 컬러 이름
  OPTION : 컬러(형제 갈래 그대로)
  ← / →  : 수라·나찰(게임)
  A      : 결정 — 옷은 캐릭터마다 기억(mem), 경기 내내 P1 자리
```
- 캐릭터 고르기 화면에선 ↑↓ 가 커서라 옷은 안 바꾼다. 다만 커서 캐릭터의 **기억된 옷**을 미리보기에 입힌다(자리 0 = 0x100~0x118, 묶음 = 커서 캐릭터, 커서가 바뀌면 refresh).
- 가운데 무작위 칸(쿠로코)·유가: 옷 없음(쿠로코는 묶음 15~17 중 하나 — 안 다룬다). 무작위로 정해진 캐릭터는 그 캐릭터 기억 옷.

## 6. 데이터 형식

- **.ss2o 팩 v2**(앱 assets `outfit/c<NN>_<이름>.ss2o`, 사용자 파일도 같은 형식)
  ```
  "SS2O" u8 ver=2  u8 char(0~14)  u8 mode=2(XOR)  u8 nlen  name[nlen](UTF-8, 5글자 이하)
  u32 crc32(그 캐릭터 타일 묶음 원본 바이트: 묶음표[char] ~ 묶음표[char+1])
  zlib( u16 n,  n × { u16 idx, 16B (새 타일 XOR 롬 타일) } )
  ```
  파일엔 원래 그림이 없다(롬이 있어야 풀린다 — 한글 패치를 패치 파일로 두는 것과 같은 생각). 백발 = 1516타일 → 11,225바이트.
- `Settings`(앱 전체): `look.outfit.<ch>` = 옷 id(0 기본, 1~4 무늬, 16~ 팩 순번 — 팩은 이름으로 다시 찾음), `look.outfitOn`, `look.oppOutfit`.
- 리그 경기 기록 `league.json` matches[].look: `{"color":n, "outfit":id, "oppOutfit":id}`(없으면 0 — 옛 기록 그대로 읽힘).
- 상태 옆 `<경로>.look`(형제 갈래 8-다): 판 번호를 올리고 `u8 outfit, u8 oppOutfit` 추가(옛 판이면 0).
- 코어 쪽은 상태 저장에 아무것도 안 더한다.
