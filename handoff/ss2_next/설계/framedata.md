# 연습 대전 프레임 데이터 — 조사와 설계 (framedata)

요청(유저 원문): «연습모드는 프레임 발동시간 경직 차 등»
→ 연습 대전에 SF6 같은 **프레임 미터**와 **발동 · 지속 · 경직 · 경직 차(유불리)** 숫자를 넣는다.

대상: Legacito · 사무라이 스피리츠!2(NGPC) «연습 대전» (`practice.c`, 소스 fgint `7a851e6`) · 코어 `core_89860fe.so` · 2026-10-15
이 폴더: `next/framedata/` — 이 문서, `x/`(실험·참조 구현·시험), `x/results/`(결과), `proto/`(시제품 패치: C·자바), `work/`(작업물: 롬에서 나온 그림·상태 파일 — **밖으로 내지 않는다**).

표시
- **[실측]** 이 조사에서 하네스로 잰 것(스크립트 이름을 붙임). **[0단계]** `ss2_practice/0단계_조사설계.md` 값(이번에 다시 확인한 것은 [실측]으로 올림).
- 주소는 모두 CPU 주소. 코어 `SYSTEM_RAM` 오프셋 = 주소 − 0x4000. 플레이어 블록 P2 = P1 + 0x200, 표시 물체 P2 = P1 + 0x40.
- 프레임 = **진짜 게임 프레임(60Hz)**. 런어헤드·프레임 생성의 숨은 프레임은 세지 않는다(4-11).

## 0. 한눈에

- **된다 — 롬·코어 손 안 대고.** `practice.c` 가 진짜 프레임마다(이미 부르는 `practice_tick` 안) 램을 **읽기만** 해서 두 사람의 프레임을 분류한다. 미터를 켜고 꺼도 게임 램은 바이트까지 같다(FD-5).
- **판정 주소 넷이면 충분하다**(전부 실측 확정)
  - 조작 바이트 `0x59CE/0x5BCE` — 0 = 움직일 수 있음. **유불리의 기준**. 두 사람 다 «↓ 를 쥐고 있으면 이 값이 0 이 되는 바로 그 프레임에 앉는다»로 확인(e12·e13, VS 경로).
  - 공격 상자 `물체 +0x1C`(P1 `0x4E4C` · P2 `0x4E8C`) — FF 가 아니면 상자 있음. **게임은 상자를 켠 다음 틱에 맞춤을 본다 → 상자 + 2프레임 = «닿을 수 있음»**. 18기술에서 순간이동 탐침과 발동이 모두 같다(5장).
  - 히트스톱 `0x5DC7` — 0 → 0 아님 = 닿은 프레임. 닿은 프레임 다음부터 얼림(미터에 안 쌓음).
  - 장풍·동물 = `0x4180` 활성 물체 목록(새로 찾음) 의 4번 칸부터 `+0x06`(살아 있음)·`+0x1E`(공격 상자)·`+0x27`(주인).
- **실측 하이라이트**(하오마루, 샬럿 더미)
  - 약베기 5A: **발동 7F · 지속 6F · 경직 14F · 히트 −2 · 가드 −6**
  - 강베기(A 길게): 발동 9F · 지속 4F · 경직 42F · 히트 −8 · 가드 −12
  - 앉아 약베기: 발동 7F · 히트 +6 · 가드 −6 · 앉아 강베기: 다운 +120 · 가드 −10
  - 236A(선풍열참·장풍): 발동 11F · 가드 −20 · 623A(호월참): 발동 5F · 가드 −42 · 잡기(→+A 길게, 붙어서): 발동 3F · +26
  - 4캐릭터 × 8기술, 위상 0/1 × 거리 2가지 = 같은 값(5장). 런어헤드 2 + 프레임 생성 켬 · 시계 셋 · 롬 4판(순정·한패 v1.01·h1 한패·동봉)에서 미터·요약이 해시까지 같다(4-11).
- **새로 알게 된 게임 규칙**(미터 뜻에 들어감)
  - 게임 로직은 30Hz → 지속·경직·유불리는 **늘 짝수**, 발동은 늘 홀수(첫 프레임을 1로 세므로).
  - **약베기는 버튼을 뗄 때 나간다** → 누른 프레임보다 최소 2F 늦게 시작. 1프레임 탭은 틱 사이에 빠질 수 있다.
  - **선입력 거의 없음**: 보통 기술은 움직일 수 있게 되기 1프레임 전부터만, 필살은 3프레임 전까지(4-4).
  - **다운 유불리는 맞은 쪽 입력에 달렸다**: 더미(가만히)는 가장 늦게 일어난다. ↓·↑ 쥐면 44F 빨리(빠른 기상), 뒤로 쥐면 32F 빨리(구르기)(4-7).
  - **B 는 발차기가 아니다**: B 단독 = 판정 없는 동작(0xB8, 32F), ↓B·→B = **튕겨내기**(5F부터 16F 판정, 전체 52F), ←B = 찌르기(발동 7F · 히트 −16 · 가드 −32).
- **시제품이 이미 돈다**(`proto/`)
  - `practice.c` 패치(+약 290줄): 참조 구현 `x/fd_ref.py` 와 **프레임마다 같음** — 10 시나리오 + CPU 더미 무작위 4800프레임(FD-1). 순정 롬·앱 모드도 같음.
  - 기존 1단계 시험 `t_practice.py` 68개 **그대로 통과** — 한패 동봉판·순정 JUE 판 둘 다(10-2).
  - NDK clang arm64·armv7 `-Wall -Wextra` 경고 0. 앱 자바 전체(+미터 뷰·EmuActivity 연결)를 android-34 `android.jar` 로 컴파일. JVM 숫자 줄 시험 15개 통과.
- **UI**
  - 켜기: 게임 속 연습 메뉴 7번째 줄 «대미지 [표시/끔]» → **«표시 [대미지 / 프레임 / 둘 다 / 끔]»**(줄 수 그대로 — 창이 더 못 커진다, 7장).
  - 미터: **앱 덮개**(안드로이드 뷰). 두 줄 × 80칸(«나» · «상대») + 숫자 줄 «발동 7F · 지속 6F · 경직 14F · 히트 -2 · 가드 -6». 안내 띠와 같은 규칙으로 패드 버튼을 피해 게임 그림 아래 빈 줄에, 자리가 없으면(가로) 게임 그림 아래 끝에 반투명으로. 끌어서 옮기고 두 번 톡 = 기본 자리.

## 1. 무엇을 보여 주나

### 1-가. 말과 셈 (SF6 와 같게)

| 말 | 뜻 | 우리 셈 |
|---|---|---|
| 프레임 미터 | 두 사람이 프레임마다 무엇을 하는지 칸으로 | 한 칸 = 진짜 프레임 1. 히트스톱으로 얼린 프레임은 안 쌓음(닿은 프레임은 쌓음) |
| 발동 | 첫 «닿을 수 있음» 프레임의 번호 | 동작 첫 프레임(조작이 0에서 바뀐 프레임) = 1 |
| 지속 | 닿을 수 있는 프레임 수 | 첫 ~ 마지막 «닿을 수 있음» 사이(중간에 빈 프레임이 있는 다단 기술은 빈 것까지 — 미터 색으로 보임) |
| 경직 | 지속이 끝난 뒤 움직일 수 있을 때까지 | 마지막 지속 다음 ~ 조작이 0 이 되기 전 |
| 전체 | 동작 길이 | 발동 − 1 + 지속 + 경직 |
| 경직 차(유불리) | 닿은 뒤 누가 먼저 움직이나 | (맞은 쪽이 움직일 수 있게 된 프레임) − (친 쪽이 …). 숫자 줄은 늘 **내(P1) 쪽에서**: + = 내가 먼저 |
| 히트 / 가드 / 잡기 / 다운 | 유불리의 종류 | 닿음 종류(6-3). 다운 = 맞은 쪽이 다운(조작 0x10)을 지남 |

- **움직일 수 있음 = 조작 바이트 0.** 앉기·걷기·막기·공격 모두 이 프레임부터 된다(4-5). 점프(0x08)·대시(0x04/06) 중에는 공격만 되고 막기는 안 되므로 유불리 셈에서는 «아직»이다.
- 기술이 맞거나 막히면 게임이 친 쪽 동작을 늘린다(히트 때 약 4~5F 더 멈춤, 가드 때 «반동»으로 바뀜 — 4-6). 그래서 **지속·경직 숫자는 헛쳤을 때 잰 값을 기억해 두고** 보여 준다(6-6). 미터 칸은 그때그때 실제 그대로.

## 2. 조사 방법

- **하네스**: `ph.PH` (앱 `native.c` 와 같은 순서: 입력 콜백 → `retro_run` → `league_tick_hub` → `practice_tick`). `x/fdh.py` 가 연습 경기에 들어가 상태를 담고 되돌린다(`fight(h, 더미, 나)`, `snap/restore` = 코어 직렬화 + `practice_state`).
- **두 모드**(`FD_MODE`)
  - `clean`(기본): 런어헤드 0 · `ngp_framegen=disabled` → `retro_run` 1번 = 진짜 1프레임. (주의: ss2probe 기본값 `off` 는 이 코어가 모르는 값이라 «자동»이 된다 — [0단계] 하네스 주의와 같음.)
  - `app`: 런어헤드 2 · 프레임 생성 `on`(앱 기본과 같음, `hosttest.Harness`).
- **시계**: `LD_PRELOAD=clkwrap/ftenv.so FIXT=1791974914`(기본) · `FIXT=1700000000` · 고정 안 함(실제 시계).
- **세 가지를 따로 재서 서로 맞춰 봄**
  1. **램 추적기**(`x/fd_ref.py`) — 이 설계의 규칙 그대로.
  2. **순간이동 탐침**(발동 확인, `x/e4.py`·`measure.py probe`): 멀리서 헛친 기술을 j 프레임째에 멈추고 더미를 내 앞 24px 로 옮겨(블록 X·지난 X·표시 X) 닿는 첫 프레임을 찾는다. j 를 하나씩 밀어 «닿을 수 있는 프레임 집합»을 얻는다 — 램 값을 하나도 믿지 않는 방법.
  3. **VS 경로 ↓ 쥐기**(유불리 확인, `x/e13.py`·`measure.py vs_run`): `0x57D4=1 · 0x5BCB bit0 끔 · 0x570D = P1 패드 · 0x5715 = P2 패드`([0단계] 2단계 경로)로 **두 사람 다 ↓ 를 계속 쥐게** 하고, 각자 실제로 앉는(ACT 0x14 · 조작 0) 첫 프레임의 차를 잰다.

| 0x14 | B 단독 동작 끝 12F | 내 동작 |
| 0xFF | 필살·강베기·잡기·점프 공격·**가드당한 반동**·잡히는 중 | 내 동작 / 맞는 줄이면 맞음·막음 |

- 맞는 줄(0x0A·0x0C·0x10·0x12, 또는 닿은 프레임에 맞은 쪽)에 들어가면 **0 이 될 때까지 경직**으로 본다 — 장풍을 막으면 0xFF 10F 뒤 0x12, 띄우는 기술은 0x0A → FF → 0x0C → FF → 0x10 → 0x02(기상) 순(e19).

### 3-다. 표시 물체 (0x4E30 + 0x40·k, 0/1 싸움꾼 · 2/3 그림자 · 4~ 장풍·효과·동물)

| 칸 | 뜻 | 근거 |
|---|---|---|
| +0x0E | ACT(u16) — 동작 id. 공통 0x08 서기 · 0x14 앉기 · 0x1C/0x20 걷기 · 0x34 점프 · 0x38 가드. 필살 ≥ 0x180 | [0단계] |
| +0x10 / +0x11 | 애니메이션 칸 ×4 / 남은 틱 — 히트 때 친 쪽이 히트스톱보다 몇 프레임 더 멈추는 것이 여기 보임 | [실측] e2·e3 |
| **+0x1C/+0x1D** | **싸움꾼 공격 상자** — FF FF = 없음(하오마루 약베기 0x40 0x02, 갈포드 0xC0). **켜진 다음 틱(+2F)부터 닿을 수 있다** | [실측] e3·e4·5장 |
| +0x1A/+0x1B | 몸(맞는) 상자 같음 — 서기 0x0C, 공격 중 0x14. 안 씀 | [실측] e3 |
| **+0x06** | 살아 있음(FF = 죽음/끝). 효과·장풍 공통 | [실측] e21 |
| **+0x1E/+0x1F** | **장풍·동물 공격 상자**(FF FF = 없음). 하오마루 장풍 0x88 0x02 · 샬럿 장풍 0x94 0x01 · 갈포드 러시 독 0x1C 0x03. 베기 잔상(0x8C/0x9C/0xA0)·불꽃 같은 효과는 FF | [실측] e21·e23 |
| **+0x27** | **주인**(0 P1 · 1 P2) — 방향(+0x24)과 따로. P1 이 왼쪽을 보고 쏴도 0 | [실측] e16·e17 |
| +0x24 | 방향(1 = 왼쪽) | [0단계] |

- 갈포드 개(4번 칸, ACT 0x24C)·나코루루 매는 **늘 살아 있고**(+06 = 07) 주인이 걸을 때도 공격 상자를 켠다(e23). 그래서 «장풍» = **주인이 동작 중일 때 공격 상자가 꺼짐 → 켜짐으로 바뀐 물체**만 친다(arm). 꺼지면 풀린다.

### 3-라. 찾았지만 안 쓰는 것 · 못 찾은 것

- 가드 경직 남은 시간 칸 — 없다(가드 애니메이션 칸 +0x10/+0x11 로 끝남). 미터는 조작 바이트로 충분.
- 입력 버퍼 — 따로 없다(4-4). 커맨드 고리 0x5DD0~ 는 [0단계] 그대로.
- 히트박스 모양(상자 번호 → 사각형) — 롬 표 해석이 필요. 이번엔 «있음/없음»만 쓴다.

## 4. 게임 규칙 실측 — 프레임 데이터를 읽는 법

### 4-1. 30Hz 박자

게임 로직은 2프레임에 한 번 돈다([0단계]). 그래서 상자·조작·애니메이션은 짝수 프레임 단위로 바뀌고, **지속·경직·전체·유불리는 늘 짝수**, 발동은 첫 프레임을 1로 세므로 **늘 홀수**다(5장 표 전부). 같은 기술을 누른 프레임의 홀짝(위상)만 바꿔도 값은 같다(5장 «위상 0/1»).

### 4-2. 판정은 상자를 켠 다음 틱

하오마루 약베기를 멀리서 헛치고(e4), j 프레임째 더미를 앞에 두면 닿는 프레임 = {8, 10, 12}, 상자 `+0x1C` 가 켜진 프레임 = 6~11. **닿을 수 있는 프레임 = 상자 프레임 + 2**. 강베기(상자 14~17 → 닿음 16·18), 앉아 약(12~17 → 14·16·18), 623A(18~ → 20~)도 같다. 추적기는 쌓은 칸 기준 **2칸 지연 줄**로 «지속»을 칠한다(6-3) — 5장 18기술 모두 탐침 발동과 같다.

### 4-3. 약베기는 뗄 때 나간다

A 를 눌러 2F 쥐면 틱 패드(0x5A6B)에 1F 뒤 보이고, **뗀 다음 틱**에 동작이 시작된다(누른 프레임 +3). 8F 넘게 쥐면 강베기(0x64)로 정해진다. B 는 누른 그 틱에 바로 시작. 1프레임 탭은 틱 사이에 빠질 때가 있다(e25 «A 탭 1F» 열의 x). → 미터의 발동은 **동작 첫 프레임부터** 센다(SF6 와 같음). 버튼에서 세면 약베기는 +2~3.

### 4-4. 선입력(버퍼)

약베기 경직 중(움직일 수 있는 첫 프레임 = F) t 프레임에 다음 입력을 넣었을 때 둘째 동작이 시작되는 때(e25):

| 입력 | t ≤ −4 | −3 | −2 | −1 | 0 | +1 | +2 |
|---|---|---|---|---|---|---|---|
| A 2F 탭 | 버려짐 | 버려짐 | 버려짐 | F+2 | F+2 | F+4 | F+4 |
| 236A(버튼 t) | 버려짐 | **F+2** | **F+2** | F+4 | F+4 | F+6 | F+6 |
| ↓ 쥐기(앉기) | — | — | — | — | **F**(e12) | | |

→ 보통 기술은 버퍼가 없고, 필살은 한 틱 남짓 일찍 넣어도 된다. 유불리 +2 로 약베기(발동 7)를 이으면 실제로는 «7 + 뗄 때 2» 를 계산해야 한다 — 미터 설명 문구에는 넣지 않고 문서·도움말에만.

### 4-5. «움직일 수 있음» = 조작 0 (두 사람 다)

- P1: 약베기 뒤 ↓ 를 쥐고 있으면 조작이 0 이 되는 **그 프레임**에 앉는다(ACT 0x14) — 히트·가드 × 위상 0/1 네 경우 모두(e12).
- P2(더미): VS 경로로 ↓ 를 쥐게 하면 역시 조작 0 인 그 프레임에 앉는다(e13).
- 그래서 유불리 = `조작이 처음 0 이 된 프레임` 차이. combat_ref([0단계] 타격 조사)와 같은 규칙이고, 무작위 7대진 × 5000프레임에서 사건 목록이 **완전히 같다**(`x/rb.py`, 아래 10-1).

### 4-6. 히트스톱 · 친 쪽 연장 · 가드 반동

- 히트스톱 동안 두 사람 다 멈춘다. **닿은 프레임은 미터에 쌓고 그다음 얼린 프레임은 안 쌓는다**(SF6). 유불리는 두 사람 다 같이 멈추므로 영향 없음.
- **히트**: 친 쪽은 히트스톱이 끝난 뒤에도 애니메이션 한 칸을 2틱 더 쥔다(+0x11 이 2 에서 4F 머묾, e2). 약베기 미터: 헛침 전체 26칸 → 히트 31칸(지속 칸이 6 → 11).
- **가드**: 친 쪽 조작이 0x02 → **0xFF(반동)** 으로 바뀌고 공격 스크립트(0x5A56~)가 지워진다. 약베기 미터: 지속 2칸 + 반동 29칸 = 37칸.
- → 지속·경직 **숫자**는 헛쳤을 때 잰 값을 기억해서 보인다(6-6). 칸은 실제 그대로.

### 4-7. 다운과 빠른 기상

하오마루 623A 히트(e22) — 맞은 쪽 조작 `0A ×28 → FF ×40 → 0C ×12 → FF ×46 → 10 ×62 → 02 ×4 → 0`. 맞은 쪽이 **입력을 쥐면 달라진다**:

| P2 입력(VS 경로, 닿은 뒤 계속) | 다운(0x10) | 움직일 수 있게 된 프레임 | 차이 |
|---|---|---|---|
| 없음 · A | 62F | 213 | 기준 |
| ↓ 또는 ↑ | **건너뜀**(바로 기상 0xB8) | 169 | **−44F**(빠른 기상) |
| 뒤(→, P2 기준 뒤) | 30F 뒤 구르기(0xC0) | 181 | −32F |

- 실측 표(5장)의 «다운 +N» 은 **가만히 있는 더미 기준**(연습 더미는 입력이 없다). VS ↓ 쥐기 값과 늘 44 차이(하오마루 2A+ 120 / 76, 236A 124 / 80, 623A 104 / 60, 갈포드 2A+ 98 / 54, 샬럿 623A 114 / 70, 나코루루 2A+ 122 / 78). 갈포드 214A 만 VS 쪽이 8F 늦다(148 / 156 — 다른 다운 종류).
- 숫자 줄은 «다운 +120» 으로 쓰고, 도움말에 «상대가 빨리 일어나면 44F 줄어요». 더미 기상 고르기(그대로·빠른 기상·구르기)는 VS 경로가 필요한 2단계 일이다(11장).

### 4-8. B 버튼은 발차기가 아니다

순정·한패 롬, SP 엔진 켬·끔 모두 같다(e9). 하오마루로 잰 값(e7·e8·e26):

| 입력 | ACT | 판정 | 미터 / 숫자 |
|---|---|---|---|
| B | 0xB8 | 없음(조작 FF 20F + 0x14 12F, 손을 내미는 자세) | 청록 32칸 «동작 · 전체 32F» |
| ↓B · →B | 0x40→0x50 · 0x3C→0x4C | 튕겨내기(자세 0x01 · 0x02), 5F부터 16F, 파란 고리 | 청록 + 위 흰 띠 «튕겨내기 5F · 지속 16F · 전체 52F» |
| ←B | 0x54(스크립트 0x007A) | 있음 | «발동 7F · 지속 6F · 경직 38F · 히트 −16 · 가드 −32»(샬럿은 발동 5F, 히트 −18 · 가드 −34) |
| A+B | 0xC8 | 있음, 여러 번 닿음(불기둥) | — |

과제 문장의 «킥»은 이 게임에 따로 없어서 ←B 를 B 계열 공격 대표로 쟀다.

### 4-9. 잡기

붙어서(간격 ≤ 17) → 또는 ← + **A 길게**(강베기 입력) = 잡기(ACT 0xBC → 0xC0 앞 / 0xC4 뒤). 공격 상자가 첫 프레임에 켜져 **발동 3F**, 히트스톱 없이 콤보 수 0 → 1(잡기로 판정) → 1 → 2(이어지는 타). 하오마루·샬럿·갈포드·나코루루 모두 **+26**(가만히 선 채 일어남).

### 4-10. 장풍·동물

- 하오마루 236A: 동작 시작 +8F 에 4번 칸 장풍(ACT 0x1F0, +1E 0x88 0x02) → **발동 11F**(탐침 11 같음). 멀리서 쏘면 날아가 맞는다(150px 에서 다운 +140).
- 갈포드 236A(러시 독): 개 칸(+1E 0x1C 0x03)이 동작 +8F 에 켜짐 → 발동 11F. 개는 뒤에서 달려오므로 **24px 앞 더미에는 19F 에 닿는다**(탐침 19). 214A 도 15F / 21F. 가드 유불리가 거리 따라 0 ~ −2, −14 ~ −16.
- 샬럿 236A: 36F 모은 뒤 장풍 → 발동 41F, 히트·가드 모두 +4.
- 나코루루 236A: 매 공격(발동 7F, 위로 날아 24px 앞 서 있는 더미에는 24F).
- 장풍만 날아가고 두 사람 다 움직일 수 있는 동안은 미터에 «줄임» 한 칸만 남긴다(6-5).

## 6. 설계 — `practice.c` 프레임 데이터 추적기

시제품: `proto/practice.c`(원본과의 차이 `proto/practice.c.diff`, 추적기 본문 `proto/fd_block.c`). 참조 구현 `x/fd_ref.py` 와 규칙이 한 줄씩 같다(FD-1 이 프레임마다 견준다).

### 6-1. 놓는 곳 · 부르는 순서

- `practice_tick()` 의 경기 램 쓰기 앞:
  ```c
  if (lv && !paused && P.menu != M_EXIT) { fd_tick(ram); game_writes(ram, input); }   /* 우리가 램을 고치기 전에 읽는다 */
  ```
  → 라운드 진행 · 일시정지 아님 · 연습 경기 중일 때만, **진짜 프레임마다 한 번**(native.c 가 합성 프레임엔 안 부름, 4-11).
- `fd_reset(1)`(기술 기억만 남기고 다 비움)을 부르는 곳: `activate()`(새 경기) · `do_reset()`(Option+방향·메뉴 «지금 리셋» — 순간이동이라 지연 줄·동작이 무의미) · `practice_forget()`(리셋·상태 불러오기).
- 일시정지(메뉴 열림) 동안은 안 돈다 — 순서는 이어지고 멈춘 프레임은 안 쌓인다.

### 6-2. 자료 구조

```c
#define FD_VIEW 80        /* 미터 칸 */
#define FD_MEM  32        /* 기술 기억 */
#define FD_RUN  8         /* 같은 칸 짝이 이만큼 이어지면 줄임 */
enum { FK_IDLE, FK_MOVE, FK_STARTUP, FK_ACTIVE, FK_RECOVERY, FK_ACTION, FK_HITSTUN, FK_BLOCKSTUN, FK_DOWN, FK_GAP };   /* 0..9 */
#define FK_F_PARRY 0x40   /* 튕겨내기 판정(자세 & 0x03) */
#define FK_F_PROJ  0x80   /* 내 장풍이 닿을 수 있음 */
#define FK_EMPTY   0xFF
enum { FC_NONE, FC_HIT, FC_BLOCK, FC_THROW, FC_OTHER, FC_DOWN };

typedef struct { uint8_t kc; uint16_t ka, ks; int16_t startup, active, recovery, total, adv[4]; } FdMem;   /* 열쇠 = (캐릭 0x5B51, 시작 ACT, 스크립트 0x59CC) · adv = 히트·다운·가드·잡기(친 쪽 기준) */
typedef struct { int live, start, n, first, last, proj, contact, contact_at, pfirst, plast; uint8_t kc; uint16_t ka, ks; } FdAct;   /* 진행 중 동작 */
typedef struct { int id, startup, active, recovery, total, contact, pstart, plen; uint8_t kc; uint16_t ka, ks; } FdSum;               /* 끝난 동작 요약 */
static struct {
   int have_prev; uint8_t p_hs, p_ctrl[2], p_combo[2]; uint16_t p_act[2]; uint8_t p_cap[32];   /* 지난 프레임 */
   int8_t armed[32];                                   /* 물체 칸 → 주인(장풍) · −1 */
   uint8_t mode[2], stun[2], downseen[2], boxq[2][2], armq[2][2];   /* mode 0 자유 · 1 동작 · 2 경직 / 2칸 지연 줄 */
   FdAct act[2];
   int seq_on, len, gap_open, gap_n, run, last_pair, frozen_n; uint32_t seq_id;
   uint8_t cell[2][FD_VIEW];                           /* len % FD_VIEW 에 씀(감김) */
   int wait_on, wait[2], last_kind, att, ckey_ok[2]; uint32_t f, contact_f; uint8_t ckc[2]; uint16_t cka[2], cks[2];
   int adv, adv_kind, adv_att, adv_id, focus;
   FdSum sum[2];
   FdMem mem[FD_MEM]; int mem_n, mem_next;
   uint32_t ver;                                       /* 바뀔 때마다 + — Java 가 다시 그릴지 정함 */
} FD;                                                  /* 약 1.1KB */
```

### 6-3. 프레임마다 (`fd_tick`)

```
읽기: hs = 0x5DC7 · 두 사람 조작·콤보·자세·Y·ACT·상자(+0x1C≠FF)
      물체: 0x4180 목록 i < min(0x41C2,30): k ≥ 4 이면 cap[k] = (+06≠FF && (+1E≠FF || +1C≠FF)), 주인 +27
f++ ; 첫 프레임은 지난 값만 담고 끝
frozen = hs && 지난 hs                                  ← 닿은 프레임 다음부터 얼림

[닿음]

  hs 0 이고 콤보가 오름: 이전 콤보 0 이면 잡기, 아니면 이어지는 타(지난 종류 그대로)
  → wait = [−1,−1], contact_f = f, last_kind, att = 친 쪽
    맞은 쪽 mode = 2(경직, 가드면 막음 줄) · 친 쪽 진행 중 동작에 contact·contact_at 기록 · 유불리를 기억할 기술 열쇠 = 친 쪽 진행 중 동작
[장풍 arm]  cap 꺼짐 → armed 풂 · 지난 프레임 꺼짐 → 켜짐이고 주인이 동작 중(mode 1) → armed[k] = 주인
            proj[p] = armed 가 p 인 칸이 있음
frozen 이면 frozen_n++ 하고 [유불리]로

[칸] 두 사람 각각
  act_now = boxq[1], proj_now = armq[1]; 지연 줄 한 칸 밀기(boxq[0] = 지금 상자, armq[0] = proj)
  flags = 자세&3 ? PARRY : 0 ;  pflag = proj_now ? PROJ : 0
  조작 0          → 동작 끝(why 0) · mode 0 · Y<128 ? MOVE : IDLE
  mode 2 또는 조작 ∈ {0A,0C,10,12}
                  → 동작 끝(why 1) · mode 2 · 0x10 을 보면 이 줄은 다운 → DOWN / (가드 줄 또는 0x12) ? BLOCKSTUN : HITSTUN
  조작 ∈ {04,06,08} → 동작 끝 · mode 0 · MOVE                     (대시·점프)
  그 밖           → 새 동작?  mode≠1, 또는 캔슬(지난 조작 0x02 이고 ACT ≥ 0x180 으로 바뀜)
                      새 동작이면: 앞 동작 끝(why 2) · 열쇠 기록 · start = len · 지연 줄 비움(act_now = proj_now = 0)
                    act_now → ACTIVE(첫·마지막 기록) / proj_now 이고 아직 지속 없음 → ACTIVE 한 칸 + 장풍 표시
                    / 지속 뒤 → RECOVERY / 아니면 STARTUP ;  자세&3 이면 튕겨내기 첫·마지막 기록 ; n++
  칸 = 종류 | flags | pflag

[순서]
  actor = 누가 IDLE 아님 · flying = proj 있음
  순서 꺼짐 && (actor || flying) → 새 순서: seq_id++ · len 0 · 칸 비움 · 진행 중 동작 start = 0
  순서 켬:
    run = (칸 짝이 지난 프레임과 같으면 +1, 아니면 1)
    waitrun = actor && run > 8 && 한 사람 IDLE && 다른 사람 HITSTUN/BLOCKSTUN/DOWN
    actor && !waitrun → 칸 쌓기(len % 80)
    (waitrun || flying) → 줄임: 처음 한 번 GAP 칸 쌓고 gap_n++
    둘 다 아님 → 순서 끝(칸은 남김)

[유불리]  (얼린 프레임에도)
  contact_f 뒤 400F 넘으면 버림 · 맞은 쪽 조작 0x10 을 보면 종류 = 다운
  hs 0 이면: 각자 처음 조작 0 인 프레임 기록 → 둘 다 있으면 adv = wait[1] − wait[0] (P1 기준) · adv_id++
             기술 기억[친 쪽 열쇠].adv[종류] = 친 쪽 기준 유불리
```

**동작 끝(fd_end)**: 지속이 한 번도 없었으면 보이는 칸의 STARTUP 을 ACTION 으로 고쳐 칠한다(튕겨내기·B·도발). 요약 `sum[p]` 에 번호+1 · 발동(first+1) · 지속(last−first+1, 장풍 −2) · 경직(n−1−last) · 전체 n · 닿음 · 튕겨내기 구간. 기억: 발동은 늘, 지속·경직·전체는 **안 닿고 움직일 수 있게 되어 끝났을 때만**(헛친 값). `focus` = 이 사람(P1 동작은 늘 · P2 동작은 닿았을 때만).

| 값 | 이름 | 조건 | 색(8-1) |

| 1 | MOVE | 조작 0 · 공중 / 04·06·08 | 회색 |
| 2 | STARTUP | 내 동작, 아직 지속 전 | 초록 |
| 3 | ACTIVE | 내 동작, 2칸 지연 상자 / 장풍 첫 칸 | 빨강 |
| 4 | RECOVERY | 내 동작, 지속 뒤(가드 반동 포함) | 파랑 |
| 5 | ACTION | 지속 없이 끝난 동작(끝날 때 고쳐 칠함) | 청록 |
| 6 | HITSTUN | 맞는 줄(잡힘 포함) | 노랑 |

### 6-5. 순서 · 줄임 · 감기

- **새 순서** = 누군가 IDLE 아님(점프·대시도) 또는 내가 쏜 장풍이 날아감. 걷기는 조작 0 이라 순서를 안 연다(중립에서 미터가 흔들리지 않게).
- **끝** = 두 사람 다 IDLE 이고 장풍 없음. 칸은 그대로 두어 다음 동작까지 볼 수 있다.
- **줄임**: 한 사람이 이미 움직일 수 있고 다른 사람이 같은 경직(맞음·막음·다운)을 8칸 넘게 이어가면, 또는 장풍만 날아가면, 그 구간을 GAP 한 칸으로. 다운 100F 짜리도 미터 안에 발동부터 들어간다(하오마루 앉아 강 히트: 줄임 104F, 칸 79개 — 80칸 안).
- **감기**: 그래도 80칸을 넘으면 앞에서부터 덮어 쓴다(SF6 처럼). Java 가 지금 자리에 흰 세로줄.

### 6-6. 요약 · 기억 · 유불리 · 무엇을 보여 줄지

- 기억 32칸(가득 차면 오래된 것부터). 열쇠 = (캐릭·유파 0x5B51, 시작 ACT, 스크립트 0x59CC) — 하오마루 약베기(ACT 0x54, 0x21FA)와 ←B(ACT 0x54, 0x007A)가 다른 열쇠가 된다(e18).
- 같은 기술을 헛치고 · 맞히고 · 막히게 하면 숫자 줄이 «발동 7F · 지속 6F · 경직 14F · 히트 -2 · 가드 -6» 으로 차 간다(방금 것만 밝게).
- `focus`: 숫자 줄은 마지막으로 끝난 **내 동작**, 또는 나를 **맞히거나 막히게 한 상대 동작**(CPU 더미) — 상대 것이면 «상대 발동 5F · 막음 +6»(유불리는 늘 내 쪽).

### 6-7. 리셋 · 메뉴 · 상태 저장 · 스레드

- 리셋(순간이동)·새 경기·잊기 → `fd_reset(1)`. 상태 불러오기 뒤에도 같다(`practice_forget`).
- 상태 저장: 미터는 저장 안 함(다음 판에 의미 없음). 설정 `PS.fd` 만 `.prac` 에(6-9).
- `practice_state_get/set`(시험용 결정성)에 `FD` 포함 → `practice_state_size` = State + Settings + FD.
- 모든 읽기·쓰기는 `P_mu` 안(지금 practice.c 와 같은 자물쇠). Java 쪽 읽기도 같은 자물쇠로 160B + 40 int 복사.

### 6-9. 설정 · 메뉴 값

- `Settings` 끝에 `int fd;` — 끝에 붙여 **옛 `.prac`(40바이트)도 읽힌다**: `practice_settings_set` 이 `n == sizeof PS || n == offsetof(Settings, fd)` 를 받고, 옛 크기면 fd = 0(FD-4).
- 메뉴 7번째 줄 «표시» 값 ↔ (대미지 숫자 PS.num, 미터 PS.fd):

| 값 | 글 | PS.num | PS.fd |
|---|---|---|---|
| 0 | 대미지 | 0(보임) | 0 |
| 1 | 프레임 | 1(끔) | 1 |
| 2 | 둘 다 | 0 | 1 |
| 3 | 끔 | 1 | 0 |

  `row_value(6) = num==0 ? (fd ? 2 : 0) : (fd ? 1 : 3)`, `change_value(6)` 이 표대로 둘 다 쓴다. 옛 설정(num 0/1, fd 없음)은 «대미지»/«끔» 그대로 보인다.

## 7. 게임 속 메뉴 · 글자 (`practice_glyphs.py`)

- 바꾸는 줄 하나(`proto/practice_glyphs.py.diff`):
  ```python
  ('표시', ['대미지', '프레임', '둘 다', '끔']),     # 예전 ('대미지', ['표시', '끔']) — 대미지 숫자와 프레임 미터를 한 줄에
  ```

### 8-2. 숫자 줄 규칙 (`FrameMeterText`, 순수 자바 — JVM 시험)

`focus` 의 마지막 동작 B:
1. B 가 없으면 빈 줄(안내 글).

### 8-3. 자리 (`EmuActivity.placeFrameMeter`, `proto/java/EmuActivity.java.diff`)

1. **유저가 옮겨 둔 자리**(`pocketcore_fdmeter_p` / `_l`, 가운데 점의 화면 비율) — 안내 띠와 같은 저장 방식.

3. **없으면(가로 화면)** — 게임 그림 아래 끝에 겹쳐: 폭 = 게임 그림 − 8dp, `top = gameBox[3] − h − 2dp`, 반투명. HUD 맨 아래 줄(«PAUSE» 줄 18)과 분노 막대(줄 17) 아래 반쯤을 덮는다 — 체력·대미지 숫자(위 HUD)·싸움꾼 발은 안 덮는다.
