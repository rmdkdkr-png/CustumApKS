## 0. Key findings (gaps per reading of «리그모드는 언제든 다시할수있게»)

**(a) Re-enter from anywhere:**
- **G1.** Inside a normal game, the only way into league is title row 3. That row exists only when all of these hold:
  - the «리그·연습» option is on (`hubOn`, EmuActivity:2430; Settings.java:313);
  - the normal-session ROM copy has a verified md5, meaning no 조작 패치 (`practiceRomOk`, EmuActivity:2417; `practiceSetup` 2446–2455);
  - league.json is readable and writable (`practiceDual`, EmuActivity:2460).
  
  If any of these fails, there is no in-game route at all.
- **G2.** From a fight in progress there is no shortcut. The user has to open the pad bar, press «리셋», wait for the title, go to row 3, press ◀▶, then A.
- **G3.** The in-game options sheet (설정 / ACT_CFG) has no «리그 순위표» link. LaunchSheet:352 shows it only in the launcher (`onSettings == null && a instanceof MainActivity`).
- **G4.** LeagueActivity hides «랭크 매치 하러 가기» whenever *any* open match exists, including a `ready` one (LeagueActivity:163). The in-game hub would simply auto-cancel that `ready` match (EmuActivity:1680).

**(b) Never get locked out:**
- **G5.** A started match with no checkpoint (a crash or kill without `onPause`, or a checkpoint that fails to load) can only be forfeited. Forfeit is a full LP loss. There is no "void" option.
- **G6.** A match whose ROM or core changed since it started can likewise only be resumed on the original build or forfeited.
- **G7.** `hold` does not release `ranked.pending`. After a hold, the same opponent is served again for up to 24 h. If the hold cause is systematic (for example a knob mismatch for that opponent), this repeats as a loop.
- **G8.** `dbProblem` or `writeProblem` is a hard lock with no in-app escape.
- **G9.** If a settle save keeps failing, it retries forever with the toast «기록 저장 실패 — 다시 시도 중».

**(c) Restart / new season:**
- **G10.** There is no reset, season or archive feature. `season` and `season_start` are written but never read, and «시즌 1» is hard-coded (LeagueActivity:248).
- The only existing "reset" is involuntary. An unreadable `league.json` is silently renamed and replaced with a fresh one (League.java:115–121).

## 3. league.json, and how reset or archive would work

### 3.1 Files

Root is `<ext>/PocketCore/league/` (`MainActivity.ROOT`, line 34; `League.dir`, line 96). It holds:

- `league.json`, `league.json.bak`, `*.tmp` (written by atomic `save()`, line 149)
- `league.json.unreadable-<ts>` and `.bak.unreadable-<ts>` (from the involuntary move, 117–118)
- `ckpt_<matchId>.state` (+ `.tmp`) (101)
- `saves/`: the league session's game flash (99)
- `rom/`: the league ROM copy, regenerated (100)
- `.write_test`

### 3.2 Structure

`v` must stay 1. `read()` (136–146) returns null when `v != 1`, so any file without `v==1` is treated as unreadable and renamed aside.

Neither `matches` nor `ranked.matches` is ever trimmed. Every `save()` rewrites the whole file with `toString(1)`.

### 3.3 What exists today

There is no reset UI. The only reset is involuntary: when both files are unreadable they are renamed `*.unreadable-<ts>` and a fresh db is created silently (115–121). `dbProblem` is set only if the rename fails. That rename pattern is the existing precedent for archiving.

### 3.4 Reset variants and code paths that need care

**Variant R-a: new season / ranked restart.** Keep the legacy data, `pref` and (optionally) `seed`. Replace `ranked` with a freshly built object (`season+1`, `placement 5`, `players {}` or kept, no `pending`, `matches []`). Optionally soft-reset MMR; design note ranked.md:409 suggests pulling it 50% toward the baseline.

**Variant R-b: full restart.** Rename `league.json` and `.bak` to `*.reset-<ts>`, set `League.db = null`, and let `db()` rebuild via `fresh()`, `upgrade()` and `upgradeRanked()` (score 1000, `old=0`, so placement 5).

**Variant R-c: archive only.** Move terminal `matches` / `ranked.matches` older than N into `league/archive/*.json`.

Points that need care:

1. **Do not just delete `ranked`.** `upgradeRanked` (772) re-creates it from legacy `me`/`opps`/`matches`. With at least 5 legacy settled matches it skips placement, sets MMR from the legacy score and rebuilds `players` h2h from `opps`. Build the new object explicitly, and carry over or omit `legacy` (the rules tab reads it, 444+).
2. `upgrade()` (232) re-adds ROSTER opponents if `opps` is emptied, and runs `backfill` when `roster < 2`. For R-b this is fine; to reset the legacy league, reset scores and w/l in place instead.
3. `db` is a private static cache (105). The reset therefore has to live inside League, be `synchronized`, and use the same backup-and-rollback pattern as `hold()`/`cancel()` (440/457): `String backup = db.toString(); … if (!save()) db = new JSONObject(backup)`. Refuse while `dbProblem != null`.
4. Open matches: require `openMatch() == null`, or cancel/forfeit first (ask the user). Delete every `ckpt_*.state` and `.tmp` (`League.ckpt`, 101).
5. Clear `pending`. It is otherwise honoured for 24 h (`meOf` 839) and `trimPlayers` keeps it.
6. Seed: a new seed regenerates the whole 39,899-player pool (nicks, avatars, ranks). Caches are safe because they are keyed by seed or avatar seed: `PF_CACHE` uses `seed:id` (920), LeagueActivity `boardKey` includes the seed, and `Avatar.CACHE` uses `pf.av`. Keeping the seed but clearing `players` resets `mmr_adj`/`lp_adj`, which `book()` and `oppView` use to shift how opponents' LP is displayed.
7. Season display: `ranked.season` is never read, and LeagueActivity:248 hard-codes «시즌 1». `RankCore.Player.games(day, seasonDay)` is called with `today-30` (LeagueActivity:350).
8. Keep `pref`: `Look.migrate` reads `pref.color` whenever league.json exists (Look.java:122), and `pref.stage` is the user's stage choice.
9. Old app versions (≤146) share the folder, read `v==1`, and keep unknown keys (comment at League.java:327–328). An archive stored inside league.json survives their writes but grows the file. A separate `league/archive/` file is better.
10. Only trigger a reset from LeagueActivity. EmuActivity hub state (`rankPick`, `rankOppV`, `rankKnobs`, `hubOpp`, `leagueId`) is in memory only, and EmuActivity is already finished when LeagueActivity is showing (`leagueExit`, 1336). There is no reset entry in-game because ACT_CFG is blocked in league.
11. `league/saves/` and `league/rom/` do not need resetting. Cards are forced on via `LEAGUE_ALLCARDS` when a match is armed, and the ROM copy is regenerated.

## 4. Constraints that matter for the waiting window (overlap with entry)

- During H_SEARCH (league.c:436–449) the title menu stays visible under the overlay and the title music keeps playing. All game input is blocked and collected as `ev` bits (1 A · 2 B · 4 OPTION · 8 ← · 16 → · 32 ↑ · 64 ↓), which Java reads via `nativeHubTakeEv` in `rankTick` (2032).
- The search length is pure presentation. `RankCore.pick` (357–367) uses 1.2–2.4 s for a held opponent, otherwise 2–6 s plus up to 12 s for high MMR.
- `onPause` (1017) and opening the pad bar (176) cancel the search. Back calls `rankBack` (796).
- The overlay is a plain View added to `root` at `gameBox` top (`rankShow`, ≈2077), so it is not an Android window. That is consistent with the Ask-card rule.
