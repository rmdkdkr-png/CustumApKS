# Ranked wait: code map and waiting-room feasibility

All paths below are relative to the worktree `/tmp/claude-0/-home-user-CustumApKS/e6c46352-6bb9-5a9d-8b3a-f2da7447674e/scratchpad/impl/ranked`.

## 0. Summary

- **The wait is presentation only.** The opponent is chosen and saved as `ranked.pending` the moment the search overlay opens (`EmuActivity.rankSearchShow` → `League.rankedPick`). After that the "search" is just a Java countdown (`rankEnd = rankT0 + searchMs`) checked every 150 ms by `hubPoll`.
- **Behind the overlay the game sits on the title menu.** The cursor stays on row 3, labelled «리그 대전» with no ◀▶. Native blocks all game input and only collects presses. Today Java uses only B during the search, and A, B and stage keys on the card. A, OPTION, ←→ and ↑↓ are already collected during the search and thrown away. A richer panel can use them with **no native change**.
- **The search never outlives EmuActivity.** It is cancelled by B, Back, opening the pad bar, or `onPause`. When the "상대 발견!" card is showing, those exits keep the opponent held.
- **There is already a code path that skips the search and the card.** Rematch (-4) calls `nativeHubMatch(go=false)`, resets, and on reaching row 3 goes straight to my character select. The pending-opponent mechanism plus this path make "accept from anywhere, then go straight to char select" cheap.
- **Practice cannot run in the league session today.** `practiceSetup` and `practicePoll` both refuse to run when `ranked()` is true or a league is active. The hub is one struct `H` whose `kind` (0 league, 1 practice) is fixed when the hub is created.
- **Recommendation:** v1 = richer in-game panel (option 1) plus a mini board inside the panel (option 2A). v2 = practice while queued in the normal session, using `switchSession` and a new "go straight to char select" flag (option 3a). Option 3b (practice inside the league session) is faster to accept and plays on the same ROM and core as ranked, but needs a refactor of how the hub and Java are tied together.

### 1.2 Native `H_SEARCH` (`league.c:436-449`)
- **Screen behind:** the title menu (MODE 240, SCR 0). Row 3 is redrawn as «리그 대전» with `focus=0`, so no arrows (`:445-446`). Title music keeps playing.
- **Idle behaviour:** test E1 found that 90 s idle on the title does not drop into the attract demo, and char select has no time limit (`handoff/ss2_next/설계/ranked.md:67`). Only 90 s was tested.
- **Input:** `block = A|B|OPTION|↑↓|←→|IN_ABFOLD` (`:437`). The A+B and one-button fold bits are blocked too, so nothing reaches the game menu.
- **Press bits collected into `H.ev`:** 1 A (only once the A that started the search has been released; `hold_a` at `:376`, `:427`, `:438`), 2 B, 4 OPTION, 8 ←, 16 →, 32 ↑, 64 ↓ (`:438-444`, edges taken against `prev_in2`, `:369`). `nativeHubTakeEv` reads and clears them (`:806-812`). They are also exposed as hub status `v[12]` (`:740`).
- **Cursor constraint:** going to char select needs `menu && H.go && H.fx_on && ram[R_MCUR]==2` (`:447`). `hub_go_fixed` then sets the cursor to 0, presses A for the player (`nav=1`), arms the fight with `fx_*` and the five difficulty knobs, and moves to `H_PICK_ME` (`:345-350`). The user can't move the cursor because ↑↓ is blocked.
- **When `go` is honoured:** `league_hub_match(..., go)` only sets `go` while in `H_SEARCH` (`:799`). Otherwise it just stores the fixed opponent (used by rematch -4).
- **If the menu disappears:** state drops silently to `H_TITLE` (`:448`, commented "impossible"). Java's `rankTick` then sees `st != 6` and closes the overlay with no toast (`EmuActivity.java:2033`).
- **No ticks while paused:** if the app pauses the game, `maxsteps=0` (`native.c:915`), so `hub_tick` doesn't run and no `ev` is collected.

### 1.3 Java loop
`hubPoll` runs every 150 ms (`EmuActivity.java:1688-1695`) → `hubTick` (`:1697-1744`). It returns early while a reset hasn't reached the GL thread yet (`:1712-1715`), and otherwise calls `rankTick(st)` (`:1734`).

`rankTick` (`:2032-2064`):
1. `st != 6` → clear `rankGoAt` and close the overlay.
2. While an `Ask` card is showing, freeze the clocks (`rankFrozenAt`, `:2035-2042`). When it closes, shift `rankT0`, `rankEnd` and `rankCardAt` forward.
3. After «대전», wait up to 2 s for native to leave state 6. Past that: `nativeHubSearch(false)` and toast «상대를 잡지 못했어요» (`:2043-2047`).
4. No view yet → `rankSearchShow()` (`:2066-2076`):
   - `League.rankedPick` picks the opponent and saves it as pending.
   - `rankEnd = now + searchMs`.
   - Builds `RankUi.search(myLabel, extra = 연승/연패 line, activeToday)`.
5. While searching: only B is handled (ev bit 2 → `rankCancel("그만뒀어요")`). `RankUi.Search.tick` updates the m:ss timer, rotates 4 lines every 2.5 s (after 6 s the last one becomes «범위 넓히는 중…»), and changes the spinning avatar every 300 ms (`RankUi.java:84-91`, `:94-95`). At `rankEnd` → `rankCardShow()` (`:2104-2117`: opponent snapshot, h2h, LP stakes, placement line, stage, haptic).
6. While the card is up: A → `rankGo`, B → `rankLeave`, OPTION/←/→ → step the stage (this also turns auto-accept off). Auto-accept after 3000 ms (`:2060-2063`). `rankGo` (`:2118-2130`) recomputes the knobs from today's opponent MMR and calls `nativeHubMatch(..., go=true)`.
7. Hub reaches state 3 → `rankNewMatch()` writes a "ready" record (`:1717-1718`, `:2137-2149`).
- The banner duplicates the overlay text: «상대 찾는 중… · B 취소» / «A 대전 · B 나가기 · ◀▶ 스테이지» (`:1785`).

### 1.4 `RankCore.pick` timing (`RankCore.java:355-391`)
- **Held opponent:** `searchMs = 1200 + rand(1200)`, so 1.2–2.4 s (`:357-360`).
- **Otherwise:** `2000 + rand(4000) + max(0, mmr-1450)*60`, capped at 12000 (`:366-367`). The pool is MU 1050, σ 230 (`:110`), so MMR 1450 is roughly the top 4%. For about 96% of players the wait is uniform 2–6 s. MMR 1650 or higher hits the 12 s cap.
- 12% of searches pick a rival (`:368-372`).
- `activeToday` = 92–98% of 39,899 (`:487`).

### 1.5 What "pending" means
- **Saved at search start, not when the card shows.** `rankedPick` writes `{id, at, mmr, stage, knobs}` (`League.java:957-976`). The design doc says "when the card shows" (`ranked.md:191`), but the code comment and call site say before the card. Consequence: cancelling with B during the search also holds an opponent the user never saw. The next search re-serves them in 1.2–2.4 s.
- `at` is not refreshed on re-serve (`:966`), so the hold expires 24 h after the first pick (`:769`, `meOf` `:841-842`).
- **Cleared only by `applyRanked`**, i.e. when a match against that opponent is settled or forfeited (`:1065-1066`). `cancel()` of a ready record (`:457-470`) and error holds do not clear it.
- The stored `knobs` are not used. `rankGo` recomputes them, and `newRankedMatch` saves whatever was actually used (`:979-1019`), so they stay consistent.

### 1.6 Ways out of the search
| Trigger | Searching | Card showing |
|---|---|---|
| B (pad) or tap 취소 / 나가기 | `rankCancel("그만뒀어요")` | `rankLeave` → toast «상대가 기다려요 — 다음에 또 만나요» |
| Back | `rankBack` (`:796`, `:2134`): same as the row above | same |
| Pad bar opened | `rankCancel(null)`, no toast (`:176`) | same |
| `onPause` (app goes to background) | `rankCancel(null)` (`:1017`) | same |
| `Ask` card shown | clocks frozen, not cancelled | same |

In every case the pending opponent stays. Each exit calls `nativeHubSearch(false)` → `H_TITLE` with the cursor still on row 3 (`league.c:787`).

### 1.7 If the user does nothing for a long time
1. Search lasts at most 12 s.
2. The card auto-accepts after 3 s.
3. Char select opens with a "ready" record. Char select has no timer (E1).
4. It stays there indefinitely: `FLAG_KEEP_SCREEN_ON` (`EmuActivity.java:107`) keeps the screen on, but no LP is at risk.
5. If the user changes the stage, auto-accept turns off and the card waits forever over the title. Only the 90 s E1 measurement backs this.
6. A "ready" record left behind blocks `openMatch()`. The next `hubStart` cancels it (`:1680`); LeagueActivity shows it as «다시 시작 / 무효로 닫기» and hides the «하러 가기» button (`LeagueActivity.java:159-163`).

### 1.8 Quirks found
- The search silently disappears if the title menu ever vanishes (`league.c:448` → `rankClose` with no message).
- The banner and the overlay repeat the same text.
- Any wait longer than about 90 s on the title (an indefinite card already, or a longer waiting room) needs a longer E1 test, e.g. `e1_idle` for 36,000 frames (10 min) on the 4 ROMs.

### 2.2 Option 2: browse the board while queued
- **2A, inside EmuActivity (recommended for v1).** Add page tabs to the panel ([내 정보] [내 주변] [최근]) using ←→ / ↑↓ via ev. Profile tap opens an in-view card, not an `AlertDialog` (dialogs are banned over GL). The queue never leaves the activity. Cost is small: `around(k=2)` needs only about 4 profiles; most of LeagueActivity's 4.9 s on the emulator is 100 profiles and avatars.
- **2B, full LeagueActivity while queued.**
  - **What breaks today:** going to the board calls `leagueExitBoard()` → `leagueExit` → `finish()` (`:2336-2341`); `onPause` cancels the search (`:1017`); and `rankTick` lives only in the league EmuActivity.
  - **Queue state:** move it out of the activity into a static `RankQueue {t0, due, oppId, stageSel}` (in-process; pending is already persisted).
  - **Handover:** add a «순위표 보며 기다리기» button that sets `RankQueue.keep` before `leagueExitBoard()`, and skip `rankCancel` in `onPause` when `keep` is set.
  - **LeagueActivity side:** a Handler poll every 250 ms drives a sticky strip «상대 찾는 중… 0:24 · 취소». At `due` show the found card; `AlertDialog` is allowed here (no GL; it already uses one at `LeagueActivity.java:505`). The «하러 가기» button becomes the queue chip.
  - **Accept:** start EmuActivity with `EXTRA_LEAGUE_HUB + EXTRA_HUB_GO + EXTRA_RANK_GO` (new) and go straight to char select (2.3, step 4).
  - **Cost of accept:** a core load and boot of about 61 frames plus activity start, roughly 2–3 s.
  - **Risks:** deciding when the queue dies (Home button, process death); keeping the found card from popping during LeagueActivity's own result dialog; the go button is hidden when `rom == null` (`LeagueActivity.java:163`), so the queue would need the ROM path.

### 2.3 Option 3: practice while waiting
**3a. Queue keeps running in the normal-session practice (recommended for v2).**
1. **Start the queue.**
   - From the league waiting panel: «연습하며 기다리기 (A)» keeps `rankPick` and `rankEnd` in `RankQueue`, calls `rankCancel(null)` without clearing the queue, then `switchSession(false, true)`. That lands on the practice opponent select via `EXTRA_PRACTICE` autostart (`EmuActivity.java:2309-2333`, `league.c:600-617`).
   - Or from the practice session itself: a «랭크 대기» chip. Guard with `League.dbProblem`, `writeProblem` and `openMatch()==null`; these checks are already reachable there (`:2459-2460`).
2. **Normal session.** `practicePoll` (`:2479-2496`) ticks the queue and shows a small chip «랭크 대기 0:31 ✕» outside the HUD and frame meter.
3. **Found card at `due`.**
   - `nativeSetPaused(true)` + `releasePhysical()`, then `RankUi.found(...)`.
   - Input stays in Java because a paused game sends no ev:
     - touch on the card's pills;
     - `dispatchKeyEvent` routed like the `Ask` handler at `:920`, but with the game's convention (A = 대전, B = 나가기). **Do not reuse the `Ask` key handler** — there A and Back mean *cancel* (`:1984-1988`);
     - on-screen pad edges caught in `onMask` (`:157`) instead of being written to `padMask`.
4. **Accept** → `switchSession(true, false)` plus a new `EXTRA_RANK_GO`.
   - In `hubStart`, if `openMatch()==null`, run the normal `nativeHubGo` (repick 2).
   - When st == 6, `rankTick` skips the overlay: `rankPick = League.rankedPick(this)` returns the pending opponent; check the id matches, else fall back to the normal card. Set `rankStageSel` from the extra and call `rankGo` with its `rankView != null` guard (`:2119`) relaxed.
   - **No native change needed.** Optionally add a native `league_hub_go_fixed` that reuses the -4 branch (`league.c:401-402`) so the hub never shows state 6.
5. **Decline / ✕** → stop the queue, unpause, toast «상대가 기다려요 — 리그 대전 A면 바로 만나요». The pending opponent stays.
6. **Back to practice afterwards.** Add «연습으로» to the result card (`:2234-2237`) → `switchSession(false, false)`. The normal session resumes from autosave, and the practice match comes back via `.prac`: `practice_before_save` / `prac_side` (`native.c:1139-1141`, `league.c:575-617`). This needs autosave on (`switchSession` saves only if `autoSave`, `:2314`); otherwise pass `practiceAuto=true`.

**3a risks:**
- Two session switches, about 1.5–3 s each.
- 19 `nativeSetPaused` call sites. The ones that recompute "bar open?" can unpause under the card: `onMenu` `:179-181`, sheet close `:582`, `Ask` onDismiss. Each needs a `|| queueCardUp`.
- Practice runs on the user's patched ROM with their mods and core; ranked uses the fixed copy and bundled core (`:88-95`, `:368`). Practice conditions are close to ranked but not identical.
- If the league can't open, `hubBlockedBack` returns to the game (`:2297-2306`) — acceptable.
- An `openMatch` created between queue start and accept would hijack `hubStart` (`:1677-1682`), so re-check it at accept.

**3b. Practice inside the league session.**
- **Native:** today `league_hub` and `league_practice_hub` both `memset` `H` (the practice one also clears `L`) and fix `kind` (`league.c:523-534`, `:600-617`). Entering practice from the title **must reset the core first**: the nav-3 step presses ↓ twice assuming the cursor starts at 0. From `H_SEARCH` it is at 2 and would land on row 4 (게임 설정) (`:390-393`).
- **Returning on accept:** reset → `nativeLeagueHub(true, sty, dif)` + look + dual + ranked + `nativeHubMatch(go=false)` + go-fixed. That is about 1 s and no activity switch. Java must also reset `hubGen` / `hubWaitGen`, because `league_hub` zeroes `hub_gen` (`:528`).
- **Java ties to undo:** `practiceSetup` / `practicePoll` are gated off in the league session (`:2443-2444`, `:2480`). `hubTick` would call `rankNewMatch` when practice reaches state 3 (`:1717`), so it needs a kind gate. Banner text, frame meter and cheat lock follow the same pattern: `league_session_owner` returns 2 for kind 1, and Java already locks cheats when `ranked()`.
- **Pros:** fastest accept; practice runs on exactly the ROM and core used for ranked; no autosave dependency; the queue lives in one activity.
- **Cons:**
  - Larger refactor.
  - Uses the league save (all cards owned) instead of the user's own save.
  - Leaving practice returns to the league title, not the user's game.
  - A core reset does not clear all RAM (`league.c:19`). Practice writes the CPU bit `0x5BCB`, multipliers `0x57E2/4`, HP, timer and rage; the game re-initialises these at fight load, and the knobs are rewritten every frame. Still needs a host test: practice → reset → ranked, compared byte-for-byte with today's `t_ranked`.
  - Do not add new fields to `H`: that changes the `.prac` blob size again (`league.c:541-546`, risk noted in `ranked.md` §6). Reuse `kind`.

### 2.4 How the found card should behave over practice
- **Pause:** pause the whole emulator (`nativeSetPaused(true)`) and call `releasePhysical()`. That also stops a held OPTION turning into a practice-menu tap on resume. The practice OPTION menu may be open underneath; that is fine.
- **Freeze the countdown** whenever another overlay holds the pause: bar menu, `Ask`, sheet. Use the same pattern as `rankFrozenAt`.
- **Accept timer: 10 s** (not 3 s). The user is mid-practice and needs to read the card. Auto-accept is "real" (SF6 and Tekken 8 both auto-start from training) and harmless, because char select has no timer.
- **Optional AFK rule:** no input for 60 s or more before the pop → no auto-accept; the card just waits.
- **Decline (B, «나가기»):** stop the queue rather than re-queue. Pending means a re-search would re-pop the same opponent in 1.2–2.4 s. The held opponent stays held; declining only postpones.
- **Inputs:** touch the pills, physical keys via `keymap.funcOf` (a / b / left / right / start), pad via `onMask` edges. Stage ◀▶ stays, and stepping it turns auto-accept off, as today.

### 2.5 Option 4: longer, more realistic waits vs boredom
- Today 96% of players wait 2–6 s. A held opponent: 1.2–2.4 s.
- On the bare title, longer waits are pure dead time (and only the 90 s E1 test covers that screen).
- **Recommendations:**
  1. Keep the title wait short. Make it feel "real" with a time-of-day factor (shorter at the Korean evening peak, longer at 3–6 am) rather than a longer average.
  2. Allow longer waits (e.g. 15–60 s) only when practising while queued (3a/3b), where the wait is useful.
  3. Optionally add a setting «매칭 대기: 빠르게 / 실제처럼».
  4. Keep the honesty rule: «상대는 모두 게임 CPU 예요» stays in the rotating lines. No ping bars and no fake "searching servers".
- Any multi-minute wait needs the longer E1 idle test, and should be a fresh `searchMs` only, not stacked on the held-opponent fast path.

## 3. Where the queue touches «리그모드는 언제든 다시» (only where relevant)
- **Queue start must check** `openMatch()==null` (`League.java:357-364`). An open playing/resume match hijacks `hubStart` (`EmuActivity.java:1677-1682`), and one that cannot resume leads to `leagueBlocked`, which offers only «리그 화면으로» / «게임으로».
- **A queue opened from LeagueActivity inherits its limits:** the go button needs `open == null && rom != null` (`LeagueActivity.java:163`). A leftover "ready" record from an AFK auto-accept hides it until the user presses «무효로 닫기».
- **A held opponent is not a lockout:** pending never blocks play; it only fixes who comes next, for up to 24 h.
