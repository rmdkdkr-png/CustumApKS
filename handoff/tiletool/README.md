# NGPC 타일 관측기 + 오프라인 시뮬레이터

에뮬을 돌리며 **화면에 실제로 뜬 ROM 타일**을 기록하고,
이후 **에뮬 없이** 임의 롬으로 그 화면을 다시 그려 회귀검사한다.

## 왜 필요했나

정적 아이템 스캐너(`gfx_scan`)는 세 가지를 놓친다.

1. 타일이 스캔 창(0x1D0000~0x1FFFFF) 밖으로 이주하면 아이템이 통째로 안 잡힌다 (SS2에서 실제로 16개 발생)
2. 아이템을 안 거치고 타일을 직접 읽는 화면(나찰 판 유형)은 정적으로 영원히 안 보인다
3. 구버전 세이브스테이트의 VRAM 잔존 때문에 눈으로도 속는다

관측은 **화면에 뜬 것만 본다.** 위 세 가지가 원리적으로 사라진다.

## 실측 확정한 VRAM 구조 (beetle-ngp, SS2)

```
0x9000  SCR1 타일맵 32x32 u16     ← SS2 텍스트 평면
0x9800  SCR2 타일맵 32x32 u16
0xA000  타일 패턴 512장 x 16B (2bpp, 행당 u16, 상위비트부터)
엔트리   pattern = v & 0x1FF
스크롤   0x8032/33 = SCR1 X/Y, 0x8034/35 = SCR2 X/Y
팔레트   화면마다 뱅크가 달라 색 재현은 미확정. 회귀 비교는 회색조로 한다
        (같은 타일맵을 두 롬으로 그려 비교하므로 색은 결과에 영향 없음)
```

## 쓰는 법

```bash
# 1) 기록 (에뮬 1회)
python3 observe.py 신판.ngc rec/ screens.json

# 2) 회귀검사 (에뮬 0회, 몇 초)
python3 regress.py rec/ 구판.ngc 신판.ngc diff_img/
```

`rec/_coverage.json` = 그 화면들에서 **실제로 화면에 뜬 ROM 타일 주소 전체**.
아이템 스캐너 결과와 대조하면 사각지대가 바로 드러난다.

## 검증

SS2 최종장 타이틀 기록으로 세 판을 오프라인 렌더:

| 롬 | 결과 |
|---|---|
| v0.95 | **빈 화면** — 「괴제 강림」 파손 그대로 재현 |
| v0.96 | 일부만 — 고쳤지만 타일 배치가 v0.99b와 다름 |
| v0.99b | **「최종장 / 괴제 강림」 정상** |

에뮬을 한 번도 안 돌리고 파손 이력이 그대로 재현된다.
이 검사가 있었으면 나코루루·괴제 강림 둘 다 자동으로 걸렸다.

## 한계 (정직하게)

- **방문하지 않은 화면은 여전히 안 잡힌다.** 커버리지를 자동화할 뿐 완전성을 보장하지 않는다
- 스프라이트·애니메이션·스크롤 합성은 재현 대상이 아니다 (텍스트 평면만 정확)
- 팔레트 뱅크가 화면마다 달라 **색 재현은 미완**. 회귀 비교에는 지장 없음
